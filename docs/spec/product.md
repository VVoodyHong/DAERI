# DAERI 제품 명세

상태: AWS 공용 서비스의 확정 요구와 현재 Python 핵심 계약.
구현 단계·대표 검증·실제 연동 경계는 [개발 안내](../development/dependencies.md#클라우드-개발-상태)가 소유한다.

## 목적과 대상

DAERI는 여러 직군의 구성원이 자연어로 업무를 맡기고 프로젝트의 서비스 경험을 함께 축적하는 멀티 오케스트레이션 에이전트다.
신규 구성원도 현재 접근 권한으로 기존 지식·성공 절차·실패 경험·피드백을 첫 업무부터 활용한다.
숙련도 향상은 누적 경험을 회상·적용·검증하는 능력으로 평가한다.

프로젝트는 구성원·공유·접근의 경계이고 서비스는 업무 대상이다.
profile은 서비스·환경별 연결 묶음이며, 목표·계획·승인·세션·코드 작업 사본은 개별 업무에 연결한다.
기존 PC 제품과 로컬 setup·MCP·SQLite 규격은 [local-agent 브랜치](https://github.com/VVoodyHong/DAERI/tree/local-agent)에 보존한다.

## 현재 제공 범위

현재 제공 단위는 배포와 독립된 Python 서비스와 설정 조립부다.
관련 기억 제공 → harness 호출 → 응답·지식 처리 보존 → 경험 정리·임베딩 → 공용 PG 회상의 핵심을 구현했다.
HTTP·회사 인증·클라우드 접속부·실제 계획 승인·관리형 연결·상시 처리·배포는 [후속 단계](../development/dependencies.md#클라우드-개발-상태)에서 연결한다.

## 업무 흐름

| 순서 | 동작 |
|---|---|
| 1. 요청 | 현재 사용자·프로젝트·서비스의 목표와 원하는 결과 접수 |
| 2. 회상 | 현재 접근 가능한 관련 지식·출처를 검색해 harness 문맥에 제공 |
| 3. 계획 | 총괄 에이전트가 대상·예상 효과·수행 범위·완료 조건 제시 |
| 4. 승인 | 실제 사용자 응답을 현재 업무·계획·대기 호출에 연결 |
| 5. 위임 | 필요한 하위 목표·에이전트 수·순서를 선택하고 근거 수집 |
| 6. 수행 | 승인 범위에서 도구·분석·페이지·재시도를 자율 선택 |
| 7. 보고 | 실제 결과·근거·파일·미충족 조건 전달과 업무 기록 보존 |
| 8. 기억 | 재사용할 경험을 정리·저장·색인해 다음 업무에 제공 |

가상 사례: “국가별 EV 충전소 개수를 확인하고 CSV로 정리해 줘”라고 요청하면 이전 집계 기준·자료 구조·실패 경험을 참고해 계획한다.
승인 후 최신 자료를 조회·검증하고 결과·한계·필요한 파일을 제공한다.
피드백과 경험은 같은 프로젝트의 후속 업무에 활용한다.

### 요청과 재개

`CloudWorkflow.start(context, prompt)`는 비어 있지 않은 요청과 내부 접근 문맥으로 업무·harness 세션을 생성한다.
`resume(context, task_id, prompt='', tool_results=())`은 저장한 업무에 후속 요청과 실제 대기 도구 응답을 전달한다.
빈 후속 메시지로 도구 응답만 전달하면 최초 업무 목표로 기억을 검색한다.

`AccessContext`는 사용자 `actor_id`, 프로젝트 `project_id`, 서비스 `service_id`, 출처 집합 `source_ids`다.
현재 구현은 각 식별자의 타입·값과 저장 범위를 검사하며 인증한 문맥의 전달은 [접근 경계](#접근과-동시-업무)에서 연결한다.
업무 재개는 작성 사용자·프로젝트·서비스·출처 집합이 현재 문맥과 일치할 때 수행한다.

| 입력·상태 | 처리 |
|---|---|
| 정상 시작·재개 | 관련 기억 최대 8건과 요청·도구 응답을 harness에 전달 |
| 대기 도구 응답 | 저장한 `toolUseId`별로 정확히 한 번 대응시키고 대기 순서로 전달 |
| 도구 응답 본문 | `success`·`error` 상태와 text·JSON 블록 검사 |
| 동일 업무 호출 진행 중 | `TASK_BUSY` 반환 |
| 응답 저장 실패 | 진행 상태를 유지해 재실행을 막음; 실행 대조·잠금 복구 API는 후속 구현 |
| 잘못된 입력·대기 대응 | `INVALID_INPUT` 반환 |
| 현재 문맥 불일치 | `ACCESS_DENIED` 반환 |

harness 어댑터는 SDK의 텍스트·도구 대기·관찰·완료·오류 이벤트를 해석한다.
장애·불완전 스트림은 확보한 응답과 오류를 보존하고 실제 실행 상태부터 확인해 재개한다.
대기 도구 ID가 중복된 스트림은 `HARNESS_STREAM_INCOMPLETE`, 호출 실패는 `HARNESS_UNAVAILABLE`로 기록한다.
Guardrails 개입 종료는 `HARNESS_GUARDRAIL_INTERVENED`와 확보한 텍스트로 보존한다.

한 응답의 `end_turn`과 업무 전체의 목표 달성을 구별한다.
외부 호출의 재전송 여부는 최초 실행·저장 상태를 확인해 판단한다.
보고 내용과 표현은 사용자 목표와 실제 근거에 맞춰 에이전트가 선택한다.

## 계획과 승인

이 절은 실제 사용자 승인 연결의 확정 동작과 연결 설계다.
현재의 대기 도구 응답 전달은 승인 왕복의 기반이며 계획 저장·자연어 결정·도구별 집행은 후속 구현이다.

총괄 에이전트는 목표·연결·대상·예상 효과·완료 조건을 계획으로 제시한다.
harness의 inline function이 승인을 기다리고 접속부가 실제 사용자 응답을 전달하면 서버가 현재 업무·계획·대기 상태에 연결하는 안이다.
기억·문서·코드·로그는 판단 자료로 취급하고 사용자 결정은 실제 대화 응답에서 확인한다.

| 실제 응답·변화 | 동작 |
|---|---|
| 현재 계획의 명확한 승인 | 승인 범위의 실행 재개 |
| 조건 수정·목표·대상·효과 확대 | 차이와 이미 수행한 내용을 담은 수정 계획 확인 |
| 거절 | 계획 조정 단계로 연결 |
| 모호한 응답·응답 부재 | 필요한 설명과 승인 대기 유지 |
| 중단·취소 | 현재 업무·대기·실행 상태에 반영하고 재개 시 현재 조건 확인 |
| 오래된 계획·다른 업무의 응답 | 현재 업무·계획·대기와 대응하는 응답 확인 |

하위 작업은 총괄 계획의 승인 범위와 현재 리소스 권한으로 수행한다.
도구·질의·순서·분해·분석·보고 형식은 그 범위에서 자율 선택한다.
승인 집행은 현재 서버 기록을 확인하는 Lambda lifecycle hook과 Gateway 정책에 연결하는 안이다.
기본 shell·파일 도구는 harness의 도구 호출 hook, Gateway 도구는 해당 정책 경계에서 검사하며 실제 응답의 진위·업무·대상 대응은 DAERI가 확인한다.
중단·재개·호스트 전환과 각 경계의 동작은 실제 연결에서 검증한다.

## 공유 기억

프로젝트·서비스의 지식 원문·출처·벡터를 공용 PostgreSQL·pgvector에 보관한다.
검색은 현재 프로젝트·서비스와 사용자가 접근하는 출처 집합에 모두 포함되는 지식을 반환한다.
가입 시점과 호스트가 달라도 같은 접근 조건으로 기존 경험을 활용한다.

| 보관처 | 역할 |
|---|---|
| AgentCore Memory | 업무별 대화·도구 이력의 저장·복구, 같은 사용자의 후속 업무 재개 |
| PostgreSQL·pgvector | 프로젝트 공유 지식·출처·벡터와 업무·지식 처리 상태 |
| S3 | 근거 자료·보고 파일·산출물 보관안 |

이 역할 분담은 현재 DAERI의 선택이다.
AgentCore Memory도 프로젝트·서비스의 공유 namespace로 장기 경험을 추출·검색할 수 있으며 [관리형 대안](../architecture/overview.md#관리형-기능과-확장)으로 비교한다.
현재 PG 방식에서는 장기 전략 없는 별도 Memory를 생성·연결해 업무 대화를 보관하는 안이다.
harness의 [Memory 설정](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/harness-memory.html) 생략 시 생성되는 관리형 Memory와 구별해 배포 설정·보존·복구를 검증한다.
같은 사용자의 호스트 전환은 현재 권한·업무·세션으로 연결한다.
담당자 변경·대화 만료에는 공용 PG의 현재 업무 상태와 허용 근거로 새 실행을 준비한다.

### 기록과 경험 처리

요청·응답·회상한 지식 참조와 지식 처리 작업은 Aurora Data API 트랜잭션으로 보존한다.
오류·대기 도구 없이 텍스트를 가진 `end_turn` 응답에 경험 처리 작업을 등록한다.
응답 기록과 경험 정리·임베딩의 진행 상태는 구별한다.

`SharedKnowledgeProcessor.process_next()`는 대기 작업 하나를 점유하고 요청·응답에서 경험 후보를 정리한다.
정리 결과는 적용 조건·불확실성·실패를 유지하도록 모델에 요청하며 유효한 UTF-8 64KiB 이내의 본문을 사용한다.
모델이 정리한 지식은 경험 후보로 취급하고 현재 자료·출처와 대조해 활용한다.

정리한 원문을 먼저 저장한 뒤 벡터·모델 식별자·처리 완료를 같은 트랜잭션으로 반영한다.
임베딩 실패에는 키워드로 찾을 수 있는 원문을 유지하며 다음 처리에서 저장한 원문을 재사용한다.
작업 점유는 5분, 경험 정리·임베딩 실패 후 다음 처리 가능 시각은 1분 뒤다.

정정·동시 갱신은 현재 내용을 대조해 적용 조건·검증 근거·상충하는 주장을 보존하는 설계다.
미병합 변경·병합 commit·실제 배포 상태를 구별하고 현재 수치·상태는 최신 자료로 확인한다.
기억 사용·결과·피드백을 연결해 회상 정확성·정정·재사용 효과를 평가한다.

### 검색과 임베딩

PG 키워드 검색은 `simple` 텍스트 검색과 `ts_rank_cd`, 벡터 검색은 같은 모델·차원의 코사인 거리를 사용한다.
각 방식 상위 50건을 RRF(Reciprocal Rank Fusion)의 `1 / (60 + 순위)`로 결합하며 동점은 지식 ID로 정렬한다.
현재 벡터 검색은 접근 조건을 통과한 자료의 정확 검색이다.

| 조건 | 처리 |
|---|---|
| 임베딩 제공자 생략·키워드 전용 선택 | 키워드 검색 |
| 검색용 임베딩 성공 | 키워드·벡터 순위 결합 |
| 검색용 임베딩 실패 | 키워드 결과와 `embedding_unavailable` 문맥으로 업무 계속 |
| 저장용 임베딩 실패 | 원문 유지·재처리 |
| 제공자·모델·차원 변경 | 기존 원문은 키워드로 활용하고 벡터 활용에는 새 모델 공간의 색인 필요; 일괄 재색인은 후속 구현 |

모든 저장 벡터는 1~8192차원의 유한하고 영벡터가 아닌 float32 표현으로 검증한다.
검색·저장은 제공자·모델·전처리 조건의 식별자와 같은 차원을 사용한다.
실제 PG의 규모별 성능·검색 품질·다중 사용자 격리는 실제 연동 검증 대상이다.

## 접속부와 리소스

Claude Code·Codex 플러그인은 프로젝트·서비스 선택, 업무 요청, 진행 표시, 실제 승인·피드백과 결과·파일 전달을 맡는다.
서버 연결부가 사용자·업무에 맞춰 회상하고 `InvokeHarness`를 호출한다.
회사 로그인·전송·스트리밍·재개는 현재 Python 서비스에 연결할 후속 구현이다.

Gateway에 연결 가능한 MCP·API는 관리형 연결을 사용하고 Policy·Identity·실제 서비스 권한으로 접근을 검사한다.
DAERI는 업무·승인·사용자·프로젝트 문맥과 필요한 업무·지식 도구를 연결한다.
stdio·특수 네트워크의 리소스는 실행 위치·인증을 확인한 호스팅·변환 어댑터로 연결한다.

대화 안내는 확인한 결과·필요한 선택·다음 조치로 구성하며 기본 언어는 한국어다.
실패에는 작업의 영향·복구 방법을, 사용자 직접 조치에는 편집·로그인·산출물 위치 등 해당 행동에 필요한 정보를 제공한다.
상세 진단 요청에는 확인한 기술적 원인·관련 설정·조치의 영향을 설명한다.

## 접근과 동시 업무

인증 경계가 검증한 사용자 신원·프로젝트 구성원·현재 출처 권한을 요청·기억·파일·재개에 전달하는 설계다.
현재 `AccessContext`는 내부 입력 계약이며 회사 신원·구성원 검증은 HTTP·로그인 경계를 연결할 때 구현한다.
출처 접근 변경은 회상·파일 제공·재개 문맥에 반영하며 여러 출처가 기여한 지식은 기여 출처의 조건을 함께 적용한다.

Gateway Policy·Identity는 리소스 접근을, DAERI는 현재 업무와 실제 승인 응답의 연결을 담당한다.
회사 SSO·Cognito·IAM, 개인 위임·프로젝트 자격의 Identity, 별도 비밀의 Secrets Manager를 우선 활용하는 안이다.
현재 SDK 경로는 서비스 IAM의 SigV4 인증이며 `actorId`·`runtimeUserId`는 downstream 사용자 위임 OAuth 인증과 구별한다.
[사용자별 위임 자격](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/harness-security.html)이 필요한 접속부는 harness inbound OAuth의 Bearer JWT로 연결한다.
구체 계정·리전·SSO·보존·네트워크·CA·로그 정책은 실제 배포 정보를 받은 뒤 설정한다.

각 업무의 소스 수정은 저장소 기준 commit과 업무별 사본·브랜치를 사용한다.
통합 시 최신 대상과의 충돌·테스트·반영 상태를 확인하고 프로젝트의 공유 지식과 각자의 변경 작업을 연결한다.
PC 또는 AWS의 실행 위치·Git 자격·사내망·기존 변경의 처리는 환경 연결 단계에서 결정한다.

## 설정과 제공자

`CloudSettings.from_yaml(path)`는 지정한 UTF-8 YAML을 읽고 검증한다.
설정 파싱은 로컬 파일·스키마를 검사하며 AWS 클라이언트·자격 조회는 `build_cloud(settings)`에서 시작한다.
`harness_model`은 관리자가 정한 신뢰 설정이며 향후 접속부도 모델·`apiBase`·`additionalParams`를 서버의 승인된 설정에서 해소한다.
설정 파일 생성·사용자 setup·공개 HTTP 진입 연결은 후속 구현이다.

YAML은 최상위 매핑과 유한한 JSON 호환 값, 2MiB 이내, 중첩 32단계로 받는다.
중복 키·명시적 태그·앵커·별칭·병합·지시문과 알 수 없는 필드는 입력 오류로 처리한다.
잘못된 구성은 비밀값을 포함하지 않는 `INVALID_INPUT`으로 반환한다.

| 필드 | 입력·기본값 |
|---|---|
| `region` | 선택 AWS 리전; 생략 시 SDK의 리전 해소 사용 |
| `harness_arn` | 필수 harness ARN |
| `harness_model` | 선택 SDK `InvokeHarness.model`; 생략 시 배포한 harness 모델 설정 사용 |
| `database.resource_arn`·`secret_arn`·`name` | 필수 Aurora cluster ARN·Secrets Manager 인증 참조·DB 이름 |
| `knowledge_model` | 필수 경험 정리 모델; `provider: bedrock` 또는 `api` |
| `embedding` | `bedrock`·`api`·`keyword_only`; 생략 시 키워드 전용 |

### 모델과 인증

Bedrock 경험 정리는 선택한 `model`의 Converse 지원 모델을 사용한다.
API 경험 정리는 `endpoint`·`model`·`api_key_secret_arn`으로 OpenAI chat completions 규격을 호출한다.
API 임베딩은 같은 연결 필드와 선택 `dimensions`로 OpenAI embeddings 규격을 호출한다.
`endpoint`는 요청의 완전한 HTTPS 주소이며 API 키는 Secrets Manager의 `SecretString`을 Bearer 인증값으로 사용한다.
현재 조립부의 API 네트워크 단계별 대기 제한은 경험 정리 30초·임베딩 15초다.

Bedrock 임베딩은 `amazon.titan-embed-text-v2:0`, 차원은 256·512·1024 중 선택하며 기본은 1024다.
API 임베딩의 차원은 1~8192 중 지정하거나 응답에서 해소한다.
API 임베딩 입력은 UTF-8 64KiB, Titan 어댑터 입력은 50,000자, 임베딩 응답 본문은 1MiB까지 검사한다.
[Titan V2의 서비스 입력 한도](https://docs.aws.amazon.com/bedrock/latest/userguide/titan-embedding-models.html)는 8,192토큰과 50,000자이며 토큰 초과는 제공자 실패로 처리한다.
API 경험 정리도 HTTP 본문 1MiB와 [정리 결과 조건](#기록과-경험-처리)을 검사한다.

생성 모델·경험 정리·임베딩 제공자는 각각 선택한다.
`build_cloud()`는 AWS 클라이언트 생성 전에 설치된 SDK의 모델 구조·필수값·타입·허용값·수치 범위를 검사한다.
실제 모델·리전·사내 API의 접근·호환성은 배포 환경에서 확인한다.

harness 외부 모델의 `apiKeyArn`은 해당 SDK 제공자 구성 안에 둔 AgentCore Identity API key credential provider ARN이다.
DAERI가 직접 호출하는 경험 정리·임베딩의 `api_key_secret_arn`은 Secrets Manager ARN이다.
두 자격은 각 호출 경계에서 해소한다.

### 구성 예시와 초기화

다음은 입력 형식을 설명하는 가상 YAML이다.
ARN·리전·경험 정리 모델을 실제 배포 값으로 바꾸고 필요한 임베딩 제공자를 선택한다.

```yaml
region: us-east-1
harness_arn: arn:aws:bedrock-agentcore:us-east-1:123456789012:harness/assistant-1234567890
database:
  resource_arn: arn:aws:rds:us-east-1:123456789012:cluster:daeri
  secret_arn: arn:aws:secretsmanager:us-east-1:123456789012:secret:daeri-db-example
  name: daeri
knowledge_model:
  provider: bedrock
  model: summary-model-id
embedding:
  provider: bedrock
  model: amazon.titan-embed-text-v2:0
  dimensions: 1024
```

`build_cloud()`는 저장소·업무 처리·지식 처리와 종료 가능한 클라이언트 묶음을 반환한다.
DB 초기화는 관리 호출 `store.initialize()`로 분리해 테이블과 pgvector 확장을 준비한다.
요청 처리·DB 초기화·지식 작업 반복 실행은 배포 단계에서 실제 서버 프로세스에 연결한다.
