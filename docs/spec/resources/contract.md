# 리소스와 어댑터의 공통 계약

상태: 공통 계약 설계 제안

리소스 연결 구조와 실행 계약을 설계하는 사람과 개발 에이전트를 위한 명세다.

이 문서는 리소스의 분류, 등록부, 포트·어댑터 호출과 공통 실패 처리를 정의한다.
제품별 최초 기능과 SDK 제안은 [초기 어댑터 명세](initial-adapters.md)에 있다.
전체 제품 조건은 [제품 명세](../product.md)를 따른다.

## 유형, 어댑터, 인스턴스

유형은 DB·Cache·Infra·Log·Ticket·Mail·Source처럼 업무 리소스의 역할이다.
어댑터는 PostgreSQL·MongoDB처럼 실제 제품에 맞춘 연결 구현이다.

인스턴스는 한 부처의 운영 DB나 특정 GitLab 프로젝트처럼 실제 호출 대상이다.
같은 어댑터로 여러 부처의 인스턴스를 등록할 수 있다.
대상은 인스턴스 ID로 선택한다.

## 등록부가 제공할 정보

| 정보 | 내용 |
|---|---|
| 식별자와 역할 | 인스턴스 ID, 리소스 유형, 어댑터 식별자·버전 |
| 적용 범위 | 부처·서비스·환경, 어떤 자료와 시스템인지 설명 |
| 기능 계약 | 기능 ID, 용도, 입력·출력 스키마, 조회·변경·부작용 여부 |
| 제품 의미와 제한 | 지원 연산, 일관성, 필드·대상 범위, 총량 한도 |
| 실행 조건 | 재시도·중복 방지 조건 |
| 구조 정보 | 스키마 또는 지원하는 구조 탐색 기능과 접근 경계 |
| 연결 진단 | 연결 가능 여부와 확인 시점; 업무 호출 오류와 구분 |
| 인증 참조 | 실행기가 해결할 비밀 저장소·profile 참조 |

인증 참조에 해당하는 비밀값은 모델에 제공하지 않는다.

에이전트에는 먼저 접근 가능한 인스턴스와 기능 요약을 제공한다.
선택한 후보의 상세 계약을 읽게 한다.
전체 연결의 모든 스키마를 항상 모델 입력에 넣지 않는다.

탐색에 노출된 기능도 실제 실행 때 현재 권한과 승인 범위를 다시 검사한다.
계획 전 탐색의 허용 경계는 [계획·승인](../tasks/approval.md)을 따른다.

## 포트·어댑터 호출

공통 호출은 기능 탐색, 입력 검증, 실행, 결과·오류 반환으로 구성한다.
유형별 포트는 해당 리소스의 의미를 표현한다.
어댑터가 이를 실제 API나 쿼리로 구현한다.

선택 기능과 제품별 확장은 기능 명세로 드러낸다.
구체적인 메서드 이름·자료형·오류 코드는 구현 설계에서 확정한다.

호출에는 업무와 계획 버전, 인스턴스·기능 ID, 구조화된 입력을 연결한다.
실행기는 인증된 권한과 승인된 계획을 원본으로 검사한다.
모델이 전달한 허용 범위나 승인 값만 믿지 않는다.

승인 수집과 범위 검사의 상세 동작은 [승인 명세](../tasks/approval.md)에 있다.
실행기의 책임은 [구조 설명](../../architecture/overview.md)을 따른다.

출력에는 결과와 원본 참조, 실제 조회 범위를 포함하는 것을 제안한다.
잘림·페이지 정보와 오류·재시도 의미도 포함한다.
실행 기록과 결과 검증은 [결과 명세](../tasks/results.md)에 있다.

코어는 계약과 등록된 기능을 사용한다.
특정 제품의 메서드를 직접 분기하지 않는다.

새 유형의 포트나 새 제품 어댑터를 추가해도 업무 판단 루프를 수정하지 않는 것을 목표로 한다.
지원하지 않는 연산은 명시적으로 실패하거나 다른 방법을 제시한다.

검색 기능은 API 지원·권한·페이지 처리·반환량의 실제 제약을 따라야 한다.
검색하지 못한 부분을 전체 결과처럼 표현하지 않는다.

## PostgreSQL에서 MongoDB로 바꿀 때

공통화하는 것은 기능 탐색, 호출 구조, 결과·오류 형식, 제한 조건이다.
PostgreSQL의 테이블·컬럼·조인·트랜잭션 의미는 각 기능 계약에 남긴다.
MongoDB의 컬렉션·문서·누락 필드·배열 조건의 의미도 각 기능 계약에 남긴다.

에이전트는 새 어댑터의 계약과 스키마를 확인해 계획을 다시 구성한다.
같은 업무가 가능한지는 새 제품의 지원 연산과 데이터 의미에 달려 있다.

임의 SQL과 문서 쿼리를 완전히 자동 변환하는 범용 쿼리 언어는 초기 범위에 넣지 않는다.

## 연결과 공통 실패

연결 주소·권한·인증은 사용자 로컬 설정으로 받는다.
비밀값은 채팅·계획·패키지·실행 로그에 넣지 않는다.

원격 제품 버전과 API 지원 여부를 진단해 실제 지원 기능만 노출한다.
원격 서버를 자동 업그레이드하지 않는다.

연결 진단 성공이 이후 업무 호출의 성공을 보장하지 않는다.
인증 만료, 접근 거부, 기능 미지원, 시간 초과, 결과 잘림, 성공 여부 불명확을 구분한다.
이 구분을 실행 기록과 결과에 반영한다.

재시도·재개는 [업무 흐름](../tasks/workflow.md)을 따른다.
결과 검증과 실패 보고는 [결과 명세](../tasks/results.md)를 따른다.
로컬 의존성과 인증 준비는 [실행 환경 명세](../installation/environment.md)에 있다.
