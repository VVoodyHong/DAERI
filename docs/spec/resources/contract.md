# 리소스 연결·도구 등록·실행 계약

상태: 기존 MCP 재사용·등록·정규화·읽기 실행 구현; 로컬 연결 검증, 실제 회사 리소스는 별도

다양한 리소스를 연결하고 에이전트가 필요한 도구를 찾아 사용하는 공통 기준이다.
범주별 관점은 [리소스 범주](initial-adapters.md), 호스트와 주고받는 동작은 [MCP 계약](../mcp/common.md)을 따른다.

## 연결 구조

DAERI는 호스트의 요청을 받아 기존 리소스 MCP를 연결한다.
어댑터는 연결·인증·입출력·대상 검사를 공통 계약에 맞추며 기존 기능을 우선 재사용한다.

```mermaid
flowchart LR
    H[Codex 또는 Claude Code] --> D[로컬 DAERI 실행기]
    D --> A[연결 어댑터]
    A --> M[기존 리소스 MCP]
    M --> R[DB·Cache·Infra·Source·Document 등]
```

리소스 MCP는 사용자 PC 또는 제공자가 운영하는 환경에서 실행할 수 있다.
원격으로 전달되는 자료와 처리 위치를 연결 설정에서 드러낸다.
중앙 서버 운영 여부와 호스트의 직접 실행 경계는 [구조 설명](../../architecture/overview.md)을 따른다.

## 기능 설계 단위

어댑터는 구조 탐색·자료 조회·검색처럼 조합 가능한 기능을 제공한다.
호스트는 사용자 목표·승인 범위와 실제 등록된 기능으로 업무 방법·순서·후속 조회를 자율적으로 정한다.
기능 계약은 조합할 수단과 실제 실행 조건을 정의한다.

실제 요청의 대상·권한·효과·한도를 검사하고 조회·변경·부수 효과를 구분한다.
등록한 기능 계약과 현재 리소스 권한을 모두 충족하면 실행 후보가 된다.

## 리소스와 profile

리소스 범주는 DB·Cache 같은 역할, 어댑터는 제품·연결 방식에 맞춘 구현, 인스턴스는 실제 대상이다.
한 범주에 여러 어댑터와 인스턴스를 둘 수 있으며 범주 자체도 확장할 수 있다.

공통 등록부는 profile에 명시한 어댑터 식별자로 구현을 찾아 연결한다.
어댑터는 지원 범주·도구·대상 설정안과 제품별 인증·대상 검사·요청 및 결과 해석을 소유한다.
profile의 범주와 어댑터의 지원 범주가 다르거나 등록되지 않은 식별자이면 연결을 거부한다.
식별자·호환 이름은 하나의 어댑터를 가리켜야 하며 중복되면 등록 충돌로 거부한다.

사용자는 [profile](../configuration/profiles.md)에 필요한 인스턴스를 묶는다.
업무는 해당 profile에 등록된 대상·연결·인증 문맥 안에서 필요한 기능을 선택한다.
연결 선택은 인스턴스·실제 대상·인증 문맥의 일치로 판정한다.

## 기능 계약

코어는 제품별 메서드나 업무별 분기 대신 등록된 기능 계약을 사용한다.
어댑터는 제품별 자료 구조·질의 의미·일관성·제약을 계약에 명시한다.

| 항목 | 등록할 내용 |
|---|---|
| 목적과 입출력 | 수행할 동작, 필요한 입력, 결과의 의미 |
| 대상과 효과 | 실제 접근 대상, 사용 주체, 조회·변경·부수 효과 |
| 허용 경계 | 제한 가능한 대상·기간·자료량·실행 시간과 미지원 조건 |
| 실패와 재시도 | 실패 구분, 중복 방지, 실행 상태 확인 방법 |
| 근거와 완전성 | 출처·확보 범위·시점·잘림·일관성 보장 |

안전성 판정에는 실제 입력·효과·대상과 제약 강제 수단을 확인한다.
읽기라도 접근 기록·사용 요금·서비스 부하가 발생할 수 있다.

## 관리 설정과 탐색

연결 추가·로그인·도구 갱신은 [관리 등록과 진단](../configuration/profiles.md#관리-등록과-진단)에서 수행한다.
새 연결·자격 증명 등록은 관리 경로에서 확인하고 업무 계획은 등록된 연결을 참조한다.

호스트에는 현재 profile에서 사용할 수 있는 기능 요약을 먼저 제공한다.
필요한 기능의 입출력·대상·제약을 확인한 뒤 계획을 세운다.
원격 구조나 실제 자료를 더 읽어야 하면 그 탐색 범위를 계획에 포함해 승인받는다.

## 도구 등록

선택한 MCP가 제공하는 도구와 지원 조건을 확인하고 어댑터의 검사·변환을 연결한다.
사용 가능 등록에는 입출력·대상·효과의 해석과 필수 제약의 강제 수단이 필요하다.
검사에 실패하면 해당 기능의 미지원 조건을 반환한다.
목록이 불완전하거나 확인에 실패하면 확인된 범위와 보류 이유를 구분한다.

등록 권한·정책의 변경은 관리 설정 경로에서 처리한다.
기존 MCP만으로 필요한 경계를 지킬 수 없으면 필요한 부분만 보완하거나 해당 기능을 보류한다.

## 등록부와 계약 변경

등록한 기능·연결·대상·인증 문맥·제약을 함께 관리한다.
계획은 확인한 계약을 참조하며 추가 도구의 사용은 그 기능·범위를 담은 계획으로 승인받는다.

도구 의미·대상·권한이 바뀌면 영향받는 호출을 보류하고 계약을 다시 확인한다.
새 계약이 업무 범위를 바꾸면 수정 계획을 승인받는다.
이미 보낸 호출의 출처와 실행 기록은 당시 계약으로 유지한다.

## 계획과 승인 범위

호스트는 사용할 기능·대상·제공 범위·예상 결과를 계획으로 제시한다.
사용자는 Codex 또는 Claude Code 대화에서 승인하며 자세한 조건은 [계획·승인](../tasks/approval.md)을 따른다.

실행기는 아래의 정규화·판정 계약으로 실제 호출의 현재 권한·대상·연산·누적 한도를 확인한다.
필수 제한을 강제할 수 없으면 거부하고 수정 계획이나 지원 가능한 방법을 제시한다.

원격에서 읽을 범위와 모델·산출물에 제공할 범위는 별도로 검사한다.
원격 접근은 실제 전송 요청으로, 모델·산출물 제공은 반환 자료의 필드·마스킹으로 각각 검사한다.

### 실제 요청 정규화와 범위 판정

어댑터 내부 경계는 `정규화 → 범위 판정 → 전송`으로 둔다.
아래 타입은 실행기와 어댑터 사이의 내부 계약이다.
호스트는 공개 MCP 입력을 제출하고 제품별 질의·경로·연산의 의미는 등록 계약에서 해석한다.

정규화는 서버가 검증한 업무 스냅샷·현재 연결·기능 계약과 바인딩된 입력을 받는다.
기본값·별칭·경로 해소·하위 MCP 인수 변환까지 적용해 보낼 요청 하나를 확정한다.
입력 스키마 검사 뒤에는 정규화한 실제 대상·연산을 승인 범위와 대조한다.

| 내부 타입·항목 | 필수 필드와 의미 |
|---|---|
| `NormalizedInvocation` 식별 | `invocation_ref: string`: 확정한 요청의 내부 참조; `instance_id`, `capability_id`, `contract_ref: string`: 등록 기능 연결 |
| `NormalizedInvocation` 대상·주체 | `target_binding: object`: 실제 대상 식별자; `identity_ref: string`: 실행기가 확인한 인증 주체의 비밀 없는 참조 |
| `NormalizedInvocation` 연산·접근 | `operation: string`, `effects: object`: 등록 계약으로 해석한 연산·변경·부수 효과; `access: object`: 실제 접근할 대상·필드·필터·기간·경로와 범위 |
| `NormalizedInvocation` 전송·제약 | `prepared_request: object`: 비밀을 제외한 최종 하위 요청; `controls: object`: 적용할 제약·강제 방법과 최대 사용량 |
| 범위 판정 | 확정 요청과 계획·현재 권한의 포함 관계 검사; 통과 시 `NormalizedInvocation`, 실패 시 오류 코드·이유 |

`NormalizedInvocation`의 하위 객체는 해당 어댑터가 검증한 내부 스키마를 사용한다.
DB의 실제 자료 영역, Infra의 계정·위치·자원, Source의 프로젝트·리비전·경로처럼 제품별 식별자를 `target_binding`·`access`에 명시한다.
검사 문맥은 실행기가 읽은 업무·계획·승인·연결·현재 권한·예산 기록에서 해소한다.
현재 구현은 필수 조건을 모두 통과한 정규화 객체를 전송 후보로 반환하고 실패 시 해당 코드·이유의 `StoreError`를 반환한다.
객체·판정·기록은 비밀 없는 인증 참조를 사용하고 실제 비밀값은 전송 경계에서 해소·주입한다.

범위 판정은 확정 요청과 실행기가 읽은 현재 권한·불변 계획·유효 승인·소비 및 예약을 비교한다.
실제 효과·권한은 등록한 정규화·검사 코드와 현재 연결 문맥에서 해소한다.
질의·변환·간접 접근의 포함 관계를 확인할 수 없으면 `unsupported` 또는 `unknown`으로 차단한다.

아래 이름은 범위 판정의 의미를 구분한다.
현재 내부 반환 형식은 위 정규화 객체·오류이며 공개 오류는 [리소스 MCP](../mcp/resources.md)에서 정의한다.

| 판정 의미 | 조건과 처리 |
|---|---|
| `allow` | 모든 필수 경계의 포함 관계와 강제 수단을 확인함; 같은 확정 요청만 전송 후보가 됨 |
| `deny` | 실제 대상·연산·범위·현재 권한·남은 한도를 벗어남; 해당 범위·문맥·권한·예산 오류로 차단 |
| `unsupported` | 조건 해석·강제 수단이 미구현; `UNSUPPORTED_CONSTRAINT`로 차단 |
| `unknown` | 현재 대상·효과·포함 관계를 확인할 근거가 부족함; 확인할 조건을 알리고 차단 |

인증을 확인할 수 없으면 `AUTHENTICATION_REQUIRED`, 연결 진단이 없으면 `CONNECTION_NOT_READY`로 반환한다.
그 외 대상·효과·포함 관계의 미확인은 `UNSUPPORTED_CONSTRAINT`로 반환한다.
대상·효과 확인에 원격 자료가 필요하면 먼저 그 확인 기능·대상·예산을 포함한 탐색 단계를 승인받아 실행한다.
정규화·범위 검사는 등록 정보와 입력으로 판정하며 원격 관찰은 승인받은 탐색 호출로 확보한다.

`allow` 판정 뒤 [실행 제어](../tasks/workflow.md#실행-검사와-기록)의 예약·의도 보존·dispatch 직전 재검사를 모두 거쳐 실행한다.
판정·예약·기록·전송은 같은 `invocation_ref`와 확정 내용을 연결하며 전송 직전 내용의 일치를 검사한다.
인수나 대상이 달라지면 다시 정규화·판정하고 연결·계약·주체가 바뀌면 기존 판정을 폐기한다.

재시도·페이지·후속 참조도 각각 같은 검사를 거친다.
하위 MCP 내부의 요청을 개별 통제할 수 없다면 등록 계약이 원 호출 전체의 대상·효과·최대 사용량을 보장해야 한다.
원 호출 전체의 제약을 보장할 수 있을 때 해당 숫자 한도·접근 경계를 지원으로 등록한다.

다음 가상 사례는 실제 요청과 승인 범위의 판정 방법을 설명한다.

| 승인과 실제 요청 | 판정 |
|---|---|
| DB의 승인한 필드·기간 안에서 필터를 더 좁힘 | 실제 접근도 부분집합이고 제약을 강제할 수 있으면 `allow` |
| 생략한 Infra 위치의 기본값이 승인한 위치와 다름 | 기본값 적용 뒤 `deny`; 실행 전에 인수 정정 또는 수정 계획 필요 |
| Source의 허용 경로가 별칭 해소 후 경로 밖을 가리킴 | 실제 경로 기준 `deny`; 실제 경로를 정정하거나 수정 계획 필요 |
| 읽기 도구가 상태를 바꾸는 질의·함수를 실행함 | 실제 효과가 읽기 승인 밖이면 `deny`; 효과가 미확인이면 `unknown` |
| 필드·기간 제한을 표시 결과에만 적용하고 원격 전체 자료를 읽음 | 원격 접근 제한 미지원이므로 `unsupported` |
| 승인 후 같은 표시명의 연결이 다른 실제 대상·주체로 교체됨 | `deny`와 문맥 변경; 새 연결의 진단·계획 승인 필요 |

## 호출과 결과

승인 범위 안에서는 호스트가 도구와 다음 절차를 자율적으로 선택한다.
추가 호출·재시도·페이지·반환 주소와 자료의 후속 읽기도 각각 실제 대상·현재 승인 범위·누적 한도를 검사한다.

결과에는 실제 확보 범위·출처·실패·잘림·미확인 상태를 남긴다.
외부 오류는 해당 오류 상태로, 일부 자료는 완전성·누락 범위를 갖춘 부분 결과로 반환한다.
하위 응답은 등록한 정규화·출력 계약으로 검사하며 [출력 검증 실패](../mcp/resources.md#반환-data)와 실제 원격 완료·효과를 구분해 기록한다.
중단·재시도·완료 확인은 [업무 실행](../tasks/workflow.md)을 따른다.

추가 로그인이나 사용자 결정이 필요하면 해당 업무의 대화로 안내한다.
인증값은 [YAML 적용·제공자 로그인](../configuration/profiles.md#인증-저장과-전달)으로 등록하고 모델에는 인증 참조·준비 상태를 제공한다.
응답 이후 현재 연결·권한·승인 범위를 다시 확인한다.

## 결과와 제품 교체

어댑터를 바꿀 때 새 제품의 지원 연산·자료 구조·제약을 읽고 계획을 구성한다.
질의와 일관성은 제품별 계약에 따라 해석한다.
여러 리소스의 결과에는 개별 관찰 시점·일관성 차이와 결합 조건을 명시한다.

새 제품은 구체 어댑터와 신뢰하는 코드의 등록 항목을 추가하고 필요한 설치 recipe·카탈로그를 연결한다.
대상·인증·읽기 제한·결과·실패와 범위 이탈을 검증한 뒤 사용자 선택에 포함한다.
새 제품의 실행 가능 여부는 어댑터의 대상·효과·제약 검사와 등록 진단으로 확정한다.
제품별 처리는 어댑터가 담당하고 업무·승인·공통 전송은 등록 계약을 사용한다.

## 구현과 검증 경계

허용·거부·범위 이탈·계약 변경·인증 변경·부분 결과·중단 후 복구를 확인한다.
실연동과 공개 범위의 완료 기준은 [최초 구현 계획](../../plans/initial-implementation.md)을 따른다.
로컬 시험 MCP의 실제 세션·스키마 등록·읽기·거부·시간 초과와 호스트용 stdio 서버를 통한 승인·실행·보고 조회를 검증했다.
실제 회사 리소스·제공자 권한과 Codex·Claude Code 설치 후 사용자 대화는 별도로 검증해야 한다.
