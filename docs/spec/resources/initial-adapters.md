# 리소스 범주와 연결 기준

상태: 기존 MCP 읽기 기능과 로컬 Source의 호스트 관찰 등록; 고정 패키지·로컬 계약 검증, 실제 회사·호스트 연결은 별도

리소스의 역할·실제 연결·읽기 판정과 현재 지원 한계를 설명한다.
호스트는 사용자 목표와 승인 범위 안에서 기능·질의·페이지·분석 방법을 선택하며 공통 원칙은 [리소스 계약](contract.md)을 따른다.

## 범주와 어댑터

범주는 에이전트가 리소스의 역할을 이해하는 공통 포트다.
한 profile에 같은 범주의 여러 제품·인스턴스와 서로 다른 범주의 연결을 등록할 수 있다.
실제 사용 예정 제품은 [제품 환경](../product.md#사용-예정-환경)에서 관리한다.

| 범주 | 역할 예시 |
|---|---|
| DB | 구조 탐색·조건 조회·집계 |
| Cache | 키 탐색·여러 자료형·상태 조회 |
| Infra | 구성·로그·지표·자원 상태 조회 |
| Source | 로컬 소스 코드·파일·Git 이력 조사와 관찰 근거 연결 |
| Document | 문서 검색·본문·구조·이력 조회 |
| Issue | 이슈 검색·상태·업무 이력 조회 |

범주·제품·연결 개수는 [setup 질문 계약](../hosts/plugins.md#setup의-정형-질문)에서 선택한다.
에이전트별 업무 구성과 위임은 [구조](../../architecture/overview.md#오케스트레이션과-자율-수행)를 따른다.

## 기존 도구 선택 기준

기존 MCP의 실제 기능·입출력·권한·실행 위치·배포 출처·복구 조건을 먼저 확인한다.
DAERI는 연결·인증·대상·자료 제공과 읽기 효과 분류에 필요한 부분만 보완한다.
`readOnlyHint`는 탐색 메타데이터이며 실제 강제 수단은 제품의 읽기 모드·서비스 권한과 검증한 구현이다.
로컬 Source는 호스트의 기존 파일·검색·실행·Git 도구를 사용하고 아래 [로컬 소스 코드](#로컬-소스-코드) 계약으로 관찰을 등록한다.

제품·정확한 패키지 버전·실행 파일·기본 환경·호환 기능 ID는 [카탈로그](../../../src/daeri/config/catalog.json)가 소유한다.
`recipes/<recipe-id>/pyproject.toml`·`uv.lock`은 하위 MCP의 별도 설치 조합이며 [개발 의존성](../../development/dependencies.md)을 따른다.

## 범주별 의미 보존

원격에서 읽는 범위와 모델·산출물에 제공하는 범위는 구분한다.
파일 전체를 읽고 일부만 반환하는 도구는 원본 파일 접근 권한이 필요하다.
특정 테이블·키·프로젝트의 접근 범위는 서비스 권한과 명시한 조건으로 정한다.

호스트는 서로 다른 관찰 시각·질의·잘림·일관성의 차이를 결과에 반영한다.
업무 완료는 승인한 목표와 실제 결과로 판단한다.

## 첫 버전의 실제 연결 방식

공통 입력은 stdio와 HTTPS Streamable HTTP 형식을 해석한다.
외부 서비스용 내장 어댑터는 실제 리소스 대상·인증 주체를 바인딩할 수 있는 로컬 stdio 연결을 지원한다.
이 어댑터로 원격 MCP를 등록하면 `UNSUPPORTED_CONSTRAINT`로 반환한다.
로컬 Source는 `host` 연결로 등록한 디렉터리와 호스트 도구를 연결한다.

로컬 연결은 준비한 실행 파일의 절대 경로·인수 배열과 별도 빈 작업 디렉터리를 사용한다.
프로그램 주입·암시적 프록시·대체 인증·TLS 검증 해제·연결을 바꾸는 실행 인수를 검사한다.
프로그램 설치·인증 준비는 명시적 관리 요청에서 수행한다.

## 등록 설정과 진단

설정 필드는 [리소스 인스턴스](../configuration/profiles.md#리소스-인스턴스), 탐색·기존 ID·갱신 절차는 [도구 등록](contract.md#도구-등록)을 따른다.
이 절은 하위 도구 목록과 스키마의 처리 범위를 정의한다.

하위 도구 목록은 최대 8페이지·512개이며 이름이 고유해야 한다.
입출력 스키마는 최상위 객체와 로컬 자기완결 참조를 지원한다.
JSON Schema의 외부 참조·동적 참조·`$id`와 처리 상한 밖의 등록은 진단 실패다.
자동 탐색 도구의 이름은 1~128자의 기능 ID 문법과 고유성을 만족해야 한다.

등록부의 변경·재진단 조건은 [등록부와 계약 변경](contract.md#등록부와-계약-변경), 도구 선택을 함께 승인하는 묶음은 [리소스 MCP](../mcp/resources.md#리소스-읽기-묶음)를 따른다.

### 범위 조건

기본 조회 영역은 등록 연결의 실제 읽기 권한 영역이다.
DB 역할·스키마 권한·행 정책, Redis ACL, AWS IAM과 서비스 토큰 권한으로 필요한 대상 범위를 제한한다.
사용자는 계획에서 연결·기능 또는 읽기 묶음·자료 제공·예산과 필요한 추가 조건을 승인한다.

| 연결의 명시적 상한 | 계획의 명시적 조건 | 검사 |
|---|---|---|
| `fixed` | `equals` | 최종 인수의 값과 타입 일치 |
| `allowed_values` | `one_of` 또는 `equals` | 값 또는 배열의 항목이 허용 목록에 포함 |
| `path_prefixes` | `path_prefixes` 또는 `equals` | 경로 요소별 포함 관계 |
| `max_values` | `max_values` 또는 `equals` | 숫자가 명시한 상한 이하 |

명시한 조건은 고정값·하위 스키마의 유효한 기본값·어댑터 변환을 적용한 최종 인수에 검사한다.
숫자 상한은 0 이상의 유한 값에, 경로 조건은 모호한 인코딩·상위 이동이 없는 상대 경로에 적용한다.
기본값도 확인할 수 없는 제한 인수는 `UNSUPPORTED_CONSTRAINT`로 명시 입력을 요구한다.
호스트는 검사한 범위 안에서 질의·필터·정렬·페이지 인수를 선택한다.

등록된 `sql_field`·`tables`·`columns`·`max_rows` 의미 제약은 모든 어댑터의 공통 검사에서 `UNSUPPORTED_CONSTRAINT`로 반환한다.
실제 서비스 권한이나 지원하는 명시적 필드 조건으로 관리 설정을 바꾸고 재진단·새 계획으로 전환한다.
알려진 과거 생성 기본값의 명시적 갱신과 사용자 지정 제약의 처리는 [설정 변경](../configuration/profiles.md#검증과-변경-의미)을 따른다.

## 어댑터별 실제 지원 경계

| 어댑터 | 재사용과 읽기 판정 |
|---|---|
| `postgres_read` | 고정 `postgres-mcp` restricted 실행과 DB 읽기 권한을 사용; SQL 원문을 그대로 전달하고 구조 탐색·실행 계획·상태 조회 도구도 등록 |
| `redis_read` | 고정 패키지의 읽기 도구 효과 메타데이터를 보완; 키 탐색·검색·자료형 읽기·상태 조회를 등록 |
| `aws_read` | `call_aws`의 단일·배치 명령을 사용; 하위 `READ_OPERATIONS_ONLY` 판정으로 읽기 연산을 결정 |
| `local_source` | 등록 디렉터리의 접근 상태를 확인하고 호스트가 조사한 관찰을 `source_observe`로 등록 |
| `confluence_read` | 하위 읽기 모드와 read annotation으로 검색·본문·구조·이력 등 읽기 도구 탐색 |
| `jira_read` | 하위 읽기 모드와 read annotation으로 이슈·검색·프로젝트·업무 이력 등 읽기 도구 탐색 |

외부 서비스 기능의 실제 사용 가능성은 해당 하위 도구의 존재·스키마·서비스 권한으로 결정한다.
과거 `sql_read`·`document_read` 식별자는 각각 PostgreSQL·Confluence 어댑터의 호환 이름이다.
기존 ID와 당시 기록은 보존한다.

PostgreSQL은 고정 하위 패키지의 restricted driver로 문법·읽기 전용 트랜잭션·자체 timeout을 강제한다.
일반적인 JOIN·CTE·함수·메타데이터 조회의 지원 여부도 하위 MCP 계약을 따른다.
자동 등록 대상은 restricted driver로 실행하는 위 읽기 도구이며 외부 모델을 선택하는 인덱스 추천은 별도 연동 계약이 필요하다.

Redis 패키지의 읽기 판정은 고정 버전 원문에서 확인한 도구 목록을 사용한다.
`scan_keys`·`scan_all_keys`로 키를 탐색하고 자료형별 읽기·인덱스 검색·상태 조회를 조합한다.
데이터 변경·메시지 발행·그룹 소비·구독·외부 문서 검색은 각각 효과와 실행 조건을 검증하는 별도 계약이 필요하다.
실제 명령·키 범위는 Redis ACL과 명시한 조건으로 제한한다.

AWS 읽기 연산은 하위 MCP가 제공자 메타데이터와 읽기 모드로 검사한다.
등록한 profile·위치의 기본값과 같은 명시 위치를 허용하고 대체 profile·endpoint·TLS 검증 해제·로컬 파일 접근을 차단한다.
서로 다른 위치·계정이 필요하면 해당 연결과 승인 범위를 사용한다.

Document 검색의 자연어·CQL과 Issue의 JQL은 선택한 하위 도구의 입력 계약으로 전달한다.
선택한 연결의 서버·인증을 사용하고 대체 서버·URL 인수는 `SCOPE_VIOLATION`이다.
Confluence의 `page_id`는 숫자로 구성한 문자열, Jira의 `issue_key`·`project_key`는 명시적 키 문법으로 검사한다.
Jira 입력 스키마에 `update_history`가 있으면 false로 정규화한다.

### 로컬 소스 코드

Source 포트의 현재 제품은 `source-local`(로컬 소스 코드), runtime 어댑터는 `local_source`다.
한 연결에 존재하는 디렉터리의 절대 경로 하나를 `target.path`로 등록한다.
setup은 심볼릭 링크를 해소한 실제 경로를 저장하며 이후 루트가 다른 디렉터리로 바뀌면 경로를 다시 설정·진단한다.
같은 profile에 여러 경로를 각각 등록하며 [사용자 YAML](../configuration/profiles.md#공통-구조와-어댑터-입력)은 `source`·`source-2`처럼 연결을 구분한다.
연결은 `connection.transport: host`, 주체는 `identity_ref: local-user`를 사용한다.
준비·진단은 현재 디렉터리의 존재·읽기·탐색 접근과 관찰 기능 확인으로 완료한다.

호스트는 승인한 계획 범위에서 기존 파일·검색·실행·Git 도구로 소스를 조사한다.
로컬 파일 편집·Git 작업은 해당 호스트 도구의 실행·권한과 기존 Git 인증을 사용한다.
runtime의 Source 기능은 조사 결과를 받는 `source-observe`이며 실제 도구 이름은 `source_observe`다.
등록된 관찰은 기존 호출·보고·파일·기억의 출처로 사용할 수 있다.

호스트는 조사 후 확인한 요약과 선택한 상대 경로를 [관찰 입력](../mcp/resources.md#로컬-source-관찰-등록)으로 전달한다.
runtime은 호출 때 현재 루트의 접근 상태와 각 경로의 존재·루트 포함 관계를 검사한다.
요약의 의미·충분성과 실제 호스트 도구 실행 여부는 호스트가 확인한다.
파일·Git 실행은 호스트가, 경로 검사와 관찰 보존은 runtime이 담당한다.

## 실제 접속 대상과 인증 문맥

실제 요청의 대상·인증은 등록한 연결에 바인딩한다.
비밀값은 전송 경계에서만 참조를 해소하고 설정·계획·결과에는 비밀 없는 참조를 사용한다.
인증 갱신과 실제 연결·대상 변경의 처리는 [등록부와 계약 변경](contract.md#등록부와-계약-변경)을 따른다.

| 제품 | 바인딩 |
|---|---|
| PostgreSQL | 단일 host·port·database·사용자와 password 또는 단일 URI; 대체 접속 옵션 검사 |
| Redis | host·port·db와 명시 인증; 등록 환경으로 실행 인수 생성 |
| Confluence·Jira | 등록 서버와 해당 토큰·계정; 대체 tenant·OAuth·서버 설정 검사 |
| 로컬 Source | 등록 디렉터리와 현재 OS 사용자; 호스트 도구의 접근 권한 |
| AWS | 제공자 profile·region·SSO 또는 역할의 등록 계정 |

DB의 새 setup은 공개 접속 정보와 비밀번호 참조를 사용한다.
자식 실행 직전에 사용자명·비밀번호·DB명을 인코딩한 URI를 구성해 인증 환경에 전달한다.
이 방식의 TLS는 `PGSSLMODE`의 `require`·`verify-ca`·`verify-full`을 받으며 기본값은 `require`다.
기존 URI 방식은 등록 host·port·database·선택 username과 대조하고 query는 단일 `sslmode`만 같은 허용값으로 받는다.
URI의 TLS 옵션을 생략한 기존 설정은 하위 연결의 기본값을 사용한다.
비밀번호·기존 URI 중 인증 참조 한 개를 선택하며 두 방식이 함께 있으면 `UNSUPPORTED_CONSTRAINT`다.

Redis는 등록 host·port·db와 TLS·선택 username으로 실제 실행 인수를 구성한다.
Confluence·Jira는 등록한 서버의 명시적 토큰 참조를 해소하며 Jira의 토큰 선택은 [setup 인증](../configuration/profiles.md#공통-구조와-어댑터-입력)을 따른다.

AWS 인증은 등록 계정과 일치하는 제공자 SSO 또는 명시 역할의 표준 설정·캐시를 사용한다.
credential process·간접 토큰 파일·endpoint·CLI 플러그인·별칭 같은 대체 실행·인증 설정은 `UNSUPPORTED_CONSTRAINT`다.
계정·위치·인증 준비는 [profile과 로그인](../configuration/profiles.md#인증-저장과-전달)을 따른다.

실제 서비스 권한 철회·오류는 해당 서비스의 응답으로 확인한다.

## 호출·출력·실패

전송 직전에 등록 연결의 현재 인증을 해소하고 정규화 요청·하위 도구 계약을 다시 확인한다.
입력은 고정값·기본값 적용 전후 UTF-8 JSON 64KiB, 정규화 응답은 2MiB까지 처리한다.
응답 상한 초과는 본문이 null인 `RESULT_TRUNCATED`다.
하위 내부 페이지·재시도 수는 미측정 값 `null`, 외부 요청 상한 강제 지원은 `false`로 제공한다.

하위 출력 스키마가 있으면 원 응답과 비밀 제거 뒤 자료를 검사한다.
레거시 text·JSON·SDK result 포장은 공통 `data` 객체로 정규화한다.
표준 MCP image·resource·resource link 등 비텍스트 콘텐츠는 그 콘텐츠 블록을 표준 JSON 표현으로 보존한다.
이 표현은 바이너리 값을 포함한 자료이며 화면의 이미지·첨부 표시는 호스트의 렌더링 지원을 따른다.
스키마가 원래 구조화 결과를 직접 요구하는 기능에서 비텍스트 콘텐츠까지 함께 반환하면 현재는 `RESULT_VALIDATION_FAILED`다.
이 조합을 지원하려면 두 표현을 함께 처리하는 어댑터 정규화 계약이 필요하다.

DB의 기존 Python literal 응답은 262,144자·깊이 64·구문 노드 50,000개 안의 상수·컨테이너·유한 Decimal을 자료로 해석한다.
Decimal은 정확한 문자열과 해당 자료의 타입 경로로 보존한다.
해석 범위 밖의 날짜·타입 표현은 원 텍스트로 남긴다.
해소한 비밀과 파생 인증 문자열을 문자열·필드명에서 제거하고 타입·스키마·모호한 키 충돌을 검사한다.
자료의 제공·내보내기·보존은 현재 계획과 profile 정책을 함께 적용한다.

### 조회 완전성

호스트는 제공자의 total·cursor·has_more·잘림·시점과 실제 응답으로 후속 페이지와 완료 여부를 판단한다.
단건·표본·전체 조회는 각각 승인한 목표를 기준으로 처리한다.

현재 어댑터의 공통 `source_complete`는 알려진 후속·잘림 신호가 있으면 `false`, 그 밖에는 `null`이다.
자료의 `metadata`가 객체이면 그 안을, `metadata`가 생략됐으면 객체 자료 자체를 검사한다.
검사 신호는 `truncated`·`has_more`·`hasNextPage`·`next_cursor`·`nextToken`·`NextToken`·`next_page`의 값이다.
`false`인 결과는 확보한 본문·참조와 `partial`·`RESULT_TRUNCATED`로 제공하고 호스트가 승인한 목표에 맞게 후속 조회를 판단한다.
동일 시점 스냅샷이 필요한 업무는 제공자의 일관성 지원과 실제 관찰 시점을 함께 확인한다.
과거 페이지 근거·완전성 메타데이터의 저장 기록은 호환 열람 대상으로 유지한다.
보고·파일·기억의 출처와 현재 제공 권한은 [결과 계약](../mcp/tasks.md#daeri_result_submit)에서 검사한다.

### 오류와 확인 경계

진단·인증·실제 대상·도구 계약의 변경 처리는 [등록부와 계약 변경](contract.md#등록부와-계약-변경)을 따른다.
읽기 상태·오류와 단절 뒤 새 관찰은 [실행 결과와 오류](../mcp/resources.md#결과와-오류)가 정의한다.

로컬 시험 MCP에서 실제 stdio 탐색·호출·계약 변경·명시적 제한·연결 이탈·출력 경계를 확인한다.
고정 패키지의 읽기 모드와 메타데이터는 캐시된 설치 원문으로 대조했다.
실제 회사 리소스·제공자 권한·호스트 UI·Windows는 [구현 검증 경계](../../plans/initial-implementation.md#현재-구현-단위와-검증-경계)를 따른다.
