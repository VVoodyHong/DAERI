# 리소스 범주와 연결 기준

상태: 범용 포트·어댑터와 기존 MCP 재사용 확정; 읽기 어댑터와 하위 MCP 전송 구현, 모의 연결 검증

리소스를 역할로 분류하고 각 연결에서 확인할 기준을 정의한다.
아래는 역할별 예시이며 추가 범주는 같은 등록 계약으로 확장한다.
실제 사용 예정 제품은 [사용 예정 환경](../product.md#사용-예정-환경)에서 별도로 관리한다.

## 범주와 어댑터

범주는 에이전트가 리소스의 역할을 이해하는 공통 포트다.
사용자는 profile마다 필요한 범주와 그 범주를 연결할 어댑터를 선택한다.
같은 범주에 여러 제품·연결 방식·인스턴스를 함께 등록할 수 있다.

setup은 실제 준비 카탈로그의 `type`으로 범주를 묶고 먼저 필요한 범주를 선택하게 한다.
범주 설명에는 해당 범주의 `display_name`을 모두 보여 준다.
제품이 하나면 그 제품을 선택하고 여럿이면 선택받은 제품을 내부 recipe 식별자에 대응시킨다.
모든 범주는 같은 선택 흐름을 따르며 질문당 항목 수는 [호스트의 항목 제한](../hosts/plugins.md#setup의-정형-질문)을 따른다.
선택지는 카탈로그와 실행·검증 계약에 등록한 어댑터에서 생성한다.
추가 제품은 해당 계약과 검증을 갖춘 뒤 같은 선택 흐름에 포함한다.

| 범주 예시 | 역할과 기능 예시 | 계획에서 확인할 조회 범위 |
|---|---|---|
| DB | 자료 구조 탐색·조건 조회·집계 | 데이터 영역·객체·필드·기간·조회 한도 |
| Cache | 항목 탐색·값·상태 조회 | 저장 영역·항목 범위·자료형·조회 한도 |
| Infra | 인프라 구성·상태·관계 조회 | 계정·환경·위치·자원·허용 작업 |
| Source | 소스 구조·내용·변경 이력 조회 | 저장소·개정·경로·조회 범위 |
| Document | 운영 문서 검색·본문 조회 | 공간·문서·공개 범위·검색 조건 |
| Log | 실행 기록 검색·분석 | 서비스·로그 영역·기간·민감 정보 |
| Ticket | 이슈·업무 요청·진행 기록 조회 | 조직·프로젝트·티켓·접근 범위 |
| Mail | 업무 이력 검색·본문 조회 | 계정·함·기간·수신자·개인정보 |

에이전트는 사용자 목표·승인 범위에 맞춰 등록된 기능을 조합하고 새로운 업무의 방법·순서를 판단한다.
각 제품이 실제 제공하는 기능과 제약은 [리소스 계약](contract.md)에 맞춰 공개한다.

## 기존 MCP 선택 기준

먼저 해당 제품·환경에서 사용할 수 있는 기존 MCP를 검토한다.
공통 포트와 연결하는 데 필요한 검사·변환만 DAERI 어댑터에서 보완한다.

| 기준 | 확인할 내용 |
|---|---|
| 사용 가능성 | 사용자 환경·조직 정책·인증과 호환되는가 |
| 기능과 의미 | 필요한 기능·입출력·부분 결과·실패를 설명할 수 있는가 |
| 범위 강제 | 승인한 실제 대상·조회·자료 제공 한도를 지킬 수 있는가 |
| 처리 위치 | 로컬·원격 실행과 외부 전달 자료가 드러나는가 |
| 운영 적합성 | 유지보수·배포 출처·라이선스·필요 프로그램을 확인할 수 있는가 |
| 복구 가능성 | 중복·중단·미확인 실행과 재시도를 구분할 수 있는가 |

공식 제공 여부와 별개로 실제 입력·대상·효과·제약을 검사한다.
어댑터 선택을 바꿀 때 연결·인증·실행 효과가 달라지면 변경 내용을 확인한다.
실패는 원 연결의 상태로 보고하며 대체 연결이 필요하면 변경 대상·인증·효과를 확인한다.

## 범주별 의미 보존

같은 DB라도 자료 구조와 질의 의미가 다를 수 있다.
Cache의 전체 탐색·특정 항목 읽기와 Infra의 목록 조회·특정 자원 접근은 각각의 실제 접근 범위로 판정한다.
반환 결과를 줄이는 것과 원격으로 읽는 범위를 제한하는 것을 구분한다.

Source는 확인한 소스 개정을, Document는 읽은 문서와 그 시점을 결과 근거에 남긴다.
보고에는 검색한 영역·제공 권한·잘림과 누락 범위를 함께 표시한다.
여러 리소스의 결과를 비교할 때에는 기준·시점·완전성 차이를 함께 설명한다.

## 공개와 검증

최초 구현은 읽기·분석으로 연결과 승인 경계를 검증한다.
변경 기능은 효과·권한·중복 방지·완료 확인 조건을 갖춘 뒤 확장한다.

제품·버전·필요 프로그램은 해당 어댑터가 구체화될 때 [의존성 관리](../installation/environment.md#버전과-재현-가능한-환경)에 연결한다.
범주 예시와 실제 연결 검증은 구분하며 확인한 조합은 최초 구현 계획에 기록한다.
실제 검증 범위와 완료 기준은 [최초 구현 계획](../../plans/initial-implementation.md)을 따른다.

## 첫 버전의 실제 연결 방식

하위 MCP는 DAERI가 업무 자료를 읽는 수단이다.
호스트에는 profile에서 선택·진단한 읽기 기능을 등록한다.
호스트는 그 수단을 조합해 업무를 수행한다.

첫 버전은 표준 입출력으로 실행하는 로컬 MCP와 HTTPS Streamable HTTP MCP를 연결한다.
실행기는 공식 MCP SDK로 세션을 열고 도구 목록·입출력 스키마를 확인한다.
원격 전송은 명시한 HTTPS 주소·인증서 검사를 사용하고 리다이렉트 응답은 연결 오류로 처리한다.
프록시 사용 여부는 등록 전송 구현에서 결정하며 현재 구현은 직접 연결한다.

로컬 MCP는 준비된 실행 파일의 절대 경로·인수 배열과 별도 빈 작업 디렉터리를 사용한다.
패키지·인증 준비는 명시적인 관리 경로에서 수행한다.

실행 인수의 접속 대상·읽기 전용 모드는 등록 설정과 일치해야 하며 충돌하면 설정 검증에 실패한다.
프로그램 주입·암시적 프록시 환경 변수는 검증 오류로 반환한다.
TLS·서버 인증서 조건은 선택한 어댑터의 제품별 연결 검사로 확인한다.
제공자 환경 변수는 표준 대문자 이름으로만 받아 운영체제의 대소문자 처리 차이로 대상이 달라지는 것을 막는다.
인증 참조는 어댑터가 정한 자격 증명 필드에 연결한다.
서버 주소·HTTP 라우팅 헤더는 검증 가능한 일반 연결 설정으로 해소한다.

제품별 배포 출처·고정 버전·실행 파일·인증 환경 변수·초기 도구는 [연결 카탈로그](../../../src/daeri/catalog.json)에서 관리한다.
카탈로그의 `display_name`은 사용자가 선택할 때 보는 제품 이름이고 키는 설정·준비에 사용하는 내부 식별자다.
카탈로그는 설정의 시작점이다.
접속 대상과 연결 진단을 확인하면 업무 기능으로 등록한다.
기존 관리 설정의 조회 상한은 함께 유지하고 업무별 실제 대상은 승인한 계획으로 정한다.
프로그램 준비와 명령은 [개발 의존성과 실행](../../development/dependencies.md), 사용자 설정의 의미는 [profile](../configuration/profiles.md)이 소유한다.

`recipes/<recipe-id>/`는 구체 MCP의 패키지·잠금 조합을 분리하는 설치 단위다.
`db-postgres` 같은 제품별 이름은 구체 설치 단위를 식별한다.
공통 역할은 범주가, 대상 설정안·로그인 방식은 선택한 어댑터가 정의한다.

## 등록 설정과 진단

profile의 `resources`에는 필요한 인스턴스를 여러 개 넣을 수 있다.
각 인스턴스는 다음 내용을 가진다.

| 설정 | 의미 |
|---|---|
| `instance_id`, `type` | profile 안의 고유 인스턴스와 DB·Cache 등의 범주 |
| `adapter` | 실제 요청을 해석하는 아래의 읽기 어댑터 |
| `target` | 접속 대상과 실제 저장 영역을 비교할 비밀 없는 정보 |
| `identity_ref` | 해당 연결 주체를 식별하는 로컬 참조 |
| `connection` | 전송 방식, 실행 파일·인수 또는 HTTPS 주소 |
| `capabilities` | 선택한 하위 도구와 접근 상한 |
| `policy` | 모델 제공·내보내기·보존·기억의 허용 범위 |

`capabilities`의 각 항목은 `capability_id`, 실제 `tool_name`, `constraints`를 가진다.
설정의 인증 값은 `auth_env` 또는 `auth_headers`의 인증 참조로 연결한다.
자격 증명은 로컬 저장소의 참조로 등록하고 실행기가 전송 경계에서 해소한다.

명시적인 진단은 선택한 MCP를 시작하고 세션·선택 도구·스키마·접근 조건을 확인해 등록부를 저장한다.
선택 도구·계약 검증에 실패하면 `CONNECTION_NOT_READY` 등 해당 오류를 반환한다.
업무 자료 조회는 별도의 계획 승인 뒤 수행한다.

등록부에는 profile 개정·설정 지문·도구 계약·인증 문맥 지문을 연결한다.
인증 문맥은 사용자 저장소의 전용 키로 만든 HMAC 지문으로 비교한다.
도구 의미·입출력·연결·인증 문맥이 바뀌면 `CONTEXT_CHANGED`로 차단하고 진단·계획 승인을 다시 받는다.

### 범위 조건

설정의 `constraints`는 연결에서 허용할 최대 범위다.
업무 계획의 `scope`는 그 안에서 이번 업무에 허용하는 범위를 더 좁힌다.
기본 setup은 접속 정보·공개 인증 설정을 받고 조회 대상은 계획에서 정한다.
새 Source·Document 연결의 `target`은 서버 주소이며 같은 서버의 실제 저장소·문서는 계획의 명시 조건으로 검사한다.
접속값 갱신은 기존 `target`의 추가 정보·조회 상한·자료 정책을 보존한다.
상시 조회 상한이 필요한 관리자는 전체 JSON의 `capabilities[].constraints`를 설정할 수 있다.
기능 계약의 `scope_schema.x-daeri-access-constraints`에서 등록한 상한을 확인할 수 있다.
모든 실제 전송 인수에는 해석 가능한 승인 조건이 있어야 한다.
하위 스키마가 명시한 기본값도 최종 인수에 포함해 검사한다.

| 연결 상한 | 계획 조건 | 검사 |
|---|---|---|
| `fixed` | `equals` | 대상·고정 값을 정확히 비교; 호출자가 덮어쓰면 거부 |
| `allowed_values` | `one_of` 또는 `equals` | 값 또는 배열의 모든 항목이 허용 목록에 포함되는지 확인 |
| `path_prefixes` | `path_prefixes` 또는 `equals` | 경로 요소 단위로 포함 관계 검사 |
| `max_values` | `max_values` 또는 `equals` | 실제 숫자가 연결 상한과 승인 상한 모두 이하인지 확인 |
| `tables`, `columns`, `max_rows` | 같은 필드 | DB 구문을 해석해 실제 접근·전체 또는 명시 목록·조회 결과 상한 검사 |

경로는 정규 상대 경로와 허용 접두사를 비교하며 상위 이동·역슬래시·URL 인코딩·간접 URL은 범위 검증에 실패한다.
알 수 없는 제약이나 승인 조건이 없는 인수는 실행 전에 거부한다.
원격 접근은 실제 요청으로, 출력 필드·마스킹은 결과 제공 단계에서 각각 검사한다.

## 어댑터별 실제 지원 경계

| 어댑터 | 입력과 수행 | 결과와 제한 |
|---|---|---|
| `postgres_read` | PostgreSQL 문법의 SQL; 명시한 스키마의 단일 테이블 `SELECT`, 허용 필드·일부 집계·조건 | 조회 자료; 서버에 보낼 SQL에 결과 행 상한 적용 |
| `redis_read` | 등록한 읽기 도구와 정확한 항목 키 | 정확한 항목 키의 읽기 결과; 지원 입력·연산 검사 |
| `aws_read` | 파싱 가능한 단일 조회 명령과 명시한 위치 | 선택한 조회 자료; 검증한 조회 연산만 허용 |
| `gitlab_read` | GitLab 저장소·개정·상대 경로 등 구조화된 인수 | 명시한 프로젝트·개정·상대 경로의 파일·구조·조회 결과 |
| `confluence_read` | Confluence 문서·공간 등 구조화된 식별자 | 명시한 공간·문서의 조회 결과; 지원 입력·질의 검사 |

setup으로 생성하는 최초 기능은 다음과 같다.

| 범주 | DAERI 기능 ID | 선택한 하위 MCP 도구 |
|---|---|---|
| DB | `query` | `execute_sql` |
| Cache | `read-key` | `get` |
| Infra | `describe` | `call_aws` |
| Source | `read-file` | `gitlab_get_file` |
| Document | `read-page` | `confluence_get_page` |

연결 진단은 명시한 도구만 등록하며 호스트는 해당 기능의 계약을 읽고 승인 범위 안에서 호출 방법을 정한다.
같은 어댑터의 추가 읽기 도구는 [관리 등록](../configuration/profiles.md#관리-등록과-진단)에서 도구별 입력·제약을 설정하고 진단해 등록한다.

새 설정안은 위 식별자를 사용한다.
기존 `sql_read`·`source_read`·`document_read`는 각각 `postgres_read`·`gitlab_read`·`confluence_read`의 호환 이름으로 해석한다.
호환 이름은 기존 제품의 구현을 선택한다.
기존 profile·업무 스냅샷·등록 계약은 저장한 식별자와 개정을 유지한다.
실제 대상·인증·도구 의미가 바뀌면 [계약 변경](contract.md#등록부와-계약-변경) 규칙을 적용한다.

현재 DB 파서는 명시한 스키마의 단일 테이블 `SELECT`와 등록한 집계·조건을 지원한다.
지원 문법·효과 밖의 질의는 `SCOPE_VIOLATION` 또는 `UNSUPPORTED_CONSTRAINT`로 반환한다.
허용 집계는 `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`다.
새 DB 연결은 내부 조회 상한을 `tables: ["*"]`, `columns: ["*"]`, `max_rows: 100`으로 구성한다.
이는 연결 계정이 읽을 수 있는 현재 데이터베이스의 테이블·컬럼을 계획에서 선택할 수 있다는 뜻이다.
실제 SQL은 승인한 계획의 테이블·컬럼·행 수·인수 조건을 통과해야 한다.
현재 연결한 데이터베이스 안에서 새로 생긴 테이블도 계정의 조회 권한과 계획 승인으로 접근한다.

전체 JSON의 상시 조회 상한과 계획의 DB 범위는 단독 `["*"]` 또는 구체적인 이름 목록으로 표현한다.
혼합 표기·필수값 누락은 범위 검증에 실패한다.
테이블 목록은 하나 이상이며 빈 컬럼 목록은 행값 접근 0개로 해석한다.
기존에 구체적인 `스키마.테이블`·컬럼·행 수 상한을 설정한 연결은 접속값 갱신 후에도 그 제한을 유지한다.
실제 허용 범위는 연결 상한과 업무 승인 범위의 교집합이다.
`SELECT *`·`테이블별칭.*`는 양쪽 컬럼 범위가 전체일 때만 허용하며 실제 접근 기록의 컬럼은 `["*"]`로 남긴다.
`COUNT(*)`는 행 수 집계로 해석하므로 빈 컬럼 목록에서도 사용할 수 있다.

결과 행 상한은 반환 행 수를 제어한다.
원격 스캔량·비용은 별도 측정·강제 계약과 제공자 정책의 대상이다.
DB 자체의 최소 조회 권한과 하위 MCP의 읽기 전용 실행 모드를 함께 설정해야 한다.
업무 실행·자료 제공·보관은 현재 계획의 리소스별 허용을 확인한다.
구조 파악이 필요하면 메타데이터 조회를 계획에 포함해 승인받는다.
기간·필터까지 고정해야 하는 업무는 `scope.equals.sql`로 실제 SQL을 정확히 승인한다.
기간·행 조건의 강제 여부는 계획에 명시한 실제 SQL·제약으로 판정한다.

새 Cache·Source·Document 연결의 기본 `constraints`는 빈 객체다.
계획은 Cache의 정확한 키, Source의 저장소·개정·정규 경로, Document의 공간·페이지 식별자를 승인 범위로 명시한다.
어댑터는 호출의 명시적인 인수·승인 조건과 실제 조회 대상을 대조한다.
자료 제공·보관·기억은 연결의 `policy`와 계획의 별도 허용을 함께 만족해야 한다.

Infra는 서비스·연산·위치·인수를 해석해 아래 조회 연산과 등록한 계정·위치·profile·접속 대상에 일치하는 단일 명령을 전달한다.
대상 변경 옵션·중복 위치 옵션·로컬 파일 참조는 축약 형태와 인수 안의 표현까지 검사해 거부한다.
현재 연산 집합은 인스턴스·네트워크·스토리지·DB 구성·로그 그룹 등의 등록된 조회다.
추가 연산은 효과·대상·입력 검사를 구현한 뒤 등록한다.

| Infra 서비스 | 현재 허용 연산 |
|---|---|
| `ec2` | `describe-instances`, `describe-security-groups`, `describe-vpcs`, `describe-subnets`, `describe-volumes` |
| `rds` | `describe-db-instances`, `describe-db-clusters` |
| `logs` | `describe-log-groups` |
| `cloudwatch` | `list-metrics` |
| `sts` | `get-caller-identity` |

Document는 페이지·공간 식별자에 대한 구조화된 인수를 해석한다.
현재 어댑터에서 `query`·`cql`·`url` 인수는 `UNSUPPORTED_CONSTRAINT` 대상이며 자연어·질의식 검색은 확장 범위다.
읽기 도구의 이름이 검색을 포함해도 실제 실행 가능성은 위 입력·범위 조건으로 판정한다.

Source·Document의 접근 범위는 하위 MCP가 실제로 읽는 원본으로 판정한다.
파일 전체를 읽고 일부를 반환하는 기능은 해당 파일 전체의 접근 승인이 필요하다.
계획의 더 좁은 접근 조건을 강제할 수 없으면 `UNSUPPORTED_CONSTRAINT`로 반환한다.

이 목록은 최초 검증한 수단의 경계다.
새 도구·제품은 [등록 계약](contract.md)의 대상·효과·제약을 해석하는 어댑터와 검증을 추가해 확장한다.

### 실제 접속 대상과 인증 문맥

DB는 인증 참조에서 해소한 접속 URI의 호스트·포트·DB 이름을 `target`과 비교한다.
접속 URI는 직접 명시한 단일 호스트·포트·DB로 해소하며 간접 서비스 파일·대체 호스트·세션 시작 옵션은 설정 검증에 실패한다.
명시한 URI의 `sslmode`와 환경 변수 `PGSSLMODE`는 `require`·`verify-ca`·`verify-full`을 허용한다.
생략한 TLS 옵션은 하위 연결의 기본값으로 해소하므로 회사가 요구하는 검증 방식은 실제 접속 설정에서 확인한다.
Cache는 설정한 호스트·포트·저장 영역을 비교한다.
선택한 Cache MCP에는 환경 설정과 동일한 대상의 명시적 실행 인수를 생성한다.
비밀번호는 지정한 인증 참조에서 해소해 자격 증명 환경 변수로 전달한다.
별도 접속 URL 등 대상과 충돌하는 설정은 검증 오류로 반환한다.
Source·Document는 연결의 서버 주소와 등록 대상이 일치해야 한다.
현재 로컬 어댑터는 명시한 토큰 참조를 해소해 인증한다.

Infra는 명시한 제공자 profile·위치와 로컬 설정의 계정 또는 역할 계정을 대조한다.
사용한 제공자 설정·인증 파일이 바뀌면 기존 호출을 차단하고 다시 진단한다.
진단 완료에는 제공자 profile에서 실제 계정을 확인할 수 있는 지원 인증 구성이 필요하다.

제공자 로그인으로 만든 표준 SSO 세션과 캐시를 사용할 수 있다.
선택한 profile과 연결된 원본 profile에 임의 인증 프로그램·간접 토큰 파일·메타데이터 인증·별도 endpoint 설정이 있으면 거부한다.
실행 대상·프로그램을 변경하는 전역 플러그인·명령 별칭은 설정 검증에서 거부한다.
하위 MCP에는 등록한 profile·위치·읽기 전용 모드를 고정하고, 별도 endpoint·메타데이터 인증·에이전트 스크립트·로컬 파일 접근을 차단하는 설정을 전달한다.
SSO 토큰을 갱신한 경우에도 인증 문맥이 바뀌므로 다시 진단하고 새 계획을 승인한다.

이 제한은 [제공자 설정 파일](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-files.html)과 [환경 변수 우선순위](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-envvars.html)에 따른 DAERI의 지원 경계다.
추가 인증 방식은 실제 계정·대상 확인과 설정 변경 검사를 갖춘 뒤 확장한다.

이는 진단한 대상·자격 증명과 실제 전송의 연결을 보호하는 검사다.
로컬 지문은 등록한 설정·인증 문맥을 비교한다.
원격 권한 철회·서비스 변경은 실제 제공자의 응답으로 확인하고 원 연결의 오류로 보고한다.

## 호출·출력·실패

승인과 예산 검사는 [업무 실행 계약](../tasks/workflow.md#실행-검사와-기록)이 담당한다.
어댑터는 같은 확정 요청을 전송하기 직전에 현재 인증 지문과 하위 도구 계약을 다시 확인한다.
현재 전송은 하위 MCP 내부 요청량을 미측정으로 기록하며 `external_requests_enforceable=false`를 제공한다.

연결 하나의 도구 탐색은 최대 8페이지·512개 도구를 처리한다.
도구 이름은 고유해야 하고 입출력 스키마는 로컬 참조로 해소하는 최상위 객체여야 한다.
탐색 한도·스키마 조건을 벗어나면 등록을 실패로 반환한다.
한 번의 호출 인수는 JSON 직렬화 기준 64KiB, 정규화한 하위 응답은 2MiB까지 처리한다.
응답 상한을 넘으면 `RESULT_TRUNCATED`로 반환하고 본문은 미제공 상태로 기록한다.

등록된 출력 스키마가 있으면 구조화된 응답과 비밀 제거 후 응답을 모두 검증한다.
스키마가 없는 레거시 응답은 `data` 필드 안에 JSON 자료 또는 텍스트를 담는 공통 객체로 정규화한다.
DB·Cache·Infra 어댑터는 기존 SDK가 자동으로 씌운 `result`·텍스트 포장도 하위 스키마로 검증한 뒤 같은 `data` 객체로 정규화한다.
이 세 어댑터의 공개 출력 계약은 하위 전송용 스키마와 구분한다.
다른 어댑터도 SDK가 명시한 결과 포장 표식이 있으면 해당 포장을 해소한다.
직접 구조화된 스키마의 수치 형식·단위는 정규화한 스키마에 보존한다.
JSON은 고유 키·유한 숫자를 요구하며 수치 형식·단위는 등록 출력 스키마를 따른다.

DB의 기존 MCP가 Python 리터럴 형태로 반환한 자료는 제한된 크기·깊이 안에서 리터럴만 해석한다.
`Decimal('문자 리터럴')`은 어댑터가 정한 유한 10진수로만 해석하고 정확한 문자열과 수치 타입 경로를 함께 남긴다.
수치 타입은 하위 스키마와 위 지원 리터럴에서 해소한다.
리터럴 파서는 등록한 상수·컨테이너·유한 Decimal 표현을 처리한다.
그 외 함수·코드를 포함한 해석 실패 자료는 원래 텍스트로 보존한다.
지원 밖 날짜·타입 표현은 텍스트로 보존하며 계산에는 검증한 구조화 자료를 요구한다.

### 조회 완전성

`source_complete`는 원격 응답을 받은 사실과 별개로 조회 범위의 전체성을 나타낸다.
공통 검사는 `truncated`·`has_more`·다음 페이지 토큰처럼 알려진 잘림 신호가 있으면 `false`를 반환한다.
현재 어댑터는 다음 조건으로 그 외의 응답을 판정한다.

| 어댑터 | 잘림 신호가 없는 응답의 판정 |
|---|---|
| DB | 배열의 행 수가 실제 결과 상한 이상이면 `false`, 그 외 `null` |
| Cache | 도구 이름이 정확히 `get`이면 `true`, 그 외 `null` |
| Source | `gitlab_get_file`·`get_repository_file`의 전체 파일 읽기에 명시적인 `truncated: false`가 있으면 `true`, 그 외 `null` |
| Infra·Document | `null` |

Source의 전체 파일 조건은 `start_line`·`end_line`·`limit` 생략과 `offset` 생략 또는 0이다.
`null`은 원본 완전성 미확인이며 확보한 자료 자체는 허용 범위 안에서 사용할 수 있다.
현재 [결과 검증](../mcp/tasks.md#파생-표와-셀-검증)은 전체 표와 호출 근거의 완료 조건 충족에 `true`를 요구한다.
따라서 완전성이 미확인인 조회는 일부 표·파일·부분 보고로 제공하고 해당 완료 조건의 제한을 남긴다.
새 전체성 판정은 제공자의 페이지·잘림·범위 의미를 확인한 어댑터와 검증을 추가해 확장한다.

### 오류와 확인 경계

| 상황 | 처리 |
|---|---|
| 진단 전·실행 파일 누락·연결 실패 | `CONNECTION_NOT_READY`; 설정·인증·진단 안내 |
| 인증 참조 미해소 | `AUTHENTICATION_REQUIRED`; 안전한 인증 경로 안내 |
| 대상·인증·계약 변경 | `CONTEXT_CHANGED`; 이전 승인으로 실행 차단 |
| 범위 밖 요청 | `SCOPE_VIOLATION`; 요청 정정 또는 수정 계획 |
| 해석·강제 불가능한 조건 | `UNSUPPORTED_CONSTRAINT`; 미지원 조건 설명 |
| 하위 도구의 명시적 오류 | `EXTERNAL_EXECUTION_FAILED`; 비밀 없는 오류 코드·상태 제공 |
| 단절·시간 초과 | `EXTERNAL_OUTCOME_UNKNOWN`; 원 호출의 미확인 상태·확인 절차 유지 |
| 출력 계약 불일치 | `RESULT_VALIDATION_FAILED`; 본문 참조 대신 검증 실패 상태 제공 |
| 반환 자료 크기 상한 초과 | `RESULT_TRUNCATED`; 크기 제한·불완전 상태 반환 |

로컬 모의 MCP 프로세스로 실제 세션·도구 탐색·호출·시간 초과·계약 변경을 검증했다.
범위 이탈·다른 profile·SQL 변경·경로 탈출·Infra 명령 변경·인증 교체의 거부도 검증했다.
Infra의 설정 파일·환경 변수·축약 옵션을 통한 우회 거부와 표준 SSO 로그인 설정의 수용도 임시 파일로 검증했다.
실제 조직 리소스의 인증·권한·자료·네트워크와 Windows 실행은 별도 설치 환경에서 확인해야 한다.
