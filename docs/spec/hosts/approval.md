# 호스트 대화에서의 사용자 승인

상태: Claude Code·Codex의 계획 제시·실제 응답 연결 구현; 실제 호스트 대화 검증은 별도

사용자는 업무를 요청한 대화에서 계획을 확인하고 승인·수정·거절 의사를 밝힌다.
승인 범위는 [계획 명세](../tasks/approval.md), 공개 입력은 [계획 MCP](../mcp/plans.md)가 소유한다.

## 화면과 사용자 흐름

호스트는 저장한 계획에서 사용자 결정에 필요한 목적·대상·수행 방법·예상 결과와 명시한 범위를 제시한다.
수정 계획에는 변경 이유와 이미 수행한 내용·남은 작업을 함께 설명한다.

1. 호스트가 계획을 제출하면 runtime이 저장과 승인 대기를 함께 만든다.
2. 호스트가 현재 계획을 사용자에게 제시하고 실제 응답을 기다린다.
3. 호스트가 실제 답변·대상 계획·해석한 결정을 전달한다.
4. runtime이 연결과 상태를 확인해 기록하고 승인된 업무를 실행 상태로 바꾼다.
5. 호스트가 같은 범위에서 자율적으로 수행하고 사용자 요청에 맞는 결과와 필요한 조치를 전달한다.

가상 예시: “DB와 Cache를 비교해 차이를 CSV로 만들고 확인한 절차를 기억하겠습니다”라는 계획에 사용자가 “진행해”라고 답하면 해당 범위로 실행한다.
기간·대상 변경이 포함된 답변은 수정 계획에 반영해 다시 제시한다.

### 결정별 처리

| 실제 응답의 가상 예시 | 처리 |
|---|---|
| “진행해”, “이 계획대로 해” | 현재 계획의 명확한 승인 |
| “좋아, 기간은 줄여 줘” | 조건을 반영한 수정 계획 |
| “거절할게” | 업무를 유지하고 계획 단계로 복귀 |
| “이 확인 요청만 취소해 줘” | 승인 대기 취소 |
| “잠시 멈춰”, “업무 취소해” | 해당 업무의 일시중지·취소 |
| 질문·모호한 대상·응답 부재 | 승인 대기 유지·필요한 설명 |

호스트는 답변의 의사와 현재 대상·대화 맥락을 함께 판단한다.
공개 결정값과 상태 전이는 [승인 MCP](../mcp/plans.md#approvaloutcome과-실제-응답)를 따른다.

## 승인 응답 검증

호스트는 실제 사용자 메시지의 출처와 의미를 확인하고 알려진 비밀값을 가린 실제 답변을 전달한다.
runtime은 현재 업무·계획·대기 상태와 선택 기억의 유효성을 확인하고 답변·결정·시각을 연결해 보존한다.
기억의 만료·정정은 근거 상태로 안내하고 호스트가 같은 승인 범위의 새 관찰로 보완한다.
메시지 참조가 제공되는 호스트는 해당 답변과의 대응도 함께 남긴다.

현재 계획이 바뀌면 새 계획을 확인받고 일시중지 뒤에도 현재 조건에 새 승인을 받는다.
상세 무효화 조건은 [승인 수명](../tasks/approval.md#중단과-승인-수명), 실제 호출은 [실행 검사](../tasks/workflow.md#실행-검사와-기록)를 따른다.

## 대화 승인의 범위

실제 사용자 메시지의 출처 구분과 자연어 해석은 호스트의 책임이다.
runtime은 전달된 답변과 저장한 계획·상태의 연결을 검사한다.
리소스 문서·코드·로그·기억은 분석 자료이며 사용자 결정은 실제 대화 응답에서 해소한다.

호스트의 도구 실행 권한과 DAERI 업무 계획 승인은 각자의 범위에 적용된다.
대화 재개·호스트 전환 시 저장한 현재 업무·계획·응답에서 실행 여부를 확인한다.

## 구현 시 검증

로컬 테스트는 명확한 승인·수정·거절·모호한 응답·오래된 계획·중복 전달·일시중지 뒤의 상태 연결을 검증한다.
실제 Claude Code·Codex에서는 계획 제시 → 실제 답변 해석 → runtime 기록 → 실행을 확인한다.
호스트별 화면·도구 연결·응답 의미 해석과 회사 연결은 별도 실제 사용 검증 대상이다.
