# 호스트 대화에서의 사용자 승인

상태: Claude Code·Codex 대화 승인 채택; 호스트 연동 실행 미검증

사용자는 업무 계획을 읽은 Claude Code·Codex 대화에서 승인하거나 수정을 요청한다.
승인할 내용은 [계획·승인](../tasks/approval.md), 도구의 역할은 [계획 MCP 규격](../mcp/plans.md)을 따른다.

## 선택한 경로와 이유

계획 제시부터 사용자 응답·결과 보고까지 같은 호스트 대화에서 진행한다.
호스트가 사용자 의사를 해석하고 실행기가 대상·계획·상태·권한을 검증하는 경로를 채택한다.
두 호스트의 표현 방식이 달라도 승인 대상과 처리 의미는 같다.

명확한 승인 응답은 해당 업무의 현재 계획과 허용 범위에 적용한다.
DAERI는 승인한 수행 방법·리소스·자료·예산 안에서 도구·조회·비교·검증 순서와 다음 행동을 판단한다.
범위 확대가 필요하면 이유와 수정 계획을 제시하고 다시 승인받는다.

## 화면과 사용자 흐름

호스트는 실행기에 저장한 현재 계획의 수행 방법·대상·조건·범위를 읽기 쉬운 요약으로 제시한다.
사용자는 요약과 연결된 현재 계획 전체에 대해 응답한다.

| 사용자가 확인할 내용 | 설명 |
|---|---|
| 업무·대상 | 요청, 사용할 profile과 리소스 |
| 수행 방법 | 어떤 자료를 조회·비교·계산하고 무엇을 검증할지 |
| 허용 범위 | 대상·조건·기간·한도와 허용한 작업 |
| 자료 제공 | 리소스별 모델 제공·내보내기·보관 범위와 마스킹 |
| 기억 활용·보존 | 참고한 기억·추가 확인, 새 지식의 범주·미래 제공·보존 범위와 기간 |
| 기대 결과 | 보고서·표·CSV 등 결과물과 완료 판단 근거 |
| 수정 계획 | 바뀐 범위, 이유, 이미 진행한 내용과 남은 작업 |

1. 호스트가 현재 계획을 저장하고 `daeri_approval_request`로 승인을 요청한다.
2. 호스트가 계획과 허용 범위를 대화에 제시하고 실제 사용자 응답을 기다린다.
3. 사용자가 같은 대화에서 승인·수정 요청·거절 의사를 밝힌다.
4. 호스트가 실제 답변과 대화 맥락에서 결정을 해석해 응답 전달 단계로 보낸다.
5. 실행기가 현재 업무·계획·대기 요청·권한을 검사하고 실제 답변과 결정을 연결해 기록한다.
6. 유효한 승인이면 호스트가 범위 안에서 자율적으로 실행하고 결과를 보고한다.

가상 예시: “이 profile의 DB와 Cache를 조회해 차이를 비교하고 허용 필드만 CSV로 만들겠습니다”라는 계획에 사용자가 “승인할게”라고 답하면 그 계획을 승인한다.
조건 추가·방법 변경이 포함되면 새 조건을 반영한 계획부터 다시 제시한다.

### 결정별 처리

| 실제 사용자 응답의 가상 예시 | 호스트 해석과 처리 |
|---|---|
| “승인할게”, “이 계획대로 진행해” | 현재 계획 전체를 명확히 가리키면 `approve` |
| “좋아, 다만 조회 기간은 줄여 줘” | `request_changes`; 새 조건을 반영한 계획을 다시 제시 |
| “이 계획은 거절할게” | `decline`; 업무를 유지하고 계획 단계로 돌아감 |
| “이 확인 요청만 취소해 줘” | `cancel`; 확인 요청만 종료 |
| “업무를 잠시 멈춰 줘” | 업무 일시중지 도구로 처리 |
| “업무를 취소해 줘” | 업무 취소 도구로 처리 |
| 질문·인용·불명확한 대상·모호한 의도 | null; 승인 대기를 유지하고 설명·확인 |

해석은 실제 사용자 답변의 명확한 의사와 현재 대상·대화 맥락을 함께 근거로 한다.
여러 업무 뒤 “응”처럼 대상이 모호하면 null이며 대화 종료·응답 부재도 승인 대기를 유지한다.
공개 enum·상태 전이·도구 연결은 [승인 MCP](../mcp/plans.md#approvaloutcome과-실제-응답)가 정본이다.

## 승인 응답 검증

호스트는 자연어 의미를 해석하고 실행기는 구조화된 대상·상태·권한을 검사한다.
계획 변경은 수정 계획의 저장·확인 경로로 처리한다.

| 담당 | 확인할 내용 |
|---|---|
| 호스트 | 실제 사용자 메시지의 출처 확인 |
| 호스트 | 승인 대상과 조건 변경·질문·거절 의도 해석 |
| 호스트 | 비밀 제거 후 실제 답변을 결정과 함께 원문으로 전달 |
| 실행기 | 업무·profile·계획·버전·표시본·대기 요청의 연결과 현재 승인 권한 검사 |
| 실행기 | 계획 교체·일시중지·취소·전제 변경·기록 만료와 멱등 중복 검사 |

사용자 결정의 출처는 실제 사용자 메시지다.
모델 설명·리소스의 코드·로그·문서는 업무 판단 자료로 취급한다.
호스트가 메시지 참조를 제공하면 실제 답변과의 대응을 함께 보존한다.
메시지 참조의 제공 여부는 호스트 기능에 따르며 그 값은 저장한 대응 검사에 사용한다.

계획 교체 뒤 이전 계획의 응답은 이전 대상의 응답으로 처리하고 현재 계획의 승인 대기를 유지한다.
일시중지 업무는 상태·계획을 다시 제시하고 새 승인을 받아 이어간다.
실제 호출은 [현재 권한·범위 검사](../tasks/workflow.md#실행-검사와-기록)를 통과해야 한다.
승인 직전에도 계획의 [기억 참조](../tasks/memory.md#계획-전-조회와-활용)를 재검사한다.
현재 승인 무효화 조건과 시간 만료·개별 철회의 확장 범위는 [승인 수명](../tasks/approval.md#취소철회만료와-hitl-완화)을 따른다.

## 대화 승인의 범위

자연어 의사의 출처 구분과 의미 해석은 호스트를 신뢰하는 경계다.
실행기가 확보하는 근거는 호스트가 전달한 실제 답변·결정·대상·메시지 참조다.
자연어 해석의 정확성은 이 경계에 의존하고 실행기는 저장한 연결·상태·권한·중복 검사를 담당한다.

호스트의 도구 실행 허용과 업무 계획 승인은 각각의 범위를 만족해야 한다.
답변 대상·의미가 모호하면 null로 전달해 승인 대기를 유지한다.
현재 요청·계획과 연결 검증에 실패하면 현재 상태를 유지한다.
호스트 전환·대화 재개 시 [업무 기록](../tasks/workflow.md)에서 현재 계획·결정을 확인한다.

## 구현 시 검증

Codex·Claude Code 각각에서 계획 제시 → 실제 사용자 응답 → 실행기 기록 → 실행을 확인한다.
호스트별 연결·표시·응답 의미 해석은 별도의 실제 사용 검증 대상이다.

명확한 승인, 동의와 조건 변경, 질문·모호한 답변, 거절·응답 부재의 상태를 확인한다.
업무 일시중지·취소·확인 요청 취소는 각각의 도구·상태로 연결하는지 확인한다.
오래된 계획 응답·자료 속 승인 문구·다른 계획의 참조·결정 변경 재전달·재연결에도 대상·범위 검사가 유지되어야 한다.
실제 호스트의 대화 전달·표시·승인 기록은 미검증이다.
