# 업무 흐름과 실행 상태

상태: 실행 흐름·상태·재개 동작 설계 제안

업무의 진행과 상태를 확인할 관리자·설계 담당자·에이전트를 위한 명세다.

이 문서는 업무의 단계와 실행 상태, 중단·재개의 동작을 정의한다.
업무 종류는 사전에 고정하지 않는다.
계획과 실행 범위의 승인 조건은 [승인 명세](approval.md)를 따른다.

## 요청에서 결과까지

다음 흐름은 업무 수행을 위한 설계 초안이다.

| 단계 | 사용자가 이해할 동작 |
|---|---|
| 요청 접수 | 자연어 요청, 요청자·부처·환경, 원하는 결과를 업무로 보존한다. |
| 리소스 탐색 | 접근 가능한 리소스와 기능·제약을 확인해 가능한 수행 방법을 찾는다. |
| 계획 작성 | 수행 방법·범위·분기·한도·완료 조건과 예상 결과물을 설명한다. |
| 계획 확인 | 사용자가 승인, 수정 요청 또는 취소한다. |
| 실행 | 호스트가 다음 행동을 선택하고 DAERI가 범위와 현재 권한을 검사해 호출한다. |
| 검증 | 실제 결과로 완료 조건과 누락·잘림·부분 실패를 확인한다. |
| 보고 | 결과물, 실제 수행 내역, 근거, 검증 결과와 남은 제한을 제공한다. |

결과를 바꾸는 대상·조건이 모호하면 필요한 정보만 묻는다.
계획 전 탐색과 계획 항목은 [승인 명세](approval.md)에 있다.
검증과 보고의 상세 계약은 [결과 명세](results.md)에 있다.

## 실행 상태

실행 상태는 업무 종류와 관계없이 공통으로 관리한다.
다음 이름은 설계 제안이다.

| 상태 | 의미 |
|---|---|
| `planning` | 계획 작성 중 |
| `awaiting_input` | 대상·조건에 필요한 답변 대기 |
| `awaiting_approval` | 현재 계획 버전의 사용자 확인 대기 |
| `running` | 승인 범위의 실행 중 |
| `verifying` | 완료 조건과 결과 확인 중 |
| `succeeded` | 완료 조건을 충족하고 결과·근거 보존 |
| `partial` | 일부 결과나 변경은 있으나 전체 완료 조건 미충족 |
| `failed` | 오류로 중단; 이미 발생한 결과·변경도 보고 |
| `cancelled` | 취소로 추가 실행 중단; 이미 발생한 결과·변경도 보고 |

범위 변경이 필요하면 `running`에서 새 계획 작성과 승인 대기로 돌아간다.
수정 계획의 확인 절차는 [승인 명세](approval.md)를 따른다.

## 재개와 재시도

세션 재개는 저장한 상태에서 이어 간다.
이때 승인·현재 권한·대상 상태를 다시 확인한다.

외부 작업의 성공 여부가 불명확하면 먼저 상태를 확인한다.
상태를 알 수 없는 변경을 무조건 재시도하지 않는다.

변경 작업의 자동 재시도는 어댑터의 중복 방지 또는 안전한 재시도 계약이 있을 때만 가능하다.
여러 리소스 변경이 하나의 트랜잭션으로 함께 성공한다고 보장하지 않는다.
어댑터별 재시도 의미는 [리소스 계약](../resources/contract.md)에 둔다.

## 취소와 외부 작업

취소해도 이미 발생한 변경은 자동으로 사라지지 않는다.
중단할 수 없는 외부 작업은 진행 상태를 확인해 보고한다.

이 동작을 설명하는 사례는 [가상 사례](scenarios.md)에 있다.
