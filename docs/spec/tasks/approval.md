# 계획과 승인 명세

상태: 불변 계획·대화 응답 연결·승인 범위 검사 구현; 원격 변경·자동 승인은 후속 범위

초기에는 총괄(root)이 분석·조회도 포함해 전체 수행 방법·허용 범위·예상 결과물을 사용자에게 확인받는다.
그 범위 안에서 총괄과 호스트 작업자(worker)는 등록 리소스·도구·분석 방법·순서·후속 조회·재시도를 자율적으로 판단한다.
승인한 단계의 의존 관계·허용 분기·예산을 지키며 범위 변경이 필요하면 차이를 담은 수정 계획을 승인받는다.
공개 필드는 [계획 MCP](../mcp/plans.md), 대화에서 응답을 받고 계획과 연결하는 기준은 [호스트 승인](../hosts/approval.md)을 따른다.

## 계획 전 탐색의 경계

현재 권한과 정책이 허용한 로컬 등록 설명·기능 계약·구조 메타데이터와 사전에 제공을 허용한 기억을 먼저 확인한다.
기억은 선택한 profile·실제 리소스 대상에 한정하며 [기억 계약](memory.md)에 따라 현재 모델 제공 권한·검증 상태·유효기간을 검사한다.
계획 제출마다 실행기가 발급한 `memory_search_refs`를 연결하고 조회 결과·제한·적용 여부를 설명한다.

목록 조회는 현재 저장한 등록부·스키마를 반환한다.
원격 진단은 관리 경로, 원격 탐색은 승인받은 업무 단계에서 수행한다.
실제 데이터·로그·코드·메일·티켓 원문의 신규 조회와 외부 변경은 계획 승인 후에 실행한다.
보존 원문은 해당 업무의 결과 조회 계약으로 확인한다.

원문이나 원격 구조가 있어야 본 계획을 만들 수 있으면 제한된 탐색 계획부터 승인받는다.
샘플 문서로 DB 스키마를 추론하는 것도 실제 데이터 읽기다.
메타데이터와 원격 탐색의 공개 접점은 [리소스 MCP](../mcp/resources.md)가 정의한다.

## 계획에 담을 설명과 실행 조건

계획은 사람이 읽는 설명과 실행기가 검사할 구조화된 조건을 함께 갖는다.
두 내용은 같은 불변 저장본을 가리키며 사용자는 전체 실행 조건을 확인할 수 있어야 한다.

| 항목 | 표시하고 검사할 내용 |
|---|---|
| 목적·완료 조건 | 해결할 문제, 기대 결과, 조건별 검증 방법·근거 |
| 기억 조회 | 검색 참조·사용한 지식, 적용 조건·오래된 근거·충돌·검색 제한과 추가 확인 방법 |
| 대상·기능 | profile·구성 개정, 실제 리소스와 접근 경계, 인스턴스·기능·계약 참조 |
| 방법·단계 | 수행 순서·의존 관계·허용 분기, 읽기·쓰기·부수 효과 |
| 범위 | 기간·필터·필드·대상 식별자·경로·변경값 |
| 후속 결과 | 허용 출처·필드·대상 입력·값의 형식·개수·범위 |
| 예산 | 업무 누적 호출·시간·지원되는 자료·변경량 한도 |
| 결과 제공·보관 | 보고·파일 형식, 리소스별 모델 제공·내보내기·보관 필드, 공통 보존기간·마스킹·전달 대상 |
| 기억 갱신 | 리소스별 허용 지식 범주·출처 필드·향후 모델 제공·장기 보존 범위와 기한 |
| 실패 처리 | 중단·부분 결과·원격 완료 확인·변경 후 검증 |

대상은 등록된 인스턴스와 실제 대상 식별자로 대조한다.
계획의 리소스는 고정 profile의 인증 참조와 연결하고 실행기가 로컬에서 해소한다.
수행 효과는 현재 계획의 목적·범위와 실제 리소스 권한을 모두 충족해야 한다.

환경 설정을 마친 사용자가 업무를 요청하면 호스트는 조회·분석·보고·필요한 파일·선별 기억을 한 업무 계획으로 구성한다.
자료·기억의 실제 범위는 이 계획의 사용자 승인으로 확정하고 profile의 [추가 제한](../configuration/profiles.md#자료-제공보관-정책)을 함께 적용한다.
업무 계획마다 리소스별 모델 제공·내보내기·종료 후 보관 필드와 마스킹을 승인받는다.
예를 들어 DB는 집계만, Source는 승인 경로의 코드 원문을 제공할 수 있다.
[출력 필드](../mcp/plans.md#예산보고완료-조건)로 표현하며 자료의 수명은 [보존 정책](workflow.md#이력과-완료-근거)을 따른다.

계획에는 해소한 기본 기억의 출처·향후 회상·보존과 사용자가 명시한 생략 조건도 표시한다.
업무 뒤의 후보 선별·저장은 [자동 기억 처리](memory.md#업무-후-갱신과-정정)를 따른다.

강제할 수 없는 조건은 보완을 요구하고 [예산 규격](../mcp/plans.md#예산보고완료-조건)이 허용한 상한 없음은 한계를 표시한다.
숫자 한도의 완화·해제는 수정 계획의 차이에 표시하고 재승인받는다.

### 후속 결과의 바인딩

이전 결과를 입력에 연결할 때 허용 출처·필드와 적용 범위를 계획에 남긴다.
값이 나중에 정해져도 리소스·연산의 경계는 승인 범위 안에 둔다.
실행기는 [바인딩 규격](../mcp/plans.md#결과-바인딩과-조건)에 따라 저장 원본·입력·대상을 대조한다.
원문은 값의 출처이며 실행 정책은 저장한 계획·현재 권한에서 해소한다.

## 불변 계획과 실제 사용자 승인

확인 전에 계획 원본과 표시본을 보존한다.
수정 시 새 `plan_id`와 증가한 `plan_version`을 발급하고 이전 원본을 유지한다.
승인 응답은 현재 대기 요청과 정확히 연결되는 계획에 적용한다.

[호스트 대화](../hosts/approval.md)에 현재 계획을 제시하고 호스트가 실제 사용자 답변·대화 맥락에서 해석한 결정을 함께 전달한다.
실행기는 업무·계획·대기 요청의 연결과 현재 상태·권한을 검사해 승인 여부를 보존한다.
불명확한 응답은 대기를 유지하고 “좋아, 다만 기간은 줄여 줘” 같은 조건 변경은 수정 계획으로 연결한다.
자연어 해석과 실행기 검사의 책임·한계는 [응답 검증](../hosts/approval.md#승인-응답-검증)을 따른다.

승인 기록은 업무·계획·요청·주체·결정·시각·유효 조건을 연결한다.
거절·수정·확인 취소, 기한·중복·응답 검증은 [호스트 승인 계약](../hosts/approval.md#결정별-처리)을 따른다.
이 결정들의 공개 상태·전이는 [승인 MCP](../mcp/plans.md#approvaloutcome과-실제-응답)에 둔다.

## 자율 실행과 재계획의 경계

매 호출은 현재 계획의 승인과 실제 리소스 권한의 교집합을 충족해야 한다.
과거 기억·선호는 방법을 판단할 참고 자료이며 실행에는 현재 업무의 승인·최신 상태 확인을 적용한다.

| 변화 | 처리 |
|---|---|
| 승인한 기간·필드 안의 필터 축소 | 범위·남은 예산 검사 후 자율 실행 |
| 허용 분기·검증된 후속 결과 사용 | 같은 승인 안에서 자율 실행 |
| 새로운 기능·대상·방법·제공 범위·예산 확대 | 호출 차단 후 수정 계획 승인 |
| 업무 스냅샷 밖의 profile·연결 필요 | 관리 설정 후 새 업무; [구성 변경 경계](../configuration/profiles.md) 적용 |
| 범위 포함 여부를 판단할 수 없음 | 호출 중단 후 조건 확인 |

단순 인수 오류는 기존 범위 안에서 정정할 수 있다.
설치·로그인·연결 등록은 관리 범위의 승인으로, 업무 조회·변경은 해당 계획의 승인으로 처리한다.

### worker 위임과 승인 범위

사용자는 하나의 root 업무 계획과 전체 수행 범위를 승인한다.
root는 승인한 단계의 의존 관계·허용 분기·예산 안에서 하위 목표·worker 수·배정·실행 순서를 자율적으로 정한다.
같은 범위의 작업 분해·병렬 수행·담당 교체는 기존 승인으로 수행한다.

위임은 현재 유효한 root 계획·승인·소유권과 단계의 부분집합에 연결한다.
worker에게 제공할 자료와 실행 인수에는 root 계획의 모델 제공·보관·출처·대상 정책을 적용한다.
실제 호출은 위임과 root 계획을 함께 검사하고 모든 worker의 소비·예약은 업무 전체 예산에 합산한다.
단계 밖의 기능·대상·자료 제공·예산이 필요하면 root가 차이를 포함한 수정 계획을 승인받는다.

총괄·작업자의 수행 책임과 위임 발급·접수·완료·철회·root 상태 변화의 효과는 [worker 실행 계약](workflow.md#worker-위임과-병렬-실행)을 따른다.
호스트의 worker 생성·도구 권한은 [호스트 연결](../hosts/plugins.md)에서 관리하고 DAERI 위임은 DAERI 도구의 허용 범위를 검사한다.

## 수정 계획에서 작업과 예산 승계

새 계획은 이전 계획·완료 호출·승계 근거·미확인 효과를 연결하고 차이를 보여 준다.
완료 호출은 검증된 근거로 승계하고 효과가 불명확한 호출은 미확인 상태와 확인 절차를 연결한다.
기존 위임의 새 호출 자격도 계획 교체와 함께 종료하고 새 계획·승인 아래 필요한 작업을 다시 배정한다.

이전 한도·소비·미정산 예약·새 총 한도·남은 예산을 함께 표시한다.
확대와 숫자 상한의 `null` 전환은 제한 완화로 명시해 재승인받는다.
누적량·예약의 승계와 정산은 [예산·재시도 원칙](workflow.md#예산과-재시도)을 따른다.

## 취소·철회·만료와 HITL 완화

확인 요청 취소는 승인 전 대기 요청을 종료하고 업무는 현재 상태로 유지한다.
업무 취소·일시중지는 각각의 업무 제어 요청으로 처리한다.
철회·만료는 이미 받은 승인의 사용 중단이다.
새 호출은 현재 유효한 승인으로만 시작하며 취소·철회·만료 상태에는 승인 대기 또는 상태 확인을 반환한다.
업무 일시중지·취소·재개와 이미 요청한 작업의 처리는 [업무 흐름](workflow.md#중단재개와-외부-결과-확인)을 따른다.
현재 승인 무효화는 일시중지·업무 종료·계획 교체·요청 및 기억 전제 변경으로 처리한다.
개별 승인 철회와 승인 시간 제한의 API·자동 전이는 후속 확장 범위다.

향후 검증된 범위에 자동 허용 정책을 적용하거나 HITL을 완화할 수 있다.
현재는 실제 사용자 응답으로 승인 결정을 기록한다.
자동 허용을 확장할 때에도 계획·정책 결정·권한·범위 검사·이력을 유지한다.
호스트 자체의 도구 권한 확인도 별도로 적용된다.

## 구현과 검증 경계

대화 응답과 계획의 연결은 [호스트 검증 범위](../hosts/approval.md#구현-시-검증), 실행·복구는 [최초 구현 계획](../../plans/initial-implementation.md)을 따른다.
로컬 MCP의 계획·응답 연결·승인 범위·재승인과 실제 시험 프로세스 호출을 검증했다.
Codex·Claude Code 설치 후의 사용자 대화와 실제 회사 리소스는 별도로 검증해야 한다.
