# 계획과 승인 명세

상태: 계획 저장·대화 승인·범위 안의 자율 읽기 실행 구현

총괄 에이전트는 목표·방법·연결·완료 조건을 계획으로 제시하고 실제 사용자 응답으로 확인받는다.
총괄 에이전트와 하위 에이전트는 승인 범위 안에서 도구·질의·순서·후속 페이지·재시도를 선택한다.
공개 입력은 [계획 MCP](../mcp/plans.md), 응답 해석은 [호스트 승인](../hosts/approval.md)이 소유한다.

## 계획 전 탐색의 경계

등록한 연결·기능 설명과 선택한 profile의 관련 기억을 먼저 확인한다.
기억 검색의 0건·실패·생략은 계획의 맥락·제한으로 처리하며 계획 제출의 필수 조건은 실제 대상·단계·완료 기준이다.
사용할 기억은 실제 검색 결과의 참조로 선택하고 현재 대상·개정·제공 범위·기한을 검사한다.

원격 데이터·로그·코드·티켓·구조 조회는 승인한 단계에서 수행한다.
원격 관찰이 있어야 본 계획을 만들 수 있으면 필요한 범위의 탐색 계획을 먼저 제시한다.
등록 메타데이터와 원격 실행의 접점은 [리소스 MCP](../mcp/resources.md)를 따른다.

## 계획에 담을 설명과 실행 조건

계획은 사람이 이해할 설명과 runtime이 확인할 조건을 같은 저장본에 연결한다.
사용자에게는 업무 판단에 필요한 내용을 제시한다.

| 항목 | 내용 |
|---|---|
| 목적·완료 | 해결할 문제·기대 결과·검증 근거 |
| 대상·방법 | profile·사용할 연결·조회와 분석 순서 |
| 범위 | 실제 대상·필터·기간·경로 등 명시한 조건 |
| 결과·기억 | 보고·필요한 파일·재사용할 지식의 자동 기억 |
| 제한 | 검색·조회 누락과 사용자가 정한 호출·시간 한도 |

연결의 현재 자료 제공·보관·기억 설정은 runtime이 계획에 해소한다.
새 profile의 기본값으로 보고·파일·자동 기억을 사용할 수 있으며 관리자가 등록한 추가 제한도 함께 적용한다.
호스트는 매 업무의 세부 필드 권한을 입력하는 대신 실제 목표와 명시한 범위를 구성한다.
상세 기본값은 [계획 출력](../mcp/plans.md#예산보고완료-조건), 자료 수명은 [업무 보존](workflow.md#이력과-완료-근거)을 따른다.

### 후속 결과의 사용

후속 호출은 승인한 연결·범위 안에서 실제 선행 결과를 사용한다.
호스트는 제공된 결과를 읽고 후속 질의·페이지·입력값을 선택해 다음 호출의 인수로 전달한다.
runtime은 실제 인수·대상·승인 범위와 명시한 단계 의존 관계를 검사한다.
공개 입력은 [리소스 실행 규격](../mcp/resources.md#daeri_capability_execute)을 따른다.

## 불변 계획과 실제 사용자 승인

계획 제출은 원본을 저장하고 현재 승인 대기를 함께 만든다.
호스트가 저장본에 대응하는 설명을 제시한 뒤 실제 사용자 응답과 결정을 전달한다.
runtime은 응답의 업무·현재 계획·대기 상태를 확인해 승인과 실행 상태를 기록한다.

수정은 새 계획으로 보존하고 과거 호출의 계획·승인 연결을 유지한다.
계획 버전·대기 요청·승인 ID의 연결은 runtime이 관리하며 호스트는 확인받은 계획을 선택한다.
이전 계획에 대한 답변은 현재 수정 계획의 실행 승인으로 처리할 수 없으므로 현재 계획을 다시 확인한다.

명확한 승인은 실행으로, 수정·거절은 계획 단계로, 모호한 응답은 승인 대기로 이어진다.
응답별 의미와 호스트 신뢰 경계는 [대화 승인](../hosts/approval.md#결정별-처리)을 따른다.

## 자율 실행과 재계획의 경계

| 변화 | 처리 |
|---|---|
| 승인한 연결·범위 안의 읽기 도구·질의·필터·페이지 선택 | 자율 실행 |
| 같은 목표의 작업 분해·순서 조정·병렬 조사·읽기 재시도 | 기존 승인으로 수행 |
| 승인한 연결·대상·자료 범위 확대 또는 명시 한도 완화 | 차이를 담은 수정 계획 확인 |
| 연결·실제 대상 변경 | 설정·진단 후 새 업무로 접수 |
| 같은 연결의 스키마·읽기 의미 변경 | 진단·계획 갱신 |
| 선택 기억의 만료·정정·무효화 | 상태를 확인하고 같은 승인 범위에서 자율 재관찰 |
| 무관한 profile 설명·설정 또는 인증값 갱신 | 현재 업무 유지 |
| 범위 판단에 필요한 조건이 모호함 | 영향받는 호출 전 확인 |

리소스의 읽기 묶음은 해당 연결에서 진단한 읽기 도구를 함께 사용할 수 있는 범위다.
단계에 명시한 조건이 있으면 각 호출에 적용하고 빈 범위는 고정 연결의 실제 계정 읽기 권한과 관리자 제한을 따른다.
특정 기능을 선택한 단계는 그 기능의 범위로 수행한다.
호스트는 이 경계 안에서 적합한 도구와 인수를 선택한다.

### 하위 에이전트 위임과 승인 범위

사용자는 하나의 총괄 에이전트 계획을 승인하고 총괄 에이전트는 그 안에서 하위 목표·하위 에이전트 수·배정·순서를 정한다.
같은 단계의 독립 조사도 병렬 배정할 수 있다.
하위 에이전트의 실제 실행은 배정 범위와 총괄 에이전트 계획·승인·명시한 업무 한도를 함께 따른다.

위임의 생성·철회·완료·중단 처리는 [하위 에이전트 실행](workflow.md#하위-에이전트-위임과-병렬-실행)이 소유한다.
실제 하위 에이전트 생성·신원·도구 권한·토큰 전달은 [호스트 연결](../hosts/plugins.md)이 담당한다.

## 수정 계획에서 작업과 예산 승계

수정 계획은 바뀐 대상·방법·범위와 이미 확인한 결과·남은 작업을 보여 준다.
이전 결과를 사용할 때 실제 출처를 승계하고 완료 판단에 필요한 최신 관찰을 구분한다.
계획 교체는 기존 하위 에이전트의 새 실행 자격을 종료하고 현재 승인 뒤 필요한 작업을 다시 배정한다.

명시한 한도는 누적 소비·진행 중 예약을 함께 계산한다.
한도 확대·해제는 수정 계획의 변경 내용에 표시하고 확인받는다.
사용량·재시도는 [실행 흐름](workflow.md#예산과-재시도)을 따른다.

## 중단과 승인 수명

승인은 현재 업무·계획과 연결되며 일시중지·취소·계획 교체·목표 변경을 반영한다.
선택 기억의 만료·정정은 현재 근거의 상태로 안내하고 호스트가 승인 범위 안에서 다시 관찰해 보완한다.
일시중지 뒤에는 현재 계획과 조건을 다시 제시해 실제 새 승인을 받는다.
확인 요청의 취소는 승인 대기를 종료하고 업무 취소는 업무를 종료한다.
진행 중 결과와 재개는 [업무 복구](workflow.md#중단재개와-외부-결과-확인)를 따른다.
