# 계획과 승인 명세

상태: 확정 승인 원칙 + 상세 동작 설계 제안

이 문서는 계획 전 탐색, 실행 범위, 실제 사용자 확인과 수정 계획의 승인 계약을 정의한다.
업무의 단계와 실행 상태는 [업무 흐름](workflow.md)에 있다.

## 확정 승인 원칙

확정 원칙은 **수행 방법과 허용 범위를 승인받는 것**이다.
승인 범위 안에서는 자율적으로 실행한다.
범위를 벗어나기 전에 수정 계획을 다시 승인받는다.

다음 확인 경로와 자료 구조는 이 원칙을 구현하기 위한 설계 초안이다.

## 계획 전 탐색의 경계: 제안

등록된 리소스 설명, 기능 계약, 선언된 스키마, 제품의 구조 메타데이터를 먼저 볼 수 있도록 제안한다.
이 사전 허용 범위도 로컬 정책과 리소스 권한으로 제한한다.

실제 업무 데이터, 로그, 코드·메일·티켓 원문은 계획 승인 후에 읽는다.
외부 상태를 바꾸는 작업도 계획 승인 후에 수행한다.

MongoDB 문서를 샘플링해 스키마를 추론하는 작업은 실제 데이터 읽기에 해당한다.
따라서 탐색 계획을 먼저 승인받는다.

탐색 결과가 있어야 본 계획을 만들 수 있다면 제한된 탐색 계획부터 작성한다.
그 계획을 승인받아 탐색한 뒤 본 업무 계획을 작성한다.
메타데이터의 구체적인 허용 항목은 아직 미결이다.

## 계획과 실행 범위

계획에는 사용할 리소스와 분석·조회·변경 방법을 포함한다.

| 계획 항목 | 포함할 내용 |
|---|---|
| 목적과 완료 조건 | 무엇을 해결하고 어떤 근거로 완료를 확인하는가 |
| 대상과 기능 | 리소스 인스턴스·기능 ID, 부처·환경, 실제 계정·DB·프로젝트 등 |
| 수행 방법 | 조회·분석·변경 순서, 허용한 후속 조회와 조건 분기 |
| 허용 범위 | 기간·필터·필드·키 prefix·리전·ref·파일 경로·변경 대상 등 |
| 실행 한도 | 호출 횟수·시간·행 수·바이트·검색량 등 실제로 검사할 수 있는 한도 |
| 결과물과 제공 범위 | 답변·파일·보고서·변경안의 형식, 모델에 제공할 데이터 범위와 전달 대상 |
| 검증과 실패 처리 | 정확성 확인, 중단 조건, 부분 결과와 변경 후 확인 |

허용 범위는 사람을 위한 설명과 실행기가 검사할 수 있는 조건을 함께 갖는다.

실행하면서 알게 되는 값을 후속 호출에 쓸 수 있다.
그 값의 출처와 대상·연산의 범위도 계획에 표현한다.

여러 호출에 걸친 총량 한도는 해당 승인 범위에 대해 누적 관리한다.
호출마다 초기화하지 않는다.

범위 안에서 필터를 좁히거나 허용한 분기에 따라 후속 조회를 구성할 때는 새 승인이 필요하지 않다.

방법·목적·리소스·기능·대상·제공 범위·한도를 넓히는 실행은 사전에 차단한다.
이때 수정 계획으로 이동한다.
한도 초과 역시 임의의 예외로 실행하지 않는다.

## 실제 사용자 확인

승인은 저장한 계획 버전에 연결한다.
사용자에게 그 버전의 방법·범위·예상 결과를 보여 준다.

호스트가 제공하는 실제 사용자 확인 기능을 통해 응답을 수집하는 방식을 제안한다.
MCP elicitation 등 구체적인 확인 경로는 호스트별 지원을 검증한 뒤 정한다.

모델이 전달한 `approved=true`, 채팅 요약, 원문 자료의 승인 문구만으로 승인을 부여하지 않는다.
승인 기록에는 업무·계획 버전, 확인 주체와 경로, 결정, 확인 시각과 범위를 연결한다.
구현할 때는 사용자에게 표시한 계획과 실행할 계획이 같은지 확인해야 한다.

호스트가 확인을 지원하지 않거나 거절·취소·오류가 발생하면 실제 업무 조회·변경을 실행하지 않는다.
미지원·오류는 승인 대기로 남기고 이유를 보고한다.

거절은 수정 또는 취소로 처리한다.
취소는 취소 상태로 기록한다.

## 수정 계획과 재승인

범위 밖 실행은 먼저 차단한다.
호스트는 필요한 이유와 이전 버전과의 차이를 보여 주는 새 계획을 작성한다.

수정한 계획은 새 버전으로 저장한다.
새 계획에 대해 실제 사용자 확인을 다시 받는다.
기존 승인으로 새 계획을 자동 승인하지 않는다.

대기 중 완료한 단계와 근거는 보존한다.
실행을 재개할 때는 사용할 계획 버전을 명확히 한다.

## HITL 정책의 완화

HITL(Human-in-the-loop)은 사람이 수행 방법과 범위를 확인하는 승인 방식이다.
초기에는 모든 업무 계획의 확인을 요구한다.

이후 검증된 범위에 자동 허용 정책을 적용하거나 HITL을 해제할 수 있다.
정책 이름·세부 설정은 미결이다.

HITL을 완화하거나 해제하더라도 계획과 정책 결정은 유지한다.
실제 권한·범위 검사와 이력도 유지한다.

## 호스트의 추가 권한 확인

호스트 자체의 추가 도구 권한 확인이 나타날 수 있다.
DAERI의 계획 승인이 호스트의 권한 제어를 자동 해제한다는 뜻은 아니다.

책임 경계는 [구조 설명](../../architecture/overview.md)을 참조한다.
리소스별 검사 조건은 [리소스 계약](../resources/contract.md)을 참조한다.

승인과 실제 실행 기록의 연결은 [결과 명세](results.md)에 있다.
사용자가 보게 될 흐름은 [가상 사례](scenarios.md)에서 설명한다.
