# profile별 기억과 검색

상태: 선별 기억·선택형 임베딩·혼합 검색·보고 후 자동 저장·재시도 구현; 실제 회사 API는 별도 검증

완료 업무에서 확인한 지식을 보존하고 다음 유사 업무의 판단에 활용한다.
실행 이력은 [추적·복구](workflow.md#이력과-완료-근거)에, 이 문서의 기억은 재사용할 지식에 사용한다.
공개 입력은 [기억 MCP](../mcp/tasks.md#기억-mcp-도구), 저장 위치는 [로컬 저장 구조](../configuration/profiles.md#로컬-저장-구조)가 소유한다.

## 채택한 방식과 책임

호스트가 관련 지식을 검색하고 현재 요청에 적용할지 판단하는 Agentic RAG를 사용한다.
총괄 에이전트는 계획 전 관련 기억을 확인하고 하위 에이전트는 배정한 연결 범위에서 필요한 후속 검색을 판단한다.
기억은 profile별로 공유하며 실제 대상·현재 제공 조건·기한으로 구분한다.

호스트는 실제 관찰·하위 에이전트 결과·사용자 정정에서 지식을 선별하고 문장의 의미와 근거를 대조한다.
runtime은 출처 존재·대상·현재 제공·보관 조건을 검사해 저장·색인한다.
자유 문장과 근거의 의미 대응은 호스트가 판단한다.

| 자료 | 용도 |
|---|---|
| profile 기본 맥락 | 사용자가 설정한 용어·안정적인 업무 규칙 |
| 업무 이력·보존 자료 | 실제 상태·승인·호출·보고 복구 |
| 기억 정본 | 적용 조건·검증 근거를 가진 지식 |
| 키워드·벡터 색인 | 정본에서 다시 만들 수 있는 검색 자료 |

기억 정본·개정·출처·벡터는 로컬 SQLite에 보관한다.
FTS5는 키워드, sqlite-vec는 벡터 유사도 계산을 담당한다.
임베딩은 setup에서 로컬 모델·회사 API·키워드 전용 중 선택하며 같은 설정으로 저장과 검색을 수행한다.
기존 profile의 선택 해소와 준비는 [임베딩 설정](../configuration/profiles.md#임베딩-제공자-선택)을 따른다.

## 기억에 남길 내용

| 범주 | 내용 | 확인 근거 |
|---|---|---|
| 서비스 규칙 | 용어·집계 기준·예외 | 실제 사용자 요청·정정 |
| 리소스 구조 | 필드 의미·대응·구조 | 실제 대상·관찰 시점 |
| 검증된 절차 | 조건·수행 방법·검증 방법 | 실제 수행·결과 |
| 실패 예방 | 실패 조건·보완 방법·이유 | 실패·반증·보완 관찰 |

후보에는 지식 문장·적용 조건·대상 연결·검증 방법·실제 출처를 담는다.
일부 결과나 실패 업무에서도 확인한 지식을 선별할 수 있으며 조회 전체성·시점·불확실성은 적용 조건에 반영한다.
비밀·개인정보·개별 행값은 지식과 구별해 정제하고 알려진 비밀 패턴이 포함된 후보는 검증 오류로 처리한다.

출처는 현재 허용·실제 제공·보관·기억 사용이 가능한 필드의 교집합으로 확정한다.
같은 기록의 다른 필드가 제한돼 있어도 사용할 수 있는 근거가 있으면 선별 지식을 저장한다.
교집합이 비거나 실제 대상·기억 범주·보존 조건을 충족하지 못하면 후보의 원인을 반환한다.
상세 해소는 [기억 출처 규격](../mcp/tasks.md#기억의-출처-필드-확정)을 따른다.

## 계획 전 조회와 활용

1. 선택한 profile의 기본 맥락과 요청에 관련된 기억을 검색한다.
2. 호스트가 적용 조건·출처·확인 시점·제한을 읽고 필요하면 추가 검색한다.
3. 사용할 기억의 실제 참조와 현재 상태를 확인할 방법을 계획에 연결한다.
4. 사용자 승인 뒤 필요한 최신 원격 관찰과 함께 수행한다.

검색 0건은 정상이며 검색 실패·색인 미준비·검색 생략은 부족한 맥락으로 표시한다.
기억 검색의 수행 여부·제한은 계획·승인의 실행 조건과 구분한다.
실제로 선택한 기억은 현재 profile·대상·개정·제공 범위·기한을 검사한다.
총괄 에이전트·하위 에이전트는 수행 중 새로 회상한 기억도 근거에 연결하며 현재 외부 상태의 완료는 실제 조회로 확인한다.

선택한 기억의 정정·무효화·만료는 현재 본문 제공에 반영하고 계획의 참고 근거 상태로 안내한다.
호스트는 같은 승인 범위의 새 관찰로 전제를 보완하고 실제 대상·범위가 바뀔 때 수정 계획을 제시한다.
사용한 근거와 이미 수행한 결과는 원 기록에 유지한다.
현재 외부 상태·완료 여부는 최신 관찰로 확인하고 과거 기억은 적용 조건을 가진 참고 근거로 사용한다.

## 혼합 검색과 색인

현재 profile의 활성·미만료 개정에서 대상·기억 범주·연결 선택·현재 제공 조건을 통과한 자료를 검색한다.
키워드는 식별자·오류 코드·용어를, 벡터는 표현이 다른 유사 요청을 찾는다.
정본의 현재 상태는 검색 후보와 최종 반환 때 다시 확인한다.

FTS5 관련도와 벡터 코사인 거리 순위를 RRF로 합친다.
각 순위의 점수는 `1 / (60 + 순위)`이며 점수가 같으면 기억 참조 순으로 정렬한다.
후보 참조를 64개씩 읽고 허용 후보를 채울 때까지 다음 순위를 확인한다.
각 검색 방식은 요청 건수의 최대 4배를 모으며 최종 결과는 기본 10건·최대 50건·본문 합계 64KiB다.

검색어는 UTF-8 4KiB까지 받고 비밀 제거 뒤 최대 64개 단어를 OR 키워드로 구성한다.
FTS5는 `unicode61` 토큰화를 사용하고 한국어 의역·표기 차이는 벡터와 함께 평가한다.
벡터는 조건과 모델이 일치하는 자료의 거리를 계산하는 정확 검색이며 실제 규모별 지연·처리량은 별도 측정 대상이다.

검색 질의의 벡터 계산은 쓰기 잠금 밖에서 처리하고 발행 전 현재 업무·profile·자료 상태를 다시 검사한다.
벡터·키워드 중 한 방식이 실패하면 가능한 결과와 제한을 반환한다.
색인 장애 중에도 기억 정본은 유지하고 검색 점수와 사실 확인 상태는 각각 관련도·출처 기록으로 표현한다.

색인은 제공자·연결 규격·endpoint·모델·차원을 식별한다.
설정이 바뀌면 호환되는 벡터를 사용하고 기존 정본은 관리 재색인으로 갱신한다.
로컬 모델 식별은 실제 모델·토크나이저 파일의 지문을 포함한다.
파일 지문은 벡터 호환성 비교에 사용하며 모델의 배포 진위 보장은 공급 경로의 책임이다.

### 임베딩 API 계약

회사 API는 [임베딩 설정](../configuration/profiles.md#임베딩-제공자-선택)의 `provider: api`, `adapter: openai_compatible`로 사용한다.
호환 여부는 모델 종류보다 인증·요청·응답 형식으로 판단하며 회사 자체 모델도 같은 규격이면 연결할 수 있다.
인증값은 [setup YAML](../configuration/profiles.md#접속-정보와-인증값)의 등록 절차로 참조화한다.

| 경계 | 처리 |
|---|---|
| 인증 | 로컬 인증 참조를 해소한 Bearer 인증 |
| 요청 | `model`·`input`·`encoding_format: float`; 설정한 경우 `dimensions` 포함 |
| 입력 | 질의 또는 기억 색인 텍스트 하나, UTF-8 최대 64KiB |
| 응답 | 최대 1MiB, `data` 한 항목·`index: 0`, 1~8192차원의 유한 숫자 벡터, 영벡터 검사 |
| 전송 | 지정 HTTPS 주소·인증서 검사·단계별 시간 제한, 한 번의 요청 |
| 저장 | 기억 정본·벡터·키워드 색인은 사용자 로컬 SQLite |

요청·응답 기준은 [공식 embeddings API](https://developers.openai.com/api/reference/resources/embeddings/methods/create)다.
회사의 endpoint·모델 또는 배포 이름·인증·차원은 해당 환경에서 진단한다.
API 서버의 자체 보관·감사·과금과 같은 식별자를 유지한 모델 교체는 회사가 관리하고 변경 시 재진단·재색인한다.

setup에서 회사 API의 연결·모델·전송 범위를 확인해 적용하면 해당 API로 기억과 검색 질의를 임베딩한다.
색인에는 현재 제공·보관 가능한 지식 문장·범주·적용 조건을 사용한다.
질의 전송은 현재 접근 가능한 기억이 하나 이상일 때 수행하며 키워드 일치 여부와 별개다.
제공 가능한 기억이 0건이면 API 전송을 생략하고 정상 빈 검색을 반환한다.
이는 제공자 연결 진단과 구분한다.

전송 직전과 결과 발행 전 현재 API 선택·설정·자료 조건을 검사한다.
설정·접근 철회는 이후 새 전송·결과 제공에 반영하고 이미 보낸 텍스트의 처리는 회사 API 정책을 따른다.
재색인은 허용 기억마다 벡터를 생성하며 임베딩 호출은 운영 리소스의 호출 한도와 구분한다.

키워드 전용은 FTS5 색인 완료 시 `index_state=ready`로 기록한다.
선택한 방식의 검색이 정상 완료되면 0건을 포함해 `status=ok`다.
벡터 장애로 키워드만 사용하거나 색인 누락이 있으면 가능한 결과와 `status=partial`·제한을 반환한다.
제공자 준비·실제 API 연결 상태는 관리 진단으로 확인한다.

## 업무 후 갱신과 정정

총괄 에이전트는 직접 수행·하위 에이전트 근거·사용자 피드백에서 재사용 지식을 선별해 [결과 제출](../mcp/tasks.md#daeri_result_submit)에 포함한다.
사용자는 업무 계획의 확인 뒤 별도 기억 명령 없이 같은 흐름으로 결과와 기억을 받는다.
실제로 재사용할 지식이 없으면 후보를 비워 기억 갱신을 생략한다.

runtime은 승인·실제 출처·대상·허용 필드·기한·비밀 패턴을 검증한다.
보고를 보존하면서 검증한 후보의 처리 대기를 함께 저장하고 기억 정본·출처·개정·색인 대기를 만든다.
그 뒤 선택한 제공자로 키워드·벡터 색인을 갱신하고 현재 유효한 정본에 발행한다.

문법·출처 검증에 실패한 후보는 본문 대신 skipped 상태·원인 코드를 남기고 보고·업무 종료는 보존한다.
후보 대기 저장 실패·사전 검증의 일시 장애나 과거의 본문 없는 대기는 재제출 필요 상태를 반환한다.
호스트가 후보를 포함해 새 제출하면 현재 입력을 다시 검증하고 기존에 완료한 기억은 유지한다.
대기 저장에 실패한 제출은 같은 요청 키로 재전송해도 최초 실패 상태를 반환한다.
검증을 마친 후보만 대기에 보존하며 반복 전달은 기존 보고·기억에 연결한다.
검증한 후보의 저장·색인 장애는 대기 상태로 보존한다.

같은 보고의 재전달과 다음 동일 profile 검색에서 대기를 자동 재시도한다.
검색당 최대 다섯 보고를 처리하고 첫 일시 실패에는 남은 대기를 유지한 채 가능한 검색을 진행한다.
만료한 대기는 정리하고 동일 후보·출처의 반복 제출은 기존 기억에 연결한다.
기억의 실제 처리 결과는 결과 제출 응답으로 제공하고 사용자 조치가 필요한 문제를 안내한다.

보고·파일을 출처로 선택하면 등록된 실제 관찰·사용자 확인까지 따라간다.
파일에는 호스트가 선언한 기여 출처를 사용하며 후보의 내용·출처 선택은 호스트가 검증한다.
현재 사용할 수 있는 최소 원출처가 정리됐으면 후보를 생략하거나 승인한 새 관찰로 보완한다.

정정은 같은 기억의 새 개정으로 저장하고 이전 개정을 검색 대상에서 제외한다.
반증·사용자 정정에 따른 무효화는 같은 실제 대상의 근거로 처리하며 새 지식 저장 허용과 구분한다.
명시적 정정·무효화 입력과 응답은 [기억 갱신 MCP](../mcp/tasks.md)를 따른다.

## 보존과 장기 운영지식

업무 본문·조회·보고·파일은 [업무 보존](workflow.md#이력과-완료-근거)을 따른다.
선별 기억은 연결과 profile의 해소한 보존 조건을 사용하며 기본은 재사용할 장기 운영지식이다.

| 대상 | 기한 |
|---|---|
| profile 기본 맥락 | 설정 변경·삭제까지 |
| 출처 연동 기억 (`source_bound`) | 업무·기여 출처의 가장 이른 유한 기한 |
| 장기 운영지식 (`long_term`) | 새 profile 기본 무기한; 설정한 경우 최초 저장부터 유한 기간 |
| 색인·벡터·반환 사본 | 원기억의 상태·기한·제공 조건 |
| 최소 추적 정보 | 출처·검증·개정·상태·기한 유지 |

장기 운영지식은 실제 근거와 검증 방법을 갖춘 파생 지식이며 현재 연결·profile이 해당 범주·재회상·보존을 허용해야 한다.
여러 리소스의 지식은 모든 실제 기여 출처의 조건을 적용한다.
하나라도 출처 연동 보존이면 관련 유한 기한 중 가장 이른 값을 사용하고 모두 무기한이면 null이다.

유한 기간은 UTC 기준 하루를 24시간으로 계산한다.
기존 명시적 기간·확정 기한은 설정 기본값 변경·조회·복사·문장 정정·재색인에도 유지한다.
새 기간은 기존 만료·차단의 기준 시점 이후 독립적으로 확인한 새 근거로 해소한다.
정기적인 원자료 만료와 명시 삭제·무효화는 구분한다.

장기 지식은 원자료의 정기 만료 뒤에도 자체 조건으로 사용할 수 있다.
현재 profile·연결·실제 대상·활성 개정·제공 조건을 검사하고 과거 근거만으로 현재 상태를 설명할 때는 확인 시점을 표시한다.
원자료의 현재 열람과 보고 재생성은 해당 자료의 조건으로 확인한다.

만료·삭제·무효화·제공 허용 철회는 기억과 관련 사본의 조회·근거 선택에 즉시 반영한다.
명시적 무효화는 본문·색인을 정리하고 runtime 시작 때도 만료·철회 자료를 정리한다.
관리 파일·검색 기록·계획 사본·파일에 복제한 기억은 원지식과 다른 기여 출처의 기한·상태를 승계한다.

## 구현 선택과 확인 범위

### 첫 버전의 실제 처리

기억은 현재 허용·제공·보관·기억 출처 필드의 교집합에 연결한다.
호스트는 그 근거로 후보를 선별하고 runtime은 실제 출처·대상·조건을 확인한다.
내보내기는 저장한 허용 증명과 현재 연결·계획의 제공 조건을 함께 검사한다.
원자료가 정기 만료됐으면 보존한 필드·대상·허용 증명으로 현재 조건을 판단한다.

로컬 모델은 준비된 파일을 사용하고 회사 API는 위 전송 규격을 적용한다.
모델 입력 한도를 넘는 기억은 정본을 유지하고 색인 제한 상태를 반환한다.
키워드·벡터의 검색 규모와 의미 품질은 다음 평가로 구분한다.

### 반복 가능한 회상 평가

[고정 합성 자료](../../../evaluations/memory_recall.json)는 기억 11개·질의 14개로 오류 코드·한국어 의역·복수 근거·정정·무관 질의·다른 profile·철회·구개정을 평가한다.
[평가 도구](../../../evaluations/memory_recall.py)는 임시 저장소에서 실제 제품 저장·검색 함수를 호출하고 기대 참조와 결과를 비교한다.
기본 상한은 5건이며 실행 입력은 [평가 안내](../../development/dependencies.md#기억-회상-평가)가 소유한다.

| 결과 | 계산·의미 |
|---|---|
| Recall@k | 기대 근거가 있는 질의의 상위 k개 회수 비율 평균 |
| MRR@k | 첫 기대 근거 순위 역수의 평균; 누락은 0 |
| 기대 근거 없는 질의 | 실제 반환 건수 관찰; Recall·MRR은 null |
| 접근 불가 결과 | 다른 profile·철회·구개정·미등록 참조 반환; 통과 기준 0 |
| 지연 | 질의별·유형별 평균·95백분위; 질의 임베딩 포함 |

JSON 보고서는 자료 버전·지문·제공자·모델·Python·SQLite·기대/실제 참조·순위·제한을 담는다.
키워드는 `keyword_baseline`, 실제 임베딩은 `semantic_recall`로 구분한다.
완료는 `complete`, 검색 제한·대체는 `incomplete`와 점수 null, 시작 실패는 `unavailable`과 점수 생략으로 반환한다.
종료 코드 0은 평가 완료와 접근 불가 결과 0건, 1은 불완전·접근 불가·저장 실패, 2는 인수 오류다.
운영 회수율·지연의 합격 기준은 실제 제공자의 측정 결과로 판단한다.

### 실제 확인과 남은 경계

담당 구현은 [기억·검색·색인](../../../src/daeri/infrastructure/memory.py), [임베딩](../../../src/daeri/infrastructure/embedding.py), [출처](../../../src/daeri/application/knowledge.py), [자동 처리](../../../src/daeri/application/automatic_memory.py)다.
[자동 기억](../../../tests/test_automatic_memory.py)·[출처와 정정](../../../tests/test_knowledge.py)·[업무 통합](../../../tests/test_memory_flow.py)·[10,000건 이후 검색 회귀](../../../tests/test_memory_search_scale.py)·[회상 평가](../../../tests/test_memory_recall_evaluation.py)가 로컬 동작을 검증한다.
모의 HTTP·벡터 검증과 실제 제공자의 의미 품질·회사 네트워크·인증·Windows 검증은 구분한다.
확보한 결과와 추가 확인은 [구현 계획](../../plans/initial-implementation.md#확보한-검증-근거)을 따른다.

설계는 [Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)의 맥락·혼합 검색과 [Hindsight](https://hindsight.vectorize.io/)의 기억 저장·회수 흐름을 참고했다.
로컬 구현은 [FastEmbed](https://github.com/qdrant/fastembed)·[sqlite-vec](https://alexgarcia.xyz/sqlite-vec/python.html), 모델 배경은 [다국어 E5 보고서](https://arxiv.org/abs/2402.05672)를 참고하며 실제 운영 품질은 별도 측정한다.
