## 목적과 제공 범위

DAERI는 여러 직군의 구성원이 자연어로 업무를 맡기고 프로젝트의 경험을 함께 축적하는 멀티 오케스트레이션 에이전트다.
신규 구성원도 기존 지식·성공 절차·실패 경험·피드백을 첫 업무부터 활용한다.
숙련도 향상은 누적 경험을 검색·적용·검증하는 능력으로 평가한다.

사용자는 Claude Code·Codex 플러그인에서 회사 로그인 뒤 허용된 프로젝트를 선택한다.
운영자가 모델·커넥터·권한을 준비하고 프로젝트 관리자가 연결 정보를 등록하면 구성원은 요청·승인·피드백으로 업무를 진행한다.
생성 모델은 사내·호환 API 또는 Bedrock을 선택하고 경험 추출·검색은 AgentCore Memory를 사용한다.

원격 도구 연결 규격(MCP)의 서비스와 호스트별 플러그인을 제공한다.
AWS·회사 로그인·호스트의 실제 연동 경계는 [구현과 검증](../development/guide.md#구현과-검증)에서 확인한다.

## 업무 흐름

| 순서 | 사용자와 서비스의 동작 |
|---|---|
| 1. 요청 | 선택한 프로젝트에서 목표·조건·원하는 결과 접수 |
| 2. 기억 검색 | Harness가 관련 프로젝트 경험을 검색해 문맥에 활용 |
| 3. 계획 | 총괄 에이전트가 대상·예상 효과·수행 범위·완료 조건 제시 |
| 4. 승인 | 호스트 확인창에서 현재 계획을 승인·수정·거절 |
| 5. 위임 | 총괄 에이전트가 필요한 하위 목표·역할·수·순서를 선택 |
| 6. 수행 | 승인 범위에서 도구·분석·페이지 조회·재시도를 자율 선택 |
| 7. 보고 | 실제 결과·근거·파일·미충족 조건 전달과 S3 원본 보존 |
| 8. 기억 저장 | Memory가 경험을 비동기로 추출·통합해 다음 업무에 제공 |

보고 형식은 목표와 실제 근거에 맞춰 선택하고 한 응답의 종료와 업무 전체의 목표 달성을 구별한다.
결과 이후 피드백은 같은 업무에서 후속 요청으로 이어간다.

사용자 안내는 한국어로 확인한 결과·필요한 선택·다음 조치를 전달한다.
로그인·편집·다운로드에는 필요한 위치를 제공하고 상세 진단 요청에는 확인한 원인·설정·조치의 영향을 설명한다.

| AgentCore Runtime | DAERI MCP 접속부·프로젝트 MCP 서버·에이전트 실행의 격리·확장·세션 라우팅 |

DAERI 자체의 업무·기억 보관은 Memory·S3로 구성하며 업무 대상 DB·API는 프로젝트 리소스로 연결한다.

### 멀티 에이전트와 도구

총괄 에이전트(orchestrator)는 업무를 분해하고 별도 하위 에이전트(subagent)를 Gateway의 MCP 도구로 호출한다.
등록된 Lambda 대상이 프로젝트·도구·하위 릴리스를 검사해 새 하위 세션을 실행하면 총괄 에이전트가 응답·완료 여부·오류와 근거를 대조·통합한다.

부모의 승인 검사는 위임 도구 호출에 적용한다.
하위 에이전트는 같은 프로젝트 Memory·서비스 자격과 서버 실행 도구를 사용하며 실제 사용자의 개인 OAuth 위임과 구분한다.
추가 입력 대기·불완전 응답·실패에는 미완료 상태와 확보한 근거로 실제 효과를 확인해 후속 동작을 판단한다.

실행 도구·네트워크·자격의 연결 조건은 [프로젝트와 Runtime](../development/guide.md#프로젝트와-runtime), 하위 등록·실행 제한은 [하위 에이전트와 개인 위임](../development/guide.md#하위-에이전트와-개인-위임)에 둔다.

## 프로젝트와 접근

프로젝트는 리소스 연결·자료·대화·도구 결과·과거 기억을 모든 구성원에게 공유할 수 있는 범위다.
일부 자료만 공유 가능한 구성원은 공유 범위별 프로젝트·Memory로 나눈다.
목표·계획·실제 승인·실행 세션·소스 사본은 개별 업무에 연결한다.

서버는 로그인 토큰의 신원·권한을 검증하고 매 요청·확인 응답에서 유효 기간과 선택 프로젝트를 다시 검사한다.
같은 권한의 토큰 갱신은 연결을 유지하고 권한 변경은 새 MCP 연결에 반영한다.
실제 대상 권한은 Gateway·Identity·리소스가 집행하며 개인 자격으로 얻은 자료의 프로젝트 공유 범위도 인증·운영 정책에 맞춰 구성한다.

| 자격 경로 | 동작 |
|---|---|
| 프로젝트 서비스 자격 | 운영자가 중앙 등록한 IAM·공유 자격으로 접근 |
| 개인 OAuth | 현재 인증한 사용자가 동의한 개인 자격으로 접근 |
| 별도 비밀 | Secrets Manager 등 인증 저장소의 참조로 연결 |

개인 위임 JWT는 요청 문맥에서 사용하고 모델 입력·S3에는 검증한 사용자 문맥을 연결한다.
회사 SSO·Cognito·IAM·Identity의 실제 연결은 [인증 설정](../development/guide.md#서버-설정)을 따른다.

Claude Code와 Codex는 같은 중앙 서비스에 연결하고 같은 프로젝트에서 자신의 업무를 선택해 이어간다.
새 업무는 현재 검증한 harness 릴리스에 고정하고 기존 업무는 저장한 릴리스·세션을 유지한다.
저장한 릴리스의 실제 버전이 바뀌면 실행 전 확인 오류로 중단한다.
버전 정보가 없는 기존 업무는 보관 기록을 확인한 뒤 새 업무로 시작한다.

### 프로젝트 연결

운영자는 재사용할 MCP 패키지·기존 원격 MCP endpoint·OpenAPI 템플릿을 검증해 중앙 카탈로그에 등록한다.
프로젝트 관리자는 허용된 커넥터를 선택하고 호스트가 표시한 실제 확인창에 연결 정보를 입력한다.
로그인 토큰의 프로젝트 구성원 권한은 연결 조회를, 별도 관리 권한은 등록·갱신을 허용한다.

DAERI 연결 관리자는 운영자가 고정한 이미지·역할·네트워크·인증 설정에 입력을 적용한다.
MCP 패키지는 같은 이미지를 재사용하되 프로젝트·연결별 설정으로 별도 AgentCore Runtime에 배포하고 endpoint와 인증을 프로젝트 Gateway에 등록한다.
기존 원격 MCP는 endpoint를 재사용하고 REST API는 OpenAPI 대상으로 직접 연결한다.
MCP의 실행 단위는 프로젝트·연결이며 개별 DB·Redis 패키지의 제공 여부는 운영자가 등록한 카탈로그에서 확인한다.

Gateway는 현재 프로젝트의 고정된 harness 릴리스에 이미 연결되어 있어야 한다.
등록된 연결과 Memory는 프로젝트 구성원이 함께 사용하고 목표·계획·승인은 각자의 업무에 연결한다.
여러 리소스는 서로 다른 연결 ID로 등록하며 같은 ID의 같은 커넥터는 갱신·재시도한다.

확인창에는 비밀이 아닌 접속 필드·기존 Secrets Manager 참조·운영자가 허용한 원격 인증 별칭을 입력한다.
서버가 제공한 확인창의 실제 응답 뒤에 현재 신원·관리 권한·설정을 다시 검사하며 취소·미지원·시간 초과에는 기존 연결을 유지한다.
MCP에서 DB로 접근할 비밀은 실제 MCP 프로그램 시작 때 해소하고, Gateway에서 원격 MCP·API로 접근할 인증은 Identity 제공자에 연결한 별칭으로 선택한다.
일반 구성원에게는 연결 이름·식별자·상태 요약을 제공한다.

연결 목록은 저장한 등록 상태를 보여 주며 `READY`는 마지막 등록 때 Gateway에서 도구를 발견한 상태다.
현재 리소스 상태와 대상 DB·API의 실제 접근 성공은 승인된 업무의 도구 호출 결과로 확인한다.
등록 중 일부 AWS 변경이 성공한 뒤 실패하면 연결 ID와 현재 원격 상태를 대조해 같은 등록을 재시도한다.
프로세스 중단으로 등록 잠금이 남으면 운영자가 원격 상태와 실행 종료를 확인한 뒤 해당 잠금을 해제한다.
설정·권한·상태와 실제 배포 검증 범위는 [프로젝트 연결 운영](../development/guide.md#프로젝트-연결-운영)을 따른다.

## 계획과 승인

총괄 에이전트는 목표·대상·예상 효과·완료 조건을 자유로운 계획 본문으로 제시한다.
서버가 계획 확인 도구의 실제 대기를 보관한 뒤 호스트 확인창에 현재 계획을 표시한다.

| 사용자 응답·상태 | 처리 |
|---|---|
| 승인·추가 조건 없음 | 현재 업무·계획·대기에 결정을 보존하고 같은 세션 재개 |
| 수정 요청·추가 조건 입력 | 수정 내용을 반영한 새 계획 확인; 승인 선택에 조건을 입력한 경우도 동일 |
| 거절 | 거절을 전달하고 계획 조정 |
| 확인창 닫기·미지원·300초 초과·연결 종료 | 현재 계획의 확인 대기 유지 |
| 확인 중 계획 변경·중복 응답·로그인 만료·권한 변경 | 현재 조건 재확인 후 유효한 계획에서 진행 |
| 결정 보존 뒤 실행 요청이 명확히 거부됨 | 같은 계획의 보관된 실제 응답으로 명시 재개 |

일반 업무 입력의 승인 문구는 후속 요청으로 해석하며 대기 중 요청 변경은 수정 계획으로 연결한다.
새 요청·새 계획에는 이전 실행 허가를 해제하고, 이미 보존한 결정도 실행 전에는 수정 요청으로 철회할 수 있다.
확인창 뒤에는 로그인·대기와 실행 점유 시점의 상태를 다시 대조한다.

호스트는 실제 확인 응답을 전달하는 신뢰 주체이며 호스트의 응답 자동화·수정 기능도 같은 경계에 속한다.
서버의 승인 근거는 현재 확인창 응답이며 기억·문서·도구 결과는 판단 자료로 사용한다.

실행 전 승인 hook은 보호된 업무·세션 연결과 보관된 현재 승인을 검사한다.
계획 확인 도구를 허용하고 나머지 도구는 승인 뒤에 허용하며 조회 실패·연결 불일치·잘린 입력에는 실행을 중단한다.
계획의 의미적 범위는 에이전트가 판단하고 실제 대상 권한은 리소스 경계에서 집행한다.
도구·hook의 등록과 입력 규격은 [서버와 플러그인](../development/guide.md#서버와-플러그인)에 둔다.

## 공유 기억

프로젝트마다 독립 Memory를 두고 실제 사용자 식별자를 유지한다.
구성원은 가입 시점·호스트와 관계없이 같은 프로젝트의 공유 경험을 활용한다.

| 기억 | 저장·활용 범위 |
|---|---|
| 프로젝트 사실 | 구성원이 공유하는 사실·용어·구조 |
| 업무 경험 | 구성원이 공유하는 성공·실패 절차와 교훈 |
| 대화 요약 | 사용자·업무 세션의 문맥 |

추출·통합은 비동기이며 검색 가능 시점은 실제 처리 결과로 확인한다.
확정된 업무 절차는 Git/S3의 Harness Skills, 누적 경험은 Memory로 관리한다.
전략·저장 경로·복원 설정은 [Memory 수집과 복원](../development/guide.md#memory-수집과-복원)에 둔다.

### 보존과 재구성

단기 이벤트는 [365일](https://docs.aws.amazon.com/bedrock-agentcore-control/latest/APIReference/API_Memory.html) 보존하고 장기 기억은 [TTL을 생략](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/long-term-record-ttl.html)하며 S3 원본도 자동 만료를 생략한다.
장기 기억은 [통합 중 교체·삭제될 수 있어](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory-record-streaming.html) S3 원본을 독립 보존하고 버전 관리·삭제 권한·배포 제거 정책으로 수명을 유지한다.

S3 보관 범위는 접수한 요청·승인·피드백과 수신한 응답·도구 관찰·파일·산출물이다.
예약 수집은 Memory 이벤트의 원래 사용자·세션·시각·분기·본문을 불변 원본으로 보존하고 같은 이벤트의 재수집은 원본과 대조한다.
수집 주기·실패 알림은 원본 이벤트의 보존 기간 안에 복구할 수 있게 운영한다.

재구성은 같은 프로젝트 소유의 비어 있는 독립 Memory에 보관 이벤트를 재생한다.
진행 기록으로 중단 지점에서 이어가며 네이티브 원본이 없으면 DAERI가 수신한 업무 기록과 그 보관 시각을 사용한다.
비동기 추출·검색 품질을 확인한 뒤 복원 대상을 새 릴리스로 공개하며 이전 장기 기억의 ID·통합 결과는 재구성 결과에 따라 달라진다.

기억의 적용 조건·불확실성·실패는 현재 자료와 대조하고 최신 수치·리소스 상태는 실제 대상으로 확인한다.
미병합 변경·병합 commit·배포 상태를 구별하며 기억 품질은 신규 구성원의 경험 재사용·프로젝트 격리·잘못된 경험의 정정으로 확인한다.
업무 성공률·기억 오적용률·도구 호출·완료 시간·비용도 함께 평가한다.

## 소스와 산출물

### 소스 개발

프로젝트 실행 환경에 여러 저장소를 등록하고 표준 Git 자격·사내망으로 연결한다.
새 작업은 기준 commit과 업무별 브랜치·사본을 사용하며 같은 사본의 재호출은 기존 변경을 유지한다.
새 실행 환경은 원격 업무 브랜치를 가져오고 로컬 전용 commit을 보존하며 양쪽 이력이 분기되면 비교·통합할 충돌 상태로 반환한다.
이전 환경의 미반영 변경은 해당 파일시스템에서 확인한다.

통합 검사는 최신 대상과 업무 commit을 임시 사본에서 병합해 충돌과 검증 결과를 반환한다.
실제 commit·push·병합은 에이전트가 승인 범위·저장소 정책에 따라 표준 Git으로 수행하고 반영·배포 완료는 실제 근거로 판정한다.
실행 도구와 사본·브랜치 규격은 [Git 작업 환경](../development/guide.md#git-작업-환경)을 따른다.

### 산출물

서버는 매 호출에 현재 업무의 S3 저장 위치를 제공한다.
에이전트가 그 위치에 생성한 파일을 업로드하면 실제 객체를 작성 사용자·프로젝트·업무의 산출물 목록에 연결한다.
다운로드는 현재 접근과 파일 버전을 확인하고 해당 버전에 한정된 임시 링크를 발급한다.
링크의 유효 기간은 최대 300초·현재 로그인 잔여 시간 이내이며 소지자는 그 기간에 파일을 받을 수 있다.

## 실패와 복구

업무·승인·원본은 S3에, 일시적인 MCP 연결은 Runtime 프로세스에 보관한다.
재연결·호스트 전환에는 자신의 업무 목록과 마지막 보관 응답으로 이어가며 상태 조회와 실행·복구 호출을 구별한다.
S3 조건부 갱신은 같은 업무의 동시 실행과 확인 중 변경을 대조한다.

| 상황 | 처리 |
|---|---|
| 같은 업무 실행 중 | 상태를 조회하고 추가 실행은 대기 |
| 응답 보관 뒤 상태 확정 실패 | 저장한 불변 응답을 반영해 복구 |
| 호출 기록이 상태 저장 크기를 초과 | 전체 원본을 업무 파일로 보관하고 실제 효과를 확인한 뒤 새 세션·계획으로 복구 |
| 복구할 응답 기록 없음·세션 만료 | 기존 실행의 종료·실제 효과를 사용자와 확인한 뒤 새 세션 복구 |
| 새 세션 복구 | 이전 상태 보존·승인/대기 해제 후 원래 목표·마지막 응답·확인 내용으로 새 계획과 승인 연결 |
| 복구 확인창 취소·미지원·시간 초과·로그인 만료·업무 변경 | 기존 상태 유지 |
| 도구·스트림 실패 | 확보한 응답·오류를 보존하고 실제 실행 효과·현재 대기로 후속 동작 판단 |

복구 도중 새 응답을 받기 전에 중단돼도 이전 보관 결과를 조회해 다시 판단한다.
호스트 연결 종료와 원격 실행 중단을 구별하며 실제 외부 효과의 판정은 리소스·운영자의 확인에 근거한다.
외부 작업의 실행과 상태 보관 사이 장애는 원본·실행 상태를 대조해 처리한다.
호출별 실패 코드·입력·원본 보관 조건은 [API와 저장 계약](../development/guide.md#api와-저장-계약)에 둔다.
