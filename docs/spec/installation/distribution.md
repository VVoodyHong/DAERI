# 배포와 업데이트

상태: 확정 배포 요구사항 + 패키징·업데이트 설계 제안

이 문서는 배포 출처, 호스트·OS별 패키징, 최초 설치 진입점과 업데이트를 정의한다.
의존성 검사와 설치 흐름은 [실행 환경 명세](environment.md)에 있다.
현재 단계는 설계이며 배포 패키지나 설치 프로그램을 구현한 상태가 아니다.

## 배포 출처와 실행 위치

배포 저장소는 사내 GitLab·GitHub 등이 될 수 있다.
비공개 저장소 접근 인증과 조직의 플러그인 출처 정책은 사용 환경의 조건이다.

개발자가 중앙 DAERI 서버를 운영하지 않아도 사용자 PC에서 로컬 실행기를 시작할 수 있어야 한다.
로컬 실행기는 원격 리소스에 연결할 수 있어야 한다.
호스트와 실행기의 책임은 [구조 설명](../../architecture/overview.md)을 따른다.

사내 저장소·마켓플레이스 배포는 플랫폼 공식 공개 디렉터리 입점과 구분한다.
초기에는 공개 입점을 전제로 하지 않는다.

## 호스트·OS별 패키징

핵심 실행기와 어댑터는 공통 소스로 유지한다.
플러그인은 Skill과 로컬 MCP 실행 설정을 제공한다.
stdio 연결을 시작점으로 제안한다.

Windows와 macOS는 실행 명령·경로가 다르다.
공통 소스에서 OS·호스트에 맞는 설정을 생성하는 방식을 검토한다.
정확한 패키지 형식과 지원 행렬은 아직 미결이다.

배포 전에 각각의 호스트에서 설치·업데이트·로컬 프로세스 실행을 검증해야 한다.
사용자 확인 경로도 검증해야 한다.
호스트별 패키지·확인 API의 지원 범위는 아직 미결이다.

## Git이 없는 최초 사용자

Git 기반 마켓플레이스 등록에는 호스트의 실제 다운로드 기능과 인증 조건을 확인해야 한다.
Git이 필요한데 없는 경우, 플러그인을 받기도 전에 그 플러그인의 hook으로 Git을 설치할 수 있다고 가정하지 않는다.

대안으로 사내 저장소의 ZIP을 브라우저로 받는 경로를 제안한다.
OS별 설치 진입점을 실행한 뒤 호스트의 로컬 마켓플레이스를 등록한다.

이 경로도 호스트별로 검증하고 사용자 안내를 제공해야 한다.
특정 호스트의 현재 설치가 Git을 함께 제공한다고 일반화하지 않는다.

## 업데이트와 로컬 데이터

실행 환경은 검증된 잠금 정보로 재현하는 방식을 제안한다.
설치한 버전별로 관리한다.

설정·비밀 참조·업무·계획·승인·결과 이력은 사용자 데이터 디렉터리에 보존한다.
이 디렉터리는 플러그인 업데이트 캐시 밖에 둔다.
업데이트 실패가 기존 이력을 지우지 않아야 한다.

설치 위치·보존 기간·상태 마이그레이션·복구 방식은 후속 설계에서 구체화한다.
업무 상태와 결과 이력의 의미는 [업무 흐름](../tasks/workflow.md)과 [결과 명세](../tasks/results.md)를 따른다.

## 종료, 재시작과 무인 실행의 한계

호스트 연결 수명에 따라 로컬 프로세스를 시작·종료한다.
PC나 호스트 종료 뒤 계속 실행되는 서비스라는 보장은 없다.

재시작 때 업무 재개는 [업무 흐름](../tasks/workflow.md)을 따른다.
무인 정기 실행은 별도 로컬 실행 방식과 운영 조건을 정해야 한다.

## 아직 검증하지 않은 항목

최초 다운로드 경로와 OS·호스트별 패키지 형식은 제안 또는 미결이다.
실제 설치·업데이트·로컬 프로세스 실행·사용자 확인 경로는 아직 검증하지 않았다.
