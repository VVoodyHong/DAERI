# 환경 준비와 배포

상태: 자동 준비·사용자 로컬 실행·macOS 우선 요구 확정, 설치·배포 구현 미검증

개발 도구가 없는 PC에서 profile에 필요한 환경을 준비하고 유지하는 기준이다.
호스트 연결은 [플러그인과 실행](../hosts/plugins.md), 리소스·인증 설정은 [사용자 구성](../configuration/profiles.md)을 따른다.

## 설치 조건과 의존성 범위

사용자 PC에는 Codex 또는 Claude Code만 준비되어 있다고 가정한다.
DAERI는 동작에 필요한 프로그램과 지원 버전·필수 기능을 검사하고 누락 항목을 준비할 수 있어야 한다.
macOS를 먼저 구현·검증하며 Windows도 같은 사용 흐름을 지원하도록 설계한다.

| 역할 | 필요한 조건 |
|---|---|
| 호스트 | 설치된 호스트의 플러그인·MCP 기능 확인 |
| 최초 설정 진입 | 다른 개발 도구 설치를 전제하지 않고 시작 |
| 로컬 실행기 | DAERI 실행과 사용자 설정·업무 기록 관리 |
| 로컬 저장 | SQLite·FTS5와 사용자 영역의 파일 저장·조회 |
| 로컬 임베딩·검색 | 임베딩 모델 실행과 SQLite 벡터 확장의 호환성·로컬 저장 공간 |
| 선택한 리소스 연결 | profile에 등록한 어댑터·MCP에 필요한 프로그램 |
| 인증 보조 | 선택한 제공자·인증 방식에서 필요한 프로그램 |

profile 없이 기본 설정 관리를 시작할 수 있어야 한다.
모든 리소스용 프로그램을 한꺼번에 설치하지 않고 선택한 연결에 필요한 것만 준비한다.
서버 제품 자체를 사용자 PC에 설치하거나 원격 운영 환경을 변경하는 작업은 로컬 준비에 포함하지 않는다.

## 버전과 재현 가능한 환경

필요 프로그램·지원 버전·OS·검사 방법·배포 출처는 구현 단계의 단일 의존성 목록에서 관리한다.
저장별 역할과 SQLite·FTS5 채택은 [로컬 저장 구조](../configuration/profiles.md#로컬-저장-구조)를 따른다.
실행 언어·패키지 도구·SQLite 바인딩·벡터 확장·임베딩 모델의 제품과 지원 버전은 구현 단계에서 선택한다.
배포할 라이브러리·확장·모델도 같은 목록에서 관리한다.
실제 설치 상태와 지원 기준은 구분한다.

기존 프로그램은 실제 경로·버전·필수 기능을 확인한 뒤 재사용한다.
호환되지 않으면 기존 설치를 덮어쓰지 않고 사용자 전용 환경에 필요한 구성을 준비한다.
설치할 배포물의 출처와 무결성을 확인하고 실패했다고 임의의 최신 버전이나 다른 출처로 전환하지 않는다.

## 아무 개발 도구가 없는 최초 진입

플러그인 전달과 최초 설정이 별도 개발 도구의 수동 설치를 연쇄적으로 요구하지 않도록 구성한다.
필요한 준비 기능을 배포물에 포함하거나 검증한 독립 진입 경로를 제공한다.
아직 설치되지 않은 플러그인 자체가 모든 선행 조건을 해결한다고 전제하지 않는다.

OS·기기 종류·사용자 설치 위치·호스트의 시작 환경을 확인한다.
사용자 권한으로 준비하는 것을 기본으로 하고 추가 권한이나 조직 조치가 필요하면 그 이유를 안내한다.
지원 배포물이 없거나 회사 정책에 막히면 미완료 사유와 가능한 다음 조치를 보고한다.

## 검사·계획·설치

profile 설정에서 선택한 연결·인증 방식과 [기억 기능](../tasks/memory.md)에 맞춰 필요한 프로그램을 계산한다.
검사 자체에 원격 로그인이나 업무 자료 조회를 숨겨 포함하지 않는다.

1. 호스트·OS와 선택한 리소스 연결·로컬 임베딩에 필요한 프로그램을 확인한다.
2. 이미 설치된 프로그램·모델의 실행 가능 여부·버전·필수 기능과 로컬 용량을 검사한다.
3. 누락·비호환 항목의 출처·설치 위치·다운로드·권한·영향을 보여 준다.
4. 사용자가 확인한 준비 범위에서 필요한 항목을 설치한다.
5. 설치 결과와 실제 호스트에서의 DAERI 시작을 확인한다.
6. 준비 완료 항목·연결 상태·남은 사용자 조치를 보고한다.

확인한 준비 범위 안에서 프로그램마다 재승인받지 않는다.
추가 프로그램·권한·시스템 변경이 범위를 벗어나면 수정 내용을 먼저 확인받는다.
설치 동의는 [업무 계획 승인](../tasks/approval.md)과 별개다.

실행에 성공하는지 확인하지 않고 파일 존재나 버전 표시만으로 준비 완료를 선언하지 않는다.
누락·비호환·정책 차단·판단 불가를 구분하고 실제 확인 결과를 남긴다.
호스트에서 시작한 환경과 수동 실행 환경의 차이도 확인한다.

### 로컬 저장·검색 준비

SQLite·FTS5는 실행기에 포함하거나 사용자 전용 런타임으로 준비한다.
전역 SQLite 프로그램이나 사용자의 `sqlite3` 명령 설치를 필수 조건으로 두지 않는다.
버전 표시뿐 아니라 실제 실행기에서 DB 열기·트랜잭션·FTS5 검색과 벡터 확장 로딩을 검사한다.

벡터 확장은 OS·기기 종류·실행기 바인딩과 맞는 검증된 배포물을 사용한다.
호환되지 않을 때 별도 벡터 DB 서버를 조용히 설치하지 않고 미완료 항목과 준비 조치를 안내한다.
저장 경로의 권한·용량·파일 발행·동시 접근 가능 여부와 OS 인증 저장소 접근도 함께 확인한다.
검사 자료는 실제 운영 자료와 구분하고 검사 종료 후 정리한다.

### 로컬 임베딩 준비

setup은 기기 종류·메모리·디스크 여유·실제 추론 가능 여부를 확인한다.
검증할 모델 배포물·실행 라이브러리와 준비에 필요한 네트워크·설치 범위를 함께 보여 준다.
모델 파일도 신뢰할 수 있는 출처와 무결성을 확인한 뒤 사용자 영역에 준비한다.

일반 업무는 준비된 모델을 사용하며 누락됐다고 설치·다운로드를 조용히 시작하지 않는다.
로컬 실행이 불가능하면 제한과 setup 조치를 안내하고 외부 임베딩 서비스로 자동 전환하지 않는다.
별도 생성 LLM은 필수 설치 대상이 아니다.

모델 가중치는 같은 사용자의 여러 profile이 재사용할 수 있다.
기억과 검색 결과의 profile·실제 대상 경계는 계속 유지한다.
모델 교체 시 호환되는 색인을 확인하거나 유효한 정본에서 다시 만들며 다른 모델의 벡터를 섞지 않는다.
실행 한도·지원 기기·배포 크기는 실제 모델을 선택한 뒤 검증해 의존성 목록에 기록한다.

## 설치 실패와 재개

중복 설치를 막고 준비가 완료된 환경만 사용 대상으로 전환한다.
실패하면 기존 정상 환경과 사용자 데이터를 보존한다.
재실행 시 실제 준비 상태를 대조해 필요한 단계부터 이어간다.

완료 여부가 불명확한 설치를 무조건 반복하지 않는다.
설치 성공·인증 성공·원격 권한·업무 데이터 접근 성공은 각각 구분한다.
여러 profile이 실행 환경을 공유할 수 있어도 연결과 인증 문맥은 분리한다.

## 배포 출처와 최초 전달

사용자는 소스 저장소를 마켓플레이스에 추가하고 DAERI 플러그인을 설치한 뒤 profile 설정을 시작한다.
현재 사용할 저장소와 호스트는 [사용 예정 환경](../product.md#사용-예정-환경)에 정리한다.
특정 저장소 제품이나 공개 마켓플레이스 입점을 공통 실행 조건으로 두지 않는다.

저장소 접근 권한과 호스트가 요구하는 전달 조건을 확인한다.
마켓플레이스 추가 전에 필요한 프로그램이 있으면 그 선행 조건과 준비 경로를 안내한다.
저장소 접근이 어려운 환경에서는 검증 가능한 완전한 배포물을 통한 최초 진입을 검토한다.

공통 기능과 Skill을 바탕으로 [호스트별 패키지](../hosts/plugins.md)를 구성한다.
실제 저장소 추가·설치·업데이트 가능 여부는 각 호스트에서 검증한다.

## 업데이트와 데이터 보존

업데이트도 새 환경을 확인한 뒤 전환하며 진행 중인 업무를 무조건 새 환경으로 옮기지 않는다.
재개 가능성과 현재 계약·권한을 확인하기 전 기존 정상 환경을 제거하지 않는다.

업데이트·재설치·임시 자료 정리는 profile·인증 참조·업무·승인·호출 기록과 유효한 기억 정본을 보존한다.
조회 자료·보고서·생성 파일은 정해진 보존기간을 따르며 만료 자료를 복구로 다시 열람 가능하게 만들지 않는다.
기억·검색 색인·캐시도 [기억 보존 기준](../tasks/memory.md)을 적용하며 색인 복구가 만료 자료를 되살리지 않는다.
사용자 간 데이터·비밀 공유는 [공유·복구 경계](../configuration/profiles.md#변경공유복구)를 따른다.

저장 형식 변경과 백업 복원은 [로컬 저장 구조](../configuration/profiles.md#로컬-저장-구조)의 이관·백업 계약을 따른다.
내부 스키마·이관 코드·백업 파일 형식은 구현 단계에서 정한다.

## 회사 환경과 자동 준비의 한계

| 상황 | 처리 |
|---|---|
| 네트워크 실패 | 실패 항목과 재개 방법 안내 |
| 조직의 네트워크·인증서 설정 | 조직이 허용한 설정을 적용해 재검사 |
| 다운로드 차단 | 허용된 배포 경로나 검증 가능한 오프라인 배포물 검토 |
| OS·회사 정책 차단 | 필요한 사용자·조직 조치와 미완료 이유 표시 |
| 제공자 로그인 필요 | 해당 제공자 안내에 따른 사용자 인증 |
| 원격 권한·기능 미지원 | 연결별 상태로 표시하고 로컬 설치 결과와 구분 |

신뢰 검증이나 회사 정책을 끄고 설치 완료로 처리하지 않는다.
자동화할 수 없는 사용자 인증과 조직 조치는 명확하게 안내한다.

## 구현 전 확인

개발 도구 없는 macOS에서 두 호스트의 최초 전달·설정 진입·환경 준비를 먼저 확인한다.
Windows에서도 같은 계약을 검증하며 OS별 확인 결과를 구분한다.
회사 제한·사용자 경로·권한·중간 실패·중복 실행·업데이트·데이터 보존을 확인한다.
SQLite·FTS5·벡터 확장의 실제 실행기 호환성, 이관 잠금·중단 복구와 DB·파일의 일관된 복원도 확인한다.
모델 다운로드 실패·무결성 오류·자원 부족·로컬 추론·색인 재생성·외부 서비스 자동 대체 차단도 확인한다.
실제 다운로드·설치·인증·호스트 시작·리소스 연결은 아직 검증하지 않았다.
