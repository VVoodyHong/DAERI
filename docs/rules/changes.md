# 문서 변경 관리 원칙

상태: 설계 단계의 작업 기준

기존 문서를 수정하고 작업을 인계하는 사람과 에이전트를 위한 원칙이다.

이 문서는 기존 문서의 수정·이동·삭제와 Git 기록, 작업 인계를 다룬다.
문서 내용은 [작성 원칙](documentation.md), 표현은 [Markdown 원칙](markdown.md)을 따른다.

## 수정 전 확인

현재 파일과 Git 차이를 읽고 사용자가 수정한 내용을 먼저 파악한다.
이전 대화의 파일 내용으로 현재 문서를 덮어쓰지 않는다.
사용자 변경을 보존하며 이번 요청에 필요한 부분만 수정한다.

수정 대상의 정본과 연결된 명세·구조 설명을 확인한다.
표현 정리와 제품 요구 변경을 구분한다.
의미를 바꾸는 수정은 변경 이유와 영향이 드러나게 한다.

## 수정과 이관

같은 계약은 한 정본에서 수정하고 관련 문서는 링크한다.
문서를 나눌 때는 이전 내용을 새 정본에 모두 이관했는지 대조한다.
짧은 내용이 같은 질문에 답하면 기존 문서의 절로 유지한다.

이동·분리 후에는 링크·앵커·필수 읽기 경로를 함께 갱신한다.
이관이 끝난 일반 문서는 삭제하고 불필요한 디렉터리도 정리한다.
새 위치와 소유 범위는 [문서 구조](../development/documentation-architecture.md)에 반영한다.

구조나 제품 조건의 선택을 바꾸면 [기획 원칙](planning.md)을 함께 적용한다.
관련 구조 설명·명세의 현재 내용과 선택 근거를 함께 갱신한다.

## Git 기록

변경 추적의 기준점과 이번 수정의 차이가 구분되도록 기록한다.
최초 저장소를 만들 때는 현재 문서를 기준 스냅샷으로 보존한다.
커밋은 관련 변경을 묶고 메시지에 변경 목적을 적는다.

스테이징 전에 변경 목록과 내용을 확인한다.
사용자 변경을 되돌리거나 관련 없는 파일을 커밋하지 않는다.
Git 작성자 정보가 없으면 이름과 이메일을 추정해 등록하지 않는다.

문서에 날짜나 변경 로그를 복제하지 않고 Git 이력을 사용한다.
운영체제의 자동 생성 파일은 추적에서 제외한다.

## 검토와 인계

수정한 문서와 영향을 받는 정본을 [검토 원칙](review.md)에 따라 확인한다.
이관 누락·범위 변경·깨진 참조를 먼저 처리한다.

제품의 확정·제안·미결과 검증 범위는 해당 정본에서 갱신한다.
문서를 바꾸면 현재 세션에서도 변경한 정본을 다시 읽고 적용한다.

작업 종료나 인계 때 수정한 내용, 수행한 확인, 남은 문제와 관련 경로를 응답에 남긴다.
임시 작업 현황과 변경 이력을 별도 상태 문서로 복제하지 않는다.
