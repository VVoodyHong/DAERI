# Markdown 표현 규칙

상태: 상세 작성 기준

문서의 문장과 표현을 작성·정리하는 사람과 에이전트를 위한 원칙이다.

이 문서는 문장·문단과 Markdown 표현의 가독성을 다룬다.
무엇을 설명하고 어떤 상태로 기록할지는 [문서 작성 규칙](documentation.md)을 따른다.

## 문장과 문단

- 한 문장에는 주요 설명이나 판단을 하나씩 담는다.
  조건·동작·결과가 길게 이어지면 문장을 나눈다.
- 한 문단에는 하나의 주제를 담는다.
  보통 1~3문장을 권장하고, 주제나 설명 단계가 바뀌면 빈 줄로 분리한다.
- 핵심 동작을 먼저 쓰고 이유와 예외를 이어서 설명한다.
  주어와 대상이 모호하면 구체적인 이름으로 바꾼다.
- 익숙한 한국어와 능동형 표현을 사용한다.
  용어와 약어는 처음 사용할 때 설명하고 같은 개념은 같은 이름으로 쓴다.
- 불필요한 수식어·반복·긴 괄호 설명을 줄인다.
  승인 조건이나 실패 경계를 짧게 쓰기 위해 생략하지 않는다.

문장 길이는 글자 수로 일률적으로 제한하지 않는다.
한 번 읽어 이해하기 어렵거나 여러 판단을 포함하면 분리한다.

## 줄바꿈과 문단 구분

산문은 기본적으로 문장 단위로 소스 줄을 나눈다.
긴 문장 자체도 함께 다듬어 원문과 렌더링 화면의 가독성을 높인다.

단일 줄바꿈은 화면에서 같은 문단으로 이어질 수 있다.
눈에 보이는 문단 구분은 빈 줄로 표현한다.
모든 문장을 별도 문단으로 만들거나 강제 줄바꿈을 일괄 적용하지 않는다.

- 제목 앞뒤, 문단 사이, 목록·표·코드 블록 앞뒤에는 빈 줄을 둔다.
- 목록의 이어지는 설명은 들여써 같은 항목에 포함시킨다.
- 링크·인라인 코드·표의 행은 중간에서 임의로 나누지 않는다.
- 일반 산문에는 `<br>`나 줄 끝 공백보다 문단 구분을 사용한다.
  강제 줄바꿈은 줄 구분 자체에 의미가 있을 때만 사용한다.

## 제목, 목록, 표와 강조

문서 제목은 하나의 `#`로 시작한다.
본문은 `##`, `###` 순서로 나누며 제목 단계는 건너뛰지 않는다.
제목은 해당 절의 내용이나 독자가 찾을 개념을 드러낸다.

절차는 번호 목록, 병렬 조건은 글머리 목록, 비교와 대응 관계는 표로 표현한다.
목록의 항목은 가능한 한 같은 문장 형식으로 작성한다.
이어지는 설명은 문단으로 쓰고 불필요한 중첩 목록을 줄인다.

표의 셀은 짧게 요약한다.
여러 문장의 설명이나 복잡한 분기는 표 아래의 문단·소제목으로 옮긴다.
모든 정보를 하나의 넓은 표에 넣지 않는다.

강조는 핵심 조건이나 결론에만 사용한다.
문장 전체를 반복해서 굵게 쓰거나 장식 기호로 중요도를 표시하지 않는다.

## 코드 블록

코드 블록은 언어를 표시하고 필요한 부분만 담는다.
열고 닫는 구분자를 맞추고 일반 설명과 빈 줄로 구분한다.
예시나 의사 코드라는 상태는 본문에서 명확히 밝힌다.

## 가독성 수정 예시

다음은 긴 문장을 나누면서 실행 조건을 유지하는 예시다.

> DAERI는 에이전트가 요청한 호출에 대해 승인된 계획 버전과 현재 권한을 확인한 다음 입력값과 대상 범위를 검사하여 어댑터를 실행하고 그 결과를 기록한다.

문장을 나누면 다음과 같다.

> DAERI는 호출 전에 승인된 계획 버전과 현재 권한을 확인한다.
> 입력값과 대상이 허용 범위에 포함되면 어댑터를 실행한다.
>
> 실행 결과는 해당 계획 버전의 이력으로 기록한다.

소스 줄바꿈은 문장 경계를, 빈 줄은 검사와 기록의 문단을 구분한다.

## 표현 형식 확인

문장과 문단이 길게 이어지거나 긴 표 셀이 읽기를 방해하지 않는지 확인한다.
제목·목록·코드 블록의 구분과 내부 링크도 확인한다.

가능하면 미리보기에서 문단·목록·표를 확인한다.
원문과 링크만 확인했다면 검증 결과에 그 범위를 적는다.
