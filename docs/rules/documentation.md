# 문서 작성과 변경 규칙

상태: 공통 작성·변경 기준

Markdown은 에이전트의 참고 자료이면서 사람이 목적·동작·판단 근거를 이해하는 문서다.
분류와 정본 위치는 [문서 구조](../development/documentation-architecture.md)를 따른다.

## 설명과 근거

문서 시작에서 목적·적용 범위와 현재 상태를 짧게 밝힌다.
동작은 입력 → 수행 방법·조건 → 결과로 연결하고 거부·실패·부분 결과·완료 근거도 설명한다.
API·모듈 이름만 나열하지 않는다.

같은 계약은 한 정본에 두고 다른 문서는 링크한다.
공식 자료의 사실과 이를 DAERI에 적용한 판단을 구별한다.
예시는 가상 사례임을 밝히고 고정 업무 목록이나 새로운 지원 약속으로 사용하지 않는다.

## 상태와 시점

| 표현 | 의미 |
|---|---|
| 확정 요구·채택 | 사용자가 정한 조건 또는 합의한 선택 |
| 설계 제안·미결 | 제안한 방법·기술·기본값 또는 남은 판단 |
| 구현 완료 | 실제 코드가 존재하고 구현 작업을 마침 |
| 검증 완료 | 대상·방법·결과를 실제 확인함 |

요구와 제안이 섞이면 해당 절에서도 구분한다.
“지원하도록 설계한다”와 “지원한다”, “검증할 예정이다”와 “검증했다”를 구별한다.
확인하지 않은 호스트·OS·리소스로 검증 결과를 일반화하지 않는다.

작성일·갱신일·변경 로그·날짜 파일명은 사용하지 않고 Git으로 관리한다.
제품 기능에 필요한 기간·실행 시각·승인 타임스탬프는 유지한다.
CLAUDE.md는 AGENTS.md 가져오기 한 줄만 둔다.

## 문장과 Markdown

한 문장은 주요 설명이나 판단 하나, 한 문단은 하나의 주제로 구성한다.
보통 1~3문장으로 쓰고 핵심 동작 뒤에 이유·예외를 설명한다.
긴 조건·괄호·반복은 나누되 승인 조건과 실패 경계는 생략하지 않는다.

산문 소스는 문장마다 줄을 나누고 주제가 바뀌면 빈 줄을 둔다.
단일 줄바꿈은 화면에서 같은 문단으로 이어지므로 문단 구분은 빈 줄로 표현한다.
익숙한 한국어·능동형과 일관된 용어를 쓰고 약어는 처음에 설명한다.

- `#` 제목은 하나, 본문은 `##`·`###` 순서로 작성한다.
- 제목·목록·표·코드 블록 앞뒤에 빈 줄을 둔다.
- 절차는 번호 목록, 병렬 조건은 글머리 목록, 비교·대응은 표로 표현한다.
- 표 셀은 짧게 쓰고 긴 설명은 표 아래 문단으로 옮긴다.
- 링크·인라인 코드·표의 행은 임의로 나누지 않는다.
- 코드 블록에는 언어를 표시하고 필요한 부분만 담는다.
- 강조·중첩 목록은 줄이고 일반 산문에 `<br>`·강제 줄바꿈을 일괄 적용하지 않는다.

내부 링크는 상대 경로와 의미 있는 이름을 사용한다.
외부 근거는 해당 주장을 뒷받침하는 공식 문서로 연결한다.
비밀값·개인정보·사내 운영 데이터는 예시에 넣지 않는다.
검증하지 않은 명령·설정은 바로 쓸 수 있는 절차처럼 제시하지 않는다.

## 변경과 이관

수정 전 현재 파일·Git 차이·관련 정본을 읽고 사용자 수정을 파악한다.
이전 대화의 내용으로 최신 파일을 덮어쓰지 않는다.
표현 정리와 제품 요구 변경을 구분하고 의미 변경의 이유·영향을 설명한다.

현재 요청을 완성하는 데 필요한 부분을 수정한다.
이관 시 필요한 내용을 새 정본에 대조하고 반복·대체된 내용은 제거한다.
짧고 같은 질문에 답하는 내용은 기존 절로 유지한다.

이동·삭제 후 링크·앵커·필수 읽기 경로와 문서 구조를 함께 갱신한다.
이관이 끝난 일반 문서는 삭제하고 redirect·빈 분류를 남기지 않는다.
제품 선택 변경은 [기획](planning.md), 정확성 확인은 [검토](review.md)를 따른다.

## Git 기록과 인계

스테이징·커밋 전 변경 범위와 내용을 확인한다.
사용자 변경을 되돌리거나 관련 없는 파일을 함께 기록하지 않는다.
커밋은 관련 목적 단위로 묶고 작성자 이름·이메일을 추정해 설정하지 않는다.
운영체제 자동 생성 파일은 추적에서 제외한다.

수정한 정본의 상태·미결·검증 범위도 함께 갱신하고 현재 세션에서 다시 읽는다.
인계 응답에는 변경·실제 확인·남은 문제·관련 경로를 남긴다.
임시 현황·변경 이력을 별도 상태 문서로 복제하지 않는다.
원문·링크만 확인했다면 미리보기나 실제 제품까지 검증했다고 보고하지 않는다.
