# 문서와 설계 검토 원칙

상태: 내용·정합성·검증 보고 기준

최신 파일·사용자 수정과 영향을 받는 정본을 읽고 검토한다.
전체 검토 요청에서는 모든 Markdown을 확인하고 분담 범위도 확인한다.

## 검토 순서

| 순서 | 확인할 내용 |
|---|---|
| 1. 요구·동작 | 사용자 지시, 책임·권한·실패·재개·완료 근거의 누락·충돌 |
| 2. 상태·근거 | 확정·제안·미결·구현·검증 구분, 출처·가상 사례의 정확성 |
| 3. 정본·변경 | 중복·과설계, 이관 누락·오래된 계약·깨진 링크·앵커 |
| 4. 표현 | 코드 없이 이해할 목적·흐름, 문장·문단·표의 가독성 |

기능 검토는 정본의 각 동작을 구현·테스트에 연결하고 공개 기능에서도 담당 정본으로 역추적한다.
입력 필수값·기본값·타입, 상태·개정·멱등성, 승인·실행 조건, 저장·삭제·오류·복구를 대조한다.
설치 안내·Skill·도구 설명·생성 설정도 같은 계약을 사용하는지 확인한다.
호스트 지침의 준수, 실행기의 강제 검사, 모의 연동과 실제 환경 검증은 각각의 근거로 판정한다.

기획은 [기획 원칙](planning.md), 구조·코드는 [개발 원칙](development.md)을 적용한다.
작성·변경은 [문서 규칙](documentation.md)을 따른다.
수정은 사용자 요구·동작 정확성·문맥 이해에 주는 영향을 기준으로 결정한다.

## 확인과 후속 조치

원문 검토와 링크·앵커·형식 확인을 함께 수행한다.
형식 확인, 계약 정합성 검토와 실제 호스트·리소스 검증은 각각 결과를 기록한다.
미리보기·실행은 실제 확인한 대상·방법·결과가 있을 때만 검증으로 기록한다.

발견은 위치·문제·영향·최소 수정을 설명한다.
확정 조건과 실행 경계의 문제를 먼저 처리하고 허용 범위의 명백한 정정은 반영한다.
제품 판단이 필요하면 담당 정본에 판단 근거·대안·미결 상태를 기록한다.

수정 후 내용과 영향받는 참조를 확인한다.
검증은 변경·실패·미해결 문제의 영향에 맞춰 수행한다.
문장마다 [동작·조건 기술 규칙](documentation.md#동작과-조건의-기술)의 입력·수행 조건·결과가 드러나는지 확인한다.
자율적인 도구 선택·업무 구성과 승인·인증·자료 제공의 실제 경계를 함께 대조한다.
결과에는 검토 범위·수정·남은 문제·확인 한계를 보고한다.

[Google 검토 지침](https://google.github.io/eng-practices/review/reviewer/looking-for.html)의 설계·복잡도·일관성 관점을 문서 검토에 적용했다.
