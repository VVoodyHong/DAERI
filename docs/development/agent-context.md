# Codex·Claude Code의 문서 로딩과 문맥 복구

상태: 공식 동작 조사 + 저장소 복구 방식 설명

## 공통 원본이 두 도구에 전달되는 방식

Codex는 실행을 시작할 때 프로젝트의 `AGENTS.md`를 탐색해 지침 체인을 구성한다.
기본 탐색은 프로젝트 루트부터 작업 디렉터리까지다.
Git 루트를 찾지 못하면 현재 디렉터리만 확인한다.

상위·전역 지침과 override 설정도 영향을 준다.
결합하는 문서량에는 기본 32 KiB 제한이 있다.
최신 규칙은 [Codex 공식 지침 문서](https://learn.chatgpt.com/docs/agent-configuration/agents-md)를 참조한다.

Claude Code는 `CLAUDE.md`에서 `@경로`로 파일을 가져올 수 있다.
상대 경로는 가져오기를 적은 파일 기준이다.
이 저장소의 CLAUDE는 `@AGENTS.md` 한 줄을 사용한다.

이 방식으로 하나의 원본을 공유한다.
Windows의 심볼릭 링크 조건에도 의존하지 않는다.
[Claude 공식 공유 방식](https://code.claude.com/docs/en/memory#share-one-file-with-other-coding-tools)을 참조한다.

이 문서는 호스트의 동작과 문맥 복구 방식을 설명한다.
필수 읽기·갱신 규칙은 [AGENTS](../../AGENTS.md)에 있다.
작업별 경로는 [문서 구조](documentation-architecture.md)에 있다.

CLAUDE → AGENTS → 작업별 `docs/rules` 순서로 공통 기준을 참조한다.
AGENTS는 기본 지침과 읽기 경로만, rules는 상세 작업 기준을 소유한다.
상세 규칙은 작업에 맞게 파일 도구로 읽는다.

## 상세 문서가 자동으로 전부 로딩되는 것은 아니다

디렉터리 이름이나 Markdown 링크는 본문 전체의 자동 로딩을 보장하지 않는다.
필요한 정본은 에이전트가 파일 도구로 실제 읽어야 한다.

모든 상세 문서를 CLAUDE에 가져오면 작업과 무관한 내용도 시작 문맥을 차지한다.
필요한 주제의 정본을 찾아 읽는 방식을 사용한다.

Claude의 대화 압축 뒤에는 루트 지침이 다시 주입된다.
일반 파일은 일부만 재독되거나 내용 대신 경로가 남을 수 있다.
[Claude 공식 압축 설명](https://code.claude.com/docs/en/context-window#what-survives-compaction)을 참조한다.

개인 자동 메모리는 환경·호스트에 따라 다르다.
두 도구의 공유 정본으로 사용하지 않는다.

공통 규칙은 루트, 상세 계약은 주제별 문서, 다음 작업은 현재 상태에 저장한다.
필요할 때 다시 읽어 문맥을 재구성한다.
이 구조는 **대화가 없어져도 근거를 다시 읽을 수 있게 한다**.

## 이 저장소에서 복구되는 정보

| 읽기 단계 | 복구되는 정보 |
|---|---|
| AGENTS | 기본 지침과 필수 읽기 경로 |
| 현재 상태 | 지금 단계·이번 범위·완료·미결·다음 행동 |
| 문서 구조 | 이번 작업의 정본 위치와 읽기 경로 |
| 작업별 rules | 문서 작성·Markdown 표현·개발의 상세 기준 |
| 관련 spec·architecture | 요구 동작·실행 경계·구성 요소 책임 |
| 필요한 ADR·향후 실행 계획 | 선택 이유와 실행할 순서, 이미 확인한 결과 |

지침 파일을 변경한 뒤에는 내용을 다시 읽는다.
이미 시작한 세션의 지침이 자동 갱신된다고 가정하지 않는다.
실제 로딩은 새 세션에서 확인할 수 있다.

Git 루트가 없는 작업 폴더에서는 폴더 루트에서 시작한다.
다른 위치에서 작업하면 지침 파일을 명시적으로 읽는다.

## 향후 실제 호스트에서 확인할 방법

새 호스트 세션을 프로젝트 루트에서 열고 다음과 같은 읽기 확인을 요청할 수 있다.
이 문서 작업에서 새 세션 검증을 실행한 것은 아니다.

> 이 저장소의 공통 지침과 현재 상태를 읽어줘.
> 현재 허용된 작업, 필요한 상세 문서, 미결인 기술 선택을 경로와 함께 설명해줘.
> 파일 수정과 프로그램 설치는 하지 마.

공통 원본과 현재 단계, 허용 작업을 정확히 설명하는지 확인한다.
향후 설치 기능과 지금 설치하는 작업을 구분하는지도 확인한다.
미결 기술 제안을 확정 사항으로 오인해서는 안 된다.

Claude에서는 지원되는 버전의 `/context`와 `/memory`로 활성 지침을 확인할 수 있다.
Codex에서는 읽은 지침 출처를 요약하게 하거나 공식 문서의 로딩 진단 방법을 적용할 수 있다.

짧은 확인에 성공해도 장시간 작업의 완전한 준수를 보장하지 않는다.
문서 링크·정본 일관성을 확인하고 작업 재개 때 필요한 내용을 다시 읽는다.
DAERI 제품 실행의 승인 경계는 실제 실행기로 검증한다.

## 참고한 스킬과 플러그인의 역할

`claude-md-management`는 지침의 간결성·최신성·충돌을 점검하는 보조 수단이다.
기본 지침은 AGENTS, 상세 기준은 해당 rules 정본에서 수정한다.
CLAUDE에는 내용을 복제하지 않는다.

`superpowers`의 명세·계획 절차는 작업 정리에 활용할 수 있다.
프로젝트의 원본 위치와 현재 단계는 AGENTS를 따른다.

Context7 같은 도구는 외부 라이브러리 문서 조회를 돕는다.
이 저장소의 상태 보존이나 모든 Markdown 자동 로딩을 대신하지 않는다.

현재 문서 체계는 추가 플러그인 설치를 요구하지 않는다.
특정 PC의 스킬 경로나 플러그인 설치 상태를 저장소 의존성으로 만들지 않는다.
