# 최초 구현 범위와 개발 순서

상태: 범위·운영 기본값 정리; 호환성 실험·구현·설치·실연동 미착수

구현 순서와 단계별 완료 근거를 정의한다.
제품 동작·입출력은 아래 정본을 따르고, 이 계획의 검증 항목을 실제 통과하기 전에는 완료로 표시하지 않는다.

## 목표와 첫 완료 지점

Mac에서 Codex와 Claude Code가 실제 승인 뒤 네 MCP의 읽기를 조합하고, 복수 리소스의 비교·계산 표와 CSV를 보고한다.
첫 중간 산출물은 PostgreSQL 하나의 요청 → 계획 → 승인 → 조회 → 보고 흐름이다.
이후 Redis·GitLab·AWS로 확장하고 같은 계약을 Windows에서 검증한다.

가짜 MCP·단일 연동의 통과와 네 실연동 완료를 구분한다.
실제 확인한 OS·CPU·호스트 조합만 지원으로 표시한다.

## 최초 구현 범위

| 영역 | 범위 | 정본 |
|---|---|---|
| 호스트·준비 | 두 호스트의 플러그인·업무/setup Skill, 독립 런처·로컬 stdio | [플러그인](../spec/hosts/plugins.md), [환경·배포](../spec/installation/environment.md) |
| 사용자 구성 | 서비스별 profile, 동일 종류의 복수 리소스, 고정 스냅샷·로컬 인증 참조 | [profile](../spec/configuration/profiles.md) |
| 업무·승인 | 공통 13개 도구, 계획·WebAuthn 승인·최근 업무 선택·일시중지·취소·재개 | [업무 흐름](../spec/tasks/workflow.md), [승인 UI](../spec/hosts/approval.md), [MCP](../spec/mcp/common.md) |
| 리소스·실행 | 기존 MCP 탐색·등록, 검증한 읽기 기능·범위·예산·중복·외부 효과 확인 | [계약](../spec/resources/contract.md), [최초 연동](../spec/resources/initial-adapters.md) |
| 결과·보존 | 근거·부분 결과·파생 표/CSV, 리소스별 제공·보관, 만료 차단·정리·재조회 | [결과](../spec/tasks/workflow.md#이력과-완료-근거), [결과 DTO](../spec/mcp/tasks.md#결과-dto) |

다음은 후속 범위다.

- 원격 데이터·설정 변경, 삭제·배포·코드 적용과 외부 게시·전송.
- 무인 정기 실행·상시 감시, HITL 자동 허용과 다중 에이전트 실행.
- 중앙 계정·공동 승인, 완전한 운영 대시보드와 공개 마켓플레이스 입점.
- 모든 Redis 자료형·AWS action, 자유 shell·일반 코드 실행과 제품 간 쿼리 자동 변환.
- 기본 MCP의 부족분이 확인되기 전의 대안 MCP·직접 SDK 구현.

제품 전체를 조회 전용으로 제한하지 않는다.
변경 실행은 부작용·중복 방지·완료 확인 계약을 갖춰 추가하고, 읽기 단계에서도 미확인 효과·소비·예약은 보존한다.

## 개발 순서

| 단계 | 산출물 | 선행 조건 |
|---|---|---|
| 1 | 호환성 실험·구현 스택 선택 | 현재 정본 |
| 2 | 로컬 준비·구성·업무 저장 | 검증한 지원 조합 |
| 3 | 실제 승인·공통 실행·보고 | 설정·저장·전송 기반 |
| 4 | PostgreSQL 전체 흐름 | 승인·검사·영속 기록 |
| 5 | Redis → GitLab → AWS와 조합 검증 | 검증한 공통 실행 계약 |
| 6 | Mac 최초 전달·복구·두 호스트 검증 | 네 실연동 |
| 7 | Windows 구현·검증 | Mac의 공통 코어 |

이 순서는 개발 의존 관계이며 업무별 도구 순서를 고정하지 않는다.
실제 업무 리소스 호출은 3단계의 실행 경계가 완성된 뒤 시작한다.

### 1. 호환성과 스택

후보인 Python·공식 MCP SDK·SQLite·uv·WebAuthn 라이브러리와 독립 런처의 배포 방식을 작은 실험으로 확인한다.
두 호스트의 플러그인·Skill·패키지 경로 치환·stdio, Safari의 localhost 키 등록·사용자 검증, 개발 도구 없는 setup 시작을 시험한다.
운영 인증·데이터 조회는 필수 실험 조건이 아니다.

완료 근거는 채택한 스택·실제 지원 조합과 단일 dependency 목록·잠금 정보의 관리 위치다.
프로그램·지원 버전을 여러 명세에 복제하지 않는다.
승인·stdio·최초 진입이 성립하지 않으면 관련 설계를 수정하며 채팅 승인·런타임 사전 설치로 전제를 바꾸지 않는다.

### 2. 준비·구성과 저장

profile 없이도 시작하는 명시적 setup, 사용자 전용 환경, profile·연결·인증 참조의 최소 관리 입력을 구현한다.
업무·스냅샷·불변 계획·요청 키·근거를 보존하고 접수·보완·최근 업무 목록·단건 조회·계획 저장을 연결한다.
SDK·저장 구현은 코어 경계에서 변환한다.

완료 근거는 재시작 복구, 개정·중복 충돌 구분, 복수 profile·인스턴스의 대상 분리다.
저장 위치·stdout 분리·비밀 제외, 기본값 변경·권한 철회, 코어 미준비 실패도 확인한다.

### 3. 승인·공통 실행·보고

실제 키 등록·계획 표시·WebAuthn 검증과 가짜 MCP의 등록 → 검사 → 예약·의도 → dispatch → 보존을 연결한다.
실제 UI 시험과 격리 자동 검증을 구분하며 시험용 자동 승인·우회 경로는 운영 패키지에 넣지 않는다.
공통 13개 도구의 완료 근거는 다음과 같다.

| 검증 묶음 | 확인할 결과 |
|---|---|
| 승인·범위 | 승인 전·범위 밖·미지원 조건의 하위 호출 0회; 오래된 승인·응답 거부 |
| 중복·장애 | 재전달의 새 외부 효과 없음; 저장 실패·단절·미확인 효과를 성공·0 사용량으로 바꾸지 않음 |
| 재개·제어 | 소유권 이전·취소·일시중지 후 새 호출 차단; 재승인과 늦은 결과 처리 |
| 근거·보고 | 계획 전 실패 보고, 의존 호출 차단·독립 읽기 지속, 필수 근거 부족의 성공 거부 |
| 제공·보존 | 리소스별 제공·보관·마스킹, 공통 보존기한·만료 차단·다음 실행 정리·삭제 실패 시 차단 유지 |
| 파생 결과 | 복수 원본의 표·CSV 생성과 계산·누락·중복·잘림·원본 대응·제공 범위 검증 |

재계획·재연결·자료 승계가 근거·누적 소비·미정산 예약·원 보존기한을 초기화하지 않는지도 확인한다.
이 단계의 통과는 실제 리소스 지원 완료를 뜻하지 않는다.

### 4. PostgreSQL 전체 흐름

보완이 확인된 DBHub 배포물로 `search_objects`·`execute_sql`의 검증한 읽기를 연결한다.
전용 시험 DB·최소 권한으로 대상·허용 SQL·객체 범위를 확인하고 업무 전용 함수를 추가하지 않는다.

완료 근거는 두 호스트에서 실제 승인 뒤 자연어 조회·집계·후속 조회·근거 보고가 되는 것이다.
쓰기·대상 밖 객체·간접 접근·여러 문장과 행·시간 제약의 거부도 시험한다.
보고 재조회가 DB를 다시 조회하지 않아야 한다.

### 5. 세 연동과 조합

공통 계약을 재사용하고 제품별 의미·제약만 연결한다.

| 순서 | 실연동 완료 근거 |
|---|---|
| Redis | 검증한 자료형 읽기, key·ACL·자료형 범위, 전체 읽기와 표시 잘림 구분, 내부 요청·미지원 상한 처리 |
| GitLab | 공식 HTTP MCP 인증, origin·project·path와 고정 SHA 일치, 부분 확보·읽지 못한 파일의 보고 |
| AWS | SigV4·제공자 profile·검증한 inventory API, 실제 주체·계정·리전·IAM 범위, 원격 task·단절·미확인 효과 확인 |

[최초 연동 명세](../spec/resources/initial-adapters.md)의 지원 사실을 실제 배포물과 시험 환경에서 확인한다.
제품별 허용·비허용 대상, 큰 결과·페이지·인증 실패를 포함하며 지원하지 않는 상한을 보장하지 않는다.

복수 리소스 사례로 PostgreSQL 주문·Redis 상태의 불일치 표/CSV를 생성·검증한다.
동일 승인 안의 후속 조회, 범위 확대 시 재승인, 외부 요청 상한이 명시적으로 없는 `null` 계획도 시험한다.

### 6. Mac 전달·복구

Codex 또는 Claude Code만 준비된 별도 환경에서 비공개 패키지 확보 → setup → 의존성 준비 → 호스트 연결을 검증한다.
Git·Python·Node.js·uv 없는 최초 진입과 사내 GitLab·GitHub의 인증·허용 정책을 포함한다.
필요한 의존성만 준비하고 로그인·원격 진단은 관리 확인을 거친다.

두 호스트 동시 접근·EOF·프로세스 종료·재연결·기본 profile 변경을 시험한다.
미완료 환경의 활성화·미확인 호출 재실행을 막고 설치 실패·업데이트·제거에서 개인 설정·이력·예약을 보존한다.

### 7. Windows 검증

같은 코어에서 런처·경로·Credential Manager·프로세스 실행 차이를 구현한다.
Edge·지원 인증기·두 호스트와 공백·한글 경로·GUI PATH·실행 정책·서명을 확인한다.
최초 환경 준비, 네 실연동과 복구·갱신을 다시 시험하며 Mac 결과로 대신하지 않는다.

## Mac 최초 구현의 완료 조건

1~6단계의 검증을 모두 통과하고 두 호스트에서 네 리소스를 조합한 요청부터 승인·파생 결과 보고까지 시연한다.
개발 환경 재사용 시험과 새 사용자 환경 시험의 근거를 구분한다.
실연동 권한·시험 환경이 없으면 코어·가짜 MCP까지만 보고하며 운영 데이터·쓰기 권한을 기본 시험 전제로 요구하지 않는다.
Windows 완료는 7단계의 별도 근거가 필요하다.

## 구현 전에 닫을 항목

아래는 개발 담당자의 상세화·검증 작업이며 추가 사용자 선택 대기가 아니다.

| 기한 | 확정·검증할 내용 | 정본 |
|---|---|---|
| 1단계 완료 전 | 코어·런처·SDK·WebAuthn·두 호스트 지원 조합, dependency 목록·잠금·배포 출처 | [환경](../spec/installation/environment.md), [호스트](../spec/hosts/plugins.md) |
| 2단계 완료 전 | 현재 권한 표현, 저장 스키마·원자성·소유권 회수·재시작 복구·갱신 방식 | [업무](../spec/mcp/tasks.md), [실행](../spec/tasks/workflow.md) |
| 3단계 착수 전 | 파생 표/CSV의 입력 확장·로컬 계산·원본 대응·마스킹 검증 | [산출물 계약](../spec/mcp/tasks.md#artifactdraft) |
| 4단계 실연동 전 | 허용 SQL·객체·간접 접근·여러 문장과 실제 행/시간 제약의 강제 계약 | [PostgreSQL](../spec/resources/initial-adapters.md#postgresql) |
| 5단계 AWS 연결 전 | 허용 API·IAM/account/region 범위, 원격 task 확인, 내부 요청 상한 또는 명시적 null | [AWS](../spec/resources/initial-adapters.md#aws) |

파생 계약은 로컬 시험 자료로 먼저 검증하고 준비 전에는 공통 보고 구현을 완료로 표시하지 않는다.
실연동 전에 시험 대상·제공자 인증·MCP 접근·최소 권한을 관리 경로로 준비한다.
파일·클래스·테스트 목록은 단계 착수 때 정하며 별도 범용 정책·변환 엔진이나 native 승인 앱을 추가하지 않는다.
작업 품질·변경은 [개발 원칙](../rules/development.md)과 [문서 규칙](../rules/documentation.md)을 따른다.
