# 최초 구현 범위와 개발 순서

상태: 첫 버전의 읽기·분석 기능과 사양 문서화 완료; 로컬 검증 통과, 회사 PC 사용 검증 필요

구현 범위·개발 의존 순서·완료 근거를 정의한다.
프로그램·실행·모듈은 [개발 의존성과 실행](../development/dependencies.md), 상세 동작은 각 사양이 소유한다.
구현된 코드·로컬 검증·실제 회사 환경의 검증을 구분한다.

## 목표와 첫 완료 지점

사용자가 배포 저장소를 마켓플레이스에 추가하고 플러그인을 설치한 뒤 profile을 준비한다.
자연어 요청 → 관련 기억 조회 → 계획 제시 → 호스트 대화 승인 → 리소스 조회 → 근거 검증·보고 → 선별 기억 갱신을 제공한다.
여러 리소스의 결과를 비교·계산한 표와 허용된 파일도 같은 승인 범위에서 생성한다.

첫 버전은 등록된 읽기 기능과 분석을 대상으로 한다.
업무마다 코어에 전용 함수를 추가하지 않고 등록 계약을 조합한다.
자료를 읽는 범위와 모델 제공·내보내기·보관·기억 범위는 각각 검사한다.

## 현재 구현 단위와 검증 경계

| 영역 | 구현한 동작 | 상세 사양 |
|---|---|---|
| 호스트 | Codex·Claude Code 패키지와 Skill, 공통 오프라인 MCP 진입 | [플러그인](../spec/hosts/plugins.md) |
| 최초 준비 | OS별 검사, user-local uv·Python·잠긴 환경의 명시적 준비·실패 복구 | [환경](../spec/installation/environment.md) |
| 사용자 구성 | 복수 profile·인스턴스, 설정 가져오기·내보내기, 인증 참조·recipe 준비·진단·제공자 로그인 | [profile](../spec/configuration/profiles.md) |
| 업무·승인 | 접수·보완·최근 목록·상태 복구, 불변 계획·대화 응답 연결, 일시중지·재승인·취소 | [업무](../spec/tasks/workflow.md)·[승인](../spec/hosts/approval.md) |
| 리소스 | stdio·HTTPS MCP의 선택 도구 등록, 실제 요청 정규화·읽기·검증 호출·누적 예산 검사 | [연결](../spec/resources/initial-adapters.md)·[계약](../spec/resources/contract.md) |
| 결과 | 완료 근거·부분 결과·파생 표·텍스트/JSON/CSV 파일·보존 자료 조회 | [결과](../spec/mcp/tasks.md#결과-dto) |
| 기억 | 출처·정책을 갖춘 선별 지식, 키워드·로컬 벡터 검색, 갱신·정정·무효화·재색인 | [기억](../spec/tasks/memory.md) |
| 저장 | profile JSON·SQLite·관리 파일·인증 저장소 분리, 기한·무결성·멱등 기록 | [저장](../spec/configuration/profiles.md#로컬-저장-구조) |
| 공개 MCP | 15개 도구의 입력·구조화 결과·오류·호스트 전달 | [도구 목록](../spec/mcp/common.md) |

지원 기능의 목적은 등록 계약의 `collect`·`verify`다.
현재 읽기 어댑터는 원격 변경·변경 효과 확인(`change`·`reconcile`)이나 제품별 측정 지표의 강제 상한을 지원한다고 선언하지 않는다.
요구한 한도를 강제할 수 없으면 실행 가능한 계획으로 승인하지 않으며 표시용 힌트로 대체하지 않는다.
원격 쓰기·배포·외부 게시·무인 실행·HITL 완화와 추가 파일 형식은 후속 범위다.

모델과 벡터 검색이 준비되면 혼합 검색을 수행한다.
준비되지 않았거나 일부 색인을 사용할 수 없으면 가능한 검색만 수행한 `partial` 상태와 제한을 보존한다.
기억 0건과 검색 불가를 구분하며 일반 업무가 모델 다운로드나 다른 profile 검색으로 전환되지 않는다.

### 확보한 검증 근거

아래는 실제 수행한 검증 방법과 그 경계다.
릴리즈 전체 완료나 실제 회사 리소스의 지원 완료를 뜻하지 않는다.

| 검증 | 확인한 범위 |
|---|---|
| 로컬 단위·계약 검사 | 입력·비밀 거부, 승인·범위·개정·멱등성, 필드·표·파일·보존·기억 정책의 허용·실패 경계 |
| 실제 stdio 통합 | 별도 리소스 프로세스 두 개의 조회 → 승인된 실행 → 계산 표·CSV·보고 → 결과 조회 → 기억 갱신 → 다음 업무 회상 |
| 실제 로컬 임베딩 | 준비한 다국어 모델로 DNS를 차단한 로딩·임베딩·한국어 질의와 영어 지식 검색 |
| 프로그램 준비 | 임시 HOME의 공식 uv 다운로드·해시 검사, 잠긴 후보 환경 전환; 공백이 있는 별도 경로의 배포 환경·번들 recipe·15개 도구 MCP 시작 |
| 하위 MCP 조합 | 격리한 잠금 환경의 실제 패키지 설치·import·선택 도구 메타데이터; 업무 자료 접근은 제외 |
| 제공자 로그인 | 가짜 device 응답의 대기·속도 제한·거절·만료와 네트워크를 차단한 실제 SDK의 요청·표준 캐시 읽기 |
| 호스트 구성 | Claude Code manifest 검사와 Codex의 읽기 전용 플러그인 조회; 설치·사용자 대화는 제외 |

실제 Codex·Claude Code의 마켓플레이스 추가·설치·Skill 진입과 사용자 답변의 의미 해석은 미검증이다.
Windows의 준비 스크립트·공통 MCP 구성은 있으나 실제 Windows 실행·정책·인증 UI는 미검증이다.
회사의 실제 리소스·SSO 로그인·권한·조직 네트워크와 Python·패키지 캐시가 전혀 없는 PC의 전체 온라인 준비도 별도로 확인해야 한다.
로컬 통합 테스트의 리소스는 시험 프로세스이며 실제 운영 서버로 보고하지 않는다.

## 최초 구현 범위

자연어 요청의 해석·계획·보고 표현은 기존 호스트가 맡는다.
실행기는 해당 profile의 현재 구성과 저장 상태를 읽고 승인·대상·기능·자료 정책·예산을 강제한다.
처리할 업무 종류를 정해진 예시 목록으로 제한하지 않지만 현재 등록하지 않은 기능을 수행했다고 주장하지 않는다.

파일 생성기는 처음에 텍스트·JSON·CSV를 제공한다.
표는 실제 출처·유일키 결합·셀 계산을 검증하며 생성 파일의 보존은 원출처와 승인 범위를 따른다.
다른 형식이 필요하면 계약을 갖춘 생성기를 추가하며 파일 생성을 원격 DB 변경으로 취급하지 않는다.

기억은 검증된 규칙·구조·절차·실패 예방 지식만 선별한다.
계획 전 검색 기록을 현재 계획에 연결하고 보고 후 허용된 출처·필드·범주만 갱신한다.
전체 대화·조회 원문을 자동으로 쌓거나 기억량만으로 판단 정확도가 개선된다고 보장하지 않는다.

## 개발 순서

| 단계 | 개발·검증 목표 | 의존 관계 |
|---|---|---|
| 1 | 두 호스트 패키징·setup 진입·대화 승인 연결 | 호스트 기능·배포 접근 |
| 2 | profile·인증·환경·업무·기억 저장과 검색 | 재현 가능한 로컬 환경 |
| 3 | 모의 리소스의 요청부터 보고·기억 갱신까지 연결 | 상태·승인·공통 실행·출처 검사 |
| 4 | 실제 리소스 하나의 전체 사용자 흐름 | 시험용 연결·최소 권한·호스트 설치 |
| 5 | 여러 범주의 실제 연결·결과 조합 | 제품별 계약·실제 대상·완전성 확인 |
| 6 | macOS의 최초 전달·업데이트·중단·복구 | 호스트만 있는 PC·조직 환경 |
| 7 | Windows의 동일 흐름·설치 정책·인증·복구 | 공통 코어와 OS별 실행 확인 |

이 순서는 기능 의존 관계이며 실제 업무의 리소스 선택 순서를 고정하지 않는다.
구현된 패키징·코어와 실제 사용자 환경에서 확인할 설치·업무 흐름을 한 단계의 성공으로 합치지 않는다.

## 완료 조건과 검증 범위

로컬 구현 완료에는 공개 계약과 실제 동작의 정합성, 허용·거부·실패·부분 결과·충돌·복구 회귀의 확인이 필요하다.
새 변경이나 발견된 결함의 검증이 끝나기 전 전체 릴리즈 완료로 표시하지 않는다.

macOS의 실제 사용 검증은 배포 저장소 → 마켓플레이스 → 설치 → setup → 자연어 요청 → 대화 승인 → 실제 조회 → 보고·기억 갱신의 근거가 필요하다.
재개·일시중지·취소·기한·업데이트 이후에도 권한·누적 사용량·미확인 결과를 잃지 않는지 확인한다.
Windows 완료는 같은 범위의 별도 OS 근거가 필요하다.

실연동 환경이 없으면 모의 연결·코어·설치 조합까지 확인한 범위만 보고하고 회사 PC에서 확인할 경계를 남긴다.
현재 로컬 자동 검증은 실제 준비 모델을 포함해 통과했고 Windows 전용 실행 검사는 macOS에서 생략했다.
승인 전 산출물 생성, 종료 후 늦은 응답 보관, 기억 철회 뒤 파생 보고·재전달, 인증·설정 우회의 거부도 회귀로 확인했다.
작업 품질과 문서 동기화는 [개발 원칙](../rules/development.md)·[문서 규칙](../rules/documentation.md)을 따른다.
