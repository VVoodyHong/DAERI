# 최초 구현 범위와 개발 순서

상태: 범위·개발 순서 정리; 제품 구현·설치·실연동 미착수

구현 순서와 단계별 완료 근거를 정의한다.
기술 스택·의존성·호스트별 연결 세부는 각 단계에서 확인하고 필요한 정본에 반영한다.

## 목표와 첫 완료 지점

사용자가 배포 저장소를 마켓플레이스에 추가하고 플러그인을 설치한 뒤 profile을 준비한다.
이후 자연어 요청 → 관련 기억 조회 → 계획 제시 → 호스트 대화 승인 → 리소스 조회 → 결과 보고·기억 갱신을 Mac에서 검증한다.
복수 리소스를 비교·계산한 표와 CSV도 최초 구현 범위다.
대화 표현·내부 저장·파일 형식은 구분하고 최초 파일 생성기는 텍스트·JSON·CSV로 검증한다.
추가 파일 형식은 등록 생성기로 확장하며 DB 파일을 실제 DB 변경으로 취급하지 않는다.

첫 중간 산출물은 단일 리소스의 전체 흐름이다.
이를 공통 계약으로 확장해 [사용 예정 환경](../spec/product.md#사용-예정-환경)의 연결과 조합을 확인한다.
가짜 연결의 통과와 실제 연동 완료를 구분하고 실제 검증한 환경만 지원으로 표시한다.

## 최초 구현 범위

| 영역 | 범위 | 정본 |
|---|---|---|
| 호스트·준비 | 두 호스트의 플러그인·Skill, setup, 로컬 실행기 시작 | [플러그인](../spec/hosts/plugins.md), [환경·배포](../spec/installation/environment.md) |
| 사용자 구성 | 서비스별 profile, 범주·어댑터 선택, 복수 리소스·인증 참조 | [profile](../spec/configuration/profiles.md) |
| 로컬 저장 | profile JSON, SQLite 정본·검색 색인, 관리 파일, 인증 저장소 분리와 수명 관리 | [저장 구조](../spec/configuration/profiles.md#로컬-저장-구조) |
| 기억·검색 | profile별 기억 정본, 로컬 임베딩, 키워드·벡터 검색, 계획 전 조회·업무 후 갱신 | [기억](../spec/tasks/memory.md), [MCP](../spec/mcp/tasks.md) |
| 업무·승인 | 계획과 대화 승인, 범위 검사, 최근 업무 선택·일시중지·취소·재개 | [업무 흐름](../spec/tasks/workflow.md), [대화 승인](../spec/hosts/approval.md), [MCP](../spec/mcp/common.md) |
| 리소스·실행 | 기존 MCP 재사용, 기능 탐색·등록, 읽기 실행·한도·중복·실패 관리 | [계약](../spec/resources/contract.md), [범주별 연결](../spec/resources/initial-adapters.md) |
| 결과·보존 | 근거·부분 결과·파생 표/CSV, 제공·보관 범위, 만료 차단·정리 | [결과](../spec/tasks/workflow.md#이력과-완료-근거), [결과 계약](../spec/mcp/tasks.md#결과-dto) |

원격 변경·배포·외부 게시, 무인 실행과 HITL 완화는 후속 범위다.
초기부터 별도 추론 루프·승인 전용 앱·범용 정책 엔진을 추가하지 않는다.
제품 전체의 업무를 읽기로 제한하는 것은 아니며 변경 실행은 부작용·중복 방지·완료 확인 계약을 갖춰 추가한다.

## 개발 순서

| 단계 | 산출물 | 선행 조건 |
|---|---|---|
| 1 | 호스트 설치·setup·대화 승인 연결의 호환성 확인 | 현재 설계 정본 |
| 2 | 로컬 준비·profile·업무·계획·기억 저장과 검색 | 검증한 진입 방식 |
| 3 | 기억 조회·대화 승인·공통 실행·보고·기억 갱신 | 구성·저장·검색 기반 |
| 4 | 단일 리소스의 실제 전체 흐름 | 승인·범위 검사·기록 |
| 5 | 여러 범주의 실제 연동·조합 | 검증한 공통 실행 계약 |
| 6 | Mac의 최초 설치·업데이트·복구 검증 | 사용 예정 연결·조합 |
| 7 | Windows의 설치·호스트·연동 검증 | 공통 코어·Mac 검증 |

이 순서는 개발 의존 관계이며 실제 업무의 리소스 선택 순서를 고정하지 않는다.
실제 업무 리소스 호출은 승인·실행 경계가 준비된 뒤 시작한다.

### 1. 호스트 진입과 대화 승인

두 호스트에서 저장소 기반 마켓플레이스 등록·플러그인 설치·Skill 진입·로컬 실행기 연결을 확인한다.
Codex 또는 Claude Code 외에 필요한 프로그램이 없는 환경에서 setup까지 시작할 방법도 검증한다.

현재 계획을 대화에 제시하고 사용자 응답을 동일 업무·계획에 연결하는 작은 실험을 수행한다.
일반 승인·수정 요청·모호한 응답·오래된 응답을 구분하며 별도 브라우저 승인을 요구하지 않는다.
호스트가 해석한 결정과 실제 답변을 함께 전달하고 실행기가 계획·상태·권한을 검사하는 [응답 계약](../spec/mcp/plans.md#daeri_approval_request)을 실증한다.
완료 근거는 호스트별로 실제 확인한 진입·응답 전달 방식과 남은 제약이다.

### 2. 준비·profile과 저장

리소스 범주·어댑터·대상·인증 방식과 기억 정책을 등록한다.
선택한 연결·로컬 임베딩에 필요한 프로그램·모델만 검사·준비한다.
업무·고정 구성·불변 계획·승인·호출·근거를 재시작 후 복구하도록 저장한다.
비밀값은 모델이나 Git 저장소에 복사하지 않고 인증 참조로 관리한다.

현재 profile은 JSON 파일, 업무·기억 정본과 접근 메타데이터는 SQLite, 본문·산출물·모델은 관리 파일로 구성한다.
데이터별 정본·조회·삭제는 [로컬 저장 계약](../spec/configuration/profiles.md#로컬-저장-구조)을 구현한다.
SQLite 트랜잭션과 동시 접근 제어, 준비 중인 파일의 발행·복구, 만료 차단과 정리 대기를 연결한다.

키워드 검색은 SQLite FTS5를 사용하고 벡터는 SQLite 확장으로 구성한다.
벡터 확장·임베딩 라이브러리는 로컬 실행·한국어와 기술 용어 검색·갱신·두 OS 배포 비용으로 검증한다.
별도 생성 LLM·중앙 서버 없이 실제 의존성·지원 범위를 정본에 반영한다.

완료 근거는 설치 실패의 복구, 복수 profile·인스턴스 분리, 기본값 변경과 권한 철회 처리다.
두 호스트의 동시 쓰기, 파일 발행 전후 중단·디스크 부족·고아 파일과 준비 상태 복구도 확인한다.
DB 기록과 파일이 모두 준비되기 전 본문 참조를 제공하지 않고 삭제 실패에도 만료 차단이 유지되는지 검증한다.
기본 맥락·유사 경험·정확한 식별자를 찾는 검색과 정본 기반 색인 복구도 확인한다.
기억의 [필드 출처 해소](../spec/mcp/tasks.md#기억의-출처-필드-확정)와 정책·기한 승계가 저장 개정에 연결되는지도 확인한다.
구현에 채택한 프로그램·지원 버전은 단일 dependency 목록으로 관리한다.

### 3. 승인·공통 실행·보고

가짜 리소스로 기억 조회 → 계획 제시 → 사용자 대화 응답 → 승인 기록 → 범위 검사 → 호출 → 보고·기억 갱신을 연결한다.
호스트가 받은 사용자 응답과 모델이 작성한 승인 주장을 구분하는 경계를 검증한다.
호스트 자체 도구 허용과 업무 계획 승인을 혼동하지 않는다.

공통 [필드 경로](../spec/mcp/common.md#필드-경로와-선택), [실제 요청 판정](../spec/resources/contract.md#실제-요청-정규화와-범위-판정), [표·셀 검증](../spec/mcp/tasks.md#파생-표와-셀-검증)을 기준으로 구현한다.
계약은 이 정본에 정의돼 있으며 이 단계에서는 허용·거부·부분 결과를 시험 자료로 검증한다.

| 검증 묶음 | 확인할 결과 |
|---|---|
| 승인·범위 | 실제 답변·조건 변경·질문·오래된 응답 구분, 과거 승인 조회·기한 적용, 승인 전·범위 밖 차단 |
| 자율 실행 | 승인 범위 안의 후속 판단·호출은 매번 재승인 없이 진행 |
| 중복·장애 | 중복 실행 방지, 저장·응답 실패와 실제 외부 효과·소비의 분리 보존 |
| 재개·제어 | 최근 업무 선택, 일시중지·취소·재승인, 상태별 목적 제한·원자적 계획 교체·늦은 결과 처리 |
| 근거·보고 | 부분 실패·누락 표시, 필수 근거가 부족한 성공 보고 차단 |
| 제공·보존 | 리소스별 마스킹·제공·보관, 보존기한·만료 차단·다음 실행 정리 |
| 파생 결과 | 파일 없는 표·같은 보고의 표 인용, 유일키 결합·셀 계산, 빈 문자열/null·기한·CSV 변환 검증 |
| 파일 형식 | 등록 형식·옵션·크기·실제 파일·기한 검증, 미지원 대체·숨은 설치·원격 쓰기 차단 |
| 필드 경로 | 배열·특수 키·부모 선택·누락/null·가림 우선·바인딩 대상 충돌의 공통 판정 |
| 기억 조회 | 계획의 검색 기록 연결, 0건과 실패 구분, 키워드·의미 검색, profile·실제 대상 격리 |
| 기억 사용 | 과거 승인의 재사용·현재 권한 확대 차단, 제한된 모델 제공, 최신 확인 필요 표시 |
| 기억 갱신 | 기록 전체의 필드 정책 승계·출처 해소 실패 차단, 미검증 후보·정정·무효화·멱등 처리 |
| 기억 보존 | 원본 상속·별도 운영 지식 보존 구분, 만료·삭제의 색인 반영, 검색·복사로 기한 연장 차단 |

재계획·재연결이 누적 소비·미확인 효과·원 보존기한을 초기화하지 않는지도 확인한다.
파생 표의 중복 키·누락·잘림·0 나눗셈과 미검증 표의 완료 근거 사용은 거부해야 한다.
이 단계의 통과는 실제 리소스 지원 완료를 뜻하지 않는다.

### 4. 단일 리소스의 실제 흐름

준비한 시험 리소스 하나를 기존 MCP와 어댑터로 연결한다.
최소 권한으로 실제 대상·허용 기능·범위·한도를 확인하며 업무 전용 함수를 코어에 추가하지 않는다.

완료 근거는 두 호스트에서 자연어 요청부터 기억 조회·대화 승인·후속 조회·근거 보고·기억 갱신까지 되는 것이다.
미승인 대상·쓰기·상한 초과·인증 실패·부분 자료를 함께 검증한다.
저장 결과 재조회가 원격 작업을 반복하지 않아야 한다.
후속 유사 업무가 유효한 경험을 찾고 현재 대상·권한·완료 근거를 다시 확인하는지 검증한다.
경험 축적만으로 정확도가 개선된다고 주장하지 않고 정답 근거가 있는 대표 업무로 검색 품질과 오용을 비교한다.

### 5. 여러 범주와 조합

DB·Cache·Infra·Source·Document 등 사용 예정 연결을 같은 계약으로 확장한다.
어댑터별 입력·결과 의미, 실제 대상, 읽기 권한, 완전성·잘림·실패를 확인한다.
제품별 차이를 숨기거나 공통 기능으로 강제 변환하지 않는다.

복수 리소스의 비교·계산 표와 CSV를 생성하고 출처·제공 범위·계산을 검증한다.
같은 승인 안의 후속 조회와 범위 확대 시 재승인을 함께 확인한다.
실제 지원 기능·미지원 한도는 어댑터 계약에 반영한다.

### 6. Mac 최초 전달·복구

호스트만 준비된 별도 환경에서 저장소 접근 → 마켓플레이스 추가 → 설치 → setup → 업무 보고를 검증한다.
선택한 의존성만 준비하는지와 사내 저장소 접근·설치 제한을 확인한다.

호스트 종료·재연결·동시 접근·profile 변경·업데이트·제거를 시험한다.
미확인 호출을 재실행하지 않고 개인 설정·이력·허용 자료를 보존하는지 확인한다.
같은 사용자의 호스트 전환에서 기억을 공유하고 모델·색인 업데이트 후에도 만료·격리가 유지되는지 확인한다.
저장 스키마 이관 중의 독점 접근과 중단 복구, DB·참조 파일을 함께 복원하는 절차를 검증한다.
복원한 자료도 현재 만료·철회 정책을 적용하고 유효한 기억 정본에서 검색 색인을 재생성하는지 확인한다.

### 7. Windows 검증

경로·사용자 인증 저장·프로그램 실행·설치 정책의 차이를 반영한다.
동일한 사용자 흐름과 실제 연결·복구를 두 호스트에서 확인한다.
Mac 결과로 Windows 완료를 대신하지 않는다.

## 완료 조건과 검증 범위

Mac 완료는 1~6단계의 근거와 사용 예정 연결의 요청부터 대화 승인·결과 보고까지의 시연이 필요하다.
실연동 환경이 없으면 가짜 연결·코어 검증까지만 보고한다.
Windows 완료는 7단계의 별도 근거가 필요하다.

이 문서는 개발 계획이며 실제 설치·호스트 동작·리소스 연결을 검증한 결과가 아니다.
전달 필드의 구현 자료형·내부 스키마·파일 배치와 미선정 의존성은 해당 단계에서 상세화한다.
채택한 저장 역할은 유지하며 추가 사용자 선택 대기로 남기지 않는다.
작업 품질·변경은 [개발 원칙](../rules/development.md)과 [문서 규칙](../rules/documentation.md)을 따른다.
