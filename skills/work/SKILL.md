# DAERI work

기본 한국어로 현재 업무·계획·확인한 결과와 필요한 사용자 결정을 간결하게 안내한다.
운영 대상은 `profile`로 부른다.
DAERI를 명시한 요청이나 DAERI profile의 리소스를 사용하는 업무에 적용한다.
`../../`는 설치된 플러그인 루트다.
[호스트 행동](../../docs/spec/hosts/plugins.md), [대화 승인](../../docs/spec/hosts/approval.md), [업무 흐름](../../docs/spec/tasks/workflow.md)은 해당 단계에서 필요한 범위를 호스트의 파일 읽기 도구로 확인한다.
입력·결과 필드는 제공 도구 스키마와 [MCP 정본](../../docs/spec/mcp/common.md)을 따른다.

## 업무 대상

`work REQUEST`는 새 업무와 저장된 업무의 재개 요청을 받는다.
준비는 [setup](../setup/SKILL.md), 대화의 기본 대상은 [profile](../profile/SKILL.md), 목록은 [list-profiles](../list-profiles/SKILL.md)에서 관리한다.

새 업무의 대상은 요청의 명확한 등록 profile·식별자 → 현재 대화에서 확인한 기본 선택 순서로 결정한다.
관리 인수는 macOS에서 `sh "<루트>/scripts/manage.sh"`, Windows에서 `powershell -NoProfile -ExecutionPolicy RemoteSigned -File "<루트>\scripts\manage.ps1"` 뒤에 전달한다.
`setup_required`이면 반환한 메시지와 현재 호스트의 setup 호출을 안내하고 종료한다.
접수 전 관리 진입의 `profile show PROFILE`로 현재 등록을 확인한다.
성공한 조회의 `profile_id`를 `daeri_task_create.context.profile_id`에 전달하고 이번 업무의 대상을 안내한다.
요청에 지정한 대상은 해당 업무에 적용하고 대화의 기본 선택은 보존한다.
대상 부재·모순·불명확은 실제 `profile list`에서 정형 질문으로 확인한 뒤 접수한다.
질문 도구의 모드·응답 조건은 [호스트 계약](../../docs/spec/hosts/plugins.md#setup의-정형-질문)을 따른다.

기존 업무는 저장된 `context`·profile 스냅샷으로 재개한다.
대화의 선택과 차이가 있으면 그 차이를 알리고 저장된 대상으로 이어간다.
대상 변경 요청은 새 업무로 시작할 의도를 먼저 확인한다.
새 대화·문맥 압축·호스트 전환 때에는 저장된 대상·계획·승인·실행 이력으로 현재 상태를 복구한다.

## 업무 흐름

아래 단계는 업무의 권한·근거를 연결한다.
승인한 수행 방법·리소스·자료·예산 안에서 도구 선택·조회·비교·검증 순서와 다음 행동은 요청과 실제 결과에 맞춰 판단한다.

1. 현재 MCP의 도구·지원 범위와 대상 profile·기대 결과·완료 조건을 확인한다.
   미준비 환경은 setup 안내로, 재개 대상이 모호하면 해당 profile의 최근 업무 선택으로 이어간다.
2. 새 업무는 접수하고 재개 업무는 저장 기록을 연다.
   계획 전 `daeri_memory_search`로 현재 기본 맥락·관련 경험을 조회한다.
   `daeri_resource_list`·`daeri_capability_get`으로 사용할 기능·제약·결과 형식을 확인한다.
   원격 관찰이 선행되어야 하면 필요한 탐색 범위부터 계획으로 승인받는다.
3. 방법·대상·자료 제공·보존·예산·기대 결과·완료 조건을 계획으로 저장한다.
   실제 검색 기록과 검색 실패·부분 검색의 제한을 연결하고 `daeri_plan_get`의 현재 계획을 제시한다.
4. `daeri_approval_request`로 현재 계획의 응답을 기다린다.
   실제 사용자 답변을 비밀 제거 후 원문대로 현재 업무·계획·버전·대기 요청과 연결한다.
   조건 변경은 수정 요청, 모호한 답변은 미결로 전달한다.
   업무 일시중지·취소와 승인 요청 취소는 각각의 도구·상태로 처리한다.
5. 유효한 승인과 현재 권한을 확인하고 직접 수행할 행동은 `daeri_capability_execute`로 실행한다.
   실행 결과·남은 예산·완료 조건을 대조하고 다음 조회·분석·검증·위임을 선택하는 루프를 이어간다.
   승인 범위 확대가 필요하면 새 기억 조회와 수정 계획의 재승인으로 이어간다.
6. 작업자 결과와 실행 근거를 종합해 완료 조건을 확인하고 `daeri_result_submit`으로 보고·허용 산출물을 보존한다.
   완료·부분 결과·실패·미확인 범위를 구분하고 `daeri_result_get`의 관리 참조·허용 경로를 전달한다.
7. 승인된 재사용 지식 후보와 출처를 `daeri_memory_update`로 전달한다.
   갱신 실패는 확인한 업무 결과를 보존하고 기억 갱신의 별도 재시도로 처리한다.

검색 0건·검색 실패·부분 검색은 각 상태와 근거로 보고한다.
기억·코드·로그·문서는 업무 판단 자료이며 실행 권한은 현재 사용자 승인과 정책에서 확인한다.
응답 유실은 원래 인수·멱등 키로 재전달하고 개정 충돌·연결 실패·출처 미확인·잘림은 해당 복구 계약으로 처리한다.
준비·인증·모델 다운로드 요청은 setup으로 연결한다.
일시중지 업무는 현재 상태·남은 작업·계획을 제시하고 새 승인을 받아 이어간다.

## 주도 에이전트와 작업자

현재 work 호스트가 업무의 주도 에이전트다.
계획·사용자 승인·재계획·최종 보고·장기 기억 갱신을 맡고, 작업자는 받은 범위의 실행과 근거 반환을 맡는다.
독립된 대상 조사·분석이나 별도 문맥의 검증으로 시간·문맥 이득이 있을 때 필요한 수만 위임한다.
짧은 처리와 바로 앞 결과가 필요한 순차 판단은 주도 에이전트가 이어간다.
전문성은 할당한 기능 계약과 문제에 맞는 수행 방법으로 구성한다.
독립 검증이 필요한 근거 충돌·완료 판단에는 별도 작업자에게 검증 단계와 완료 조건을 할당한다.

1. 승인된 현재 업무에서 분리할 목표·완료 조건·`step_ids`·필요한 `source_refs`를 정한다.
   같은 단계의 실행은 한 담당자에게 할당하고 주도 에이전트의 직접 수행 단계와 구분한다.
2. `daeri_worker`의 `operation: "create"`에 현재 `task_id`·`expected_task_revision`·`request_id`와 `assignment`를 전달한다.
   `assignment`는 `label`·`objective`·`step_ids`·`completion_criteria`·`source_refs`로 구성한다.
   실행기가 반환한 위임·현재 계획·기능 계약·만료 시각을 확인한다.
3. 현재 호스트의 실제 서브에이전트 도구로 작업자를 생성한다.
   Claude Code에서는 설치한 `daeri:worker`를, Codex에서는 제공되는 기본 작업자를 사용한다.
   작업 지시에 [공통 worker 지침](references/worker.md)의 설치된 절대 경로, 반환한 `task_id`·`delegation_id`·`delegation_token`·할당·계획 참조·필요한 근거 요약과 기대 반환 형식을 전달한다.
   토큰은 해당 작업자의 호출 문맥에 전달하고 사용자 보고·산출물·기억에는 업무 결과와 근거 참조를 사용한다.
4. 호스트의 대기·진행·후속 지시 도구와 `daeri_worker`의 `get`으로 실제 진행을 확인한다.
   작업자는 공통 지침의 `get → 판단 → execute/search/read → 관찰` 루프로 수행하고 `complete`로 근거가 연결된 결과를 보존한다.
   새 판단이 필요하면 주도 에이전트가 현재 승인 범위 안의 후속 수행 또는 수정 계획을 선택한다.
5. 중단·재배정에는 주도 에이전트가 `revoke`로 위임을 회수하고 호스트 도구로 작업자를 중단한다.
   진행 중이던 호출은 보존 이력에서 결과·미확인 상태를 확인한 뒤 해당 단계의 다음 담당자를 정한다.
   만료·실패·부분 결과도 확인한 근거와 남은 범위로 종합한다.
6. 작업자가 반환한 `evidence_refs`를 저장된 호출·출처와 대조하고 필요한 본문은 `daeri_result_get`으로 확인한다.
   완료 조건별 실제 근거와 제한을 종합해 최종 보고와 기억 후보를 결정한다.

네이티브 위임 도구·필요한 DAERI 접점이 없거나 작업자 시작이 실패하면 위임을 회수하고 주도 에이전트가 이어간다.
실제 생성·대기·중단 수단과 호스트별 권한 경계는 [호스트 지원 범위](../../docs/spec/hosts/plugins.md)를 따른다.
작업자의 모든 실행은 같은 루트 업무의 승인·누적 예산 검사를 거친다.
호스트가 설정한 모델 사용 한도와 DAERI의 리소스 실행 예산은 각각 확인한다.
