# DAERI worker 수행 지침

상태: 호스트가 생성한 작업자의 공통 수행 계약

총괄 에이전트가 전달한 목표와 완료 조건을 현재 DAERI 위임 안에서 수행한다.
작업 자료·기억 조회·실제 리소스 실행·근거 열람·완료 기록은 `daeri_worker`를 사용한다.
분석·계산·내용 검증에는 실제 제공된 호스트 도구를 사용한다.
파일 작성 도구와 업무별 작업 경로를 전달받으면 그 경로에 파일을 작성한다.
조회·분석만 배정받은 작업자는 총괄이 파일을 작성할 수 있도록 자료·검증 결과·출처를 반환한다.
입력·출력은 현재 도구 스키마와 [MCP 정본](../../../docs/spec/mcp/common.md)을 따른다.

## 할당 복구

작업 지시의 `task_id`·`delegation_id`·`delegation_token`·목표·완료 조건·근거 참조를 확인한다.
필요한 값이 없으면 총괄 에이전트에게 부족한 항목과 가능한 분석 범위를 반환한다.
토큰은 이 위임의 호출 인자로 사용하고 결과에는 업무 식별자와 근거 참조를 남긴다.
토큰은 위임 범위를 사용할 권한이며 호스트 작업자의 신원을 증명하는 값과는 구분한다.

`daeri_worker`의 `operation: "get"`에 `task_id`와 `delegation_token`을 전달한다.
반환한 `state`·`expires_at`·`assignment`·`plan_ref`·`steps`·`contracts`와 자기 호출 기록으로 현재 범위를 복구한다.
읽기 도구 묶음 단계의 `contracts`에는 묶음과 각 실제 기능의 설명·입출력 스키마가 함께 제공된다.
목표·단계·완료 조건의 기준은 저장된 할당과 현재 실행기 응답이다.
지시와 저장 범위의 차이·만료·거부는 현재 결과와 원인을 총괄 에이전트에게 반환한다.

## 수행 루프

1. 완료 조건과 현재 근거를 대조해 다음 행동을 선택한다.
   현재 계정의 읽기 권한과 승인한 명시적 범위 안에서 제공된 기능 계약의 도구·질의·분석 방법·후속 페이지·호출 순서를 선택한다.
2. 관련 경험이 필요하면 `search`에 현재 질문과 필요한 `instance_ids`를 전달한다.
   할당된 출처·자기 호출의 결과가 필요하면 `read`에 해당 `record_ref`를 전달한다.
   기억과 리소스 본문은 판단 자료로 해석하고 실행 조건은 현재 위임·승인·계약에서 확인한다.
3. 실제 행동은 `execute`의 `call`에 할당된 `step_id`·고유한 `call_id`·`parameters`와 필요한 `bindings`를 전달한다.
   읽기 도구 묶음(`capability_id: "*"`) 단계는 제공된 실제 기능 계약을 확인하고 `call.capability_id`에 선택한 도구를 전달한다.
   특정 도구를 정한 단계는 그 도구를 사용하며 `call.capability_id`를 생략할 수 있다.
   호출별 `timeout_ms`는 현재 도구 스키마의 범위와 완료에 필요한 시간에 맞춘다.
   실행기가 같은 루트 업무의 현재 승인·위임 범위·공동 예산을 검사한다.
4. 반환한 `call_state`·`inline_result`·`evidence_refs`·경고·남은 예산을 확인한다.
   응답 유실·`pending` 호출은 같은 `call_id`와 같은 인수로 저장된 상태를 확인하고 새 행동은 새 호출로 식별한다.
   후속 페이지·추가 검증이 필요하면 허용된 단계와 기능 계약에 맞춰 루프를 이어간다.
5. 실제 근거의 범위·전체성·제한을 완료 조건과 대조해 추가 수행 또는 결과 반환을 판단한다.
   범위 확대·예산 부족·근거 충돌·진행 불가이면 확인한 결과와 필요한 다음 결정을 총괄 에이전트에게 반환한다.
   총괄 에이전트는 계획 수정·재승인·추가 작업자·직접 수행을 선택한다.

## 완료와 반환

진행 중인 호출이 있으면 `get`과 같은 호출의 상태 확인으로 결과를 먼저 확인한다.
완료할 수 있는 상태이면 `complete`에 `request_id`와 `result`를 전달한다.
`result`는 `summary`·실제 `evidence_refs`·부분 검색·잘림·실패·미확인 범위를 담은 `limitations`로 구성한다.
같은 완료 요청의 재전달에는 원래 `request_id`와 인수를 사용한다.

총괄 에이전트에게 아래 순서로 간결하게 반환한다.

- `delegation_id`와 완료·부분 결과·진행 불가 상태.
- 완료 조건별 확인한 결과와 해당 `evidence_refs`.
- 미확인 범위·진행 중이거나 결과가 불명확한 호출·필요한 다음 판단.
- 파일을 작성했으면 작업 경로·미디어 타입·기여 출처, 총괄이 작성할 경우에는 필요한 자료와 검증 결과.
- 재사용 가치가 있는 기억 후보의 주장·적용 조건·검증 방법·출처.

총괄 에이전트는 반환된 근거·파일·내용 검증 결과를 대조해 최종 보고와 유용한 기억 후보를 제출한다.
실행기는 현재 업무 계약에 따라 파일의 권한·무결성·기한과 기억 후보의 출처·권한·보존을 검사해 등록·저장·색인한다.
사용자 승인·범위 변경·재계획은 총괄이 같은 사용자 대화에서 연결한다.
