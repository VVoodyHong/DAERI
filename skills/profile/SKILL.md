# DAERI profile

기본 한국어로 확인한 결과·현재 선택·필요한 다음 행동을 간결하게 안내한다.
운영 대상은 `profile`로 부른다.
`profile PROFILE`은 이 대화의 이후 새 업무에 사용할 기본 대상을 선택한다.
`profile delete PROFILE`은 대상과 정리 범위를 확인한 뒤 해당 profile의 로컬 자료를 삭제한다.
백업·복원 요청은 [이관 계약](../../docs/spec/configuration/profiles.md#이관백업복원)의 `profile backup/restore`로 처리한다.
사용자 로컬 암호 입력 경로를 준비하고, 복원 미리보기의 대상·건수와 사용자 확인을 받은 뒤 해당 확인값으로 적용한다.
완료 후 새 환경의 인증 등록·연결 진단과 선택한 기억 제공자의 재색인으로 연결한다.
`../../`는 설치된 플러그인 루트다.

## 관리 명령 실행

관리 인수는 macOS에서 `sh "<루트>/scripts/manage.sh"`, Windows에서 `powershell -NoProfile -ExecutionPolicy RemoteSigned -File "<루트>\scripts\manage.ps1"` 뒤에 전달한다.
기존 profile의 조회·선택은 관리 인수 앞에 `--connect`를 붙여 현재 설치의 실행 환경과 공유 저장소 연결을 준비한다.
`setup_required`이면 반환한 메시지와 현재 호스트의 setup 호출을 안내한다.
선택·확인은 [호스트 질문 계약](../../docs/spec/hosts/plugins.md#setup의-정형-질문)의 현재 도구와 모드에서 받는다.
상세 계약은 해당 단계에서 호스트의 파일 읽기 도구로 확인한다.

## 선택과 전환

1. `--connect profile list`로 공유 저장소의 실제 등록 목록을 읽는다.
   빈 목록은 setup 안내, 조회 실패는 해당 오류 안내로 처리한다.
2. 요청의 profile·식별자를 실제 목록에서 확인한다.
   생략·미등록·모호한 대상은 정형 질문 도구로 선택받는다.
3. `--connect profile show PROFILE`이 성공하면 반환한 `name`·`profile_id`를 현재 대화의 기본 선택으로 확인한다.
   저장한 연결·인증·임베딩 선택을 재사용하고 [호스트 연결](../../docs/spec/hosts/plugins.md#설치부터-업무-시작까지의-실제-경계)에 따라 새 MCP 구성을 읽는다.
   오류·취소·미응답이면 기존 선택을 유지한다.
4. 선택한 profile과 필요한 식별자, 이후 새 업무에 적용된다는 사실을 짧게 알린다.
   선택의 수명·우선순위·재확인은 [선택 계약](../../docs/spec/configuration/profiles.md#선택과-기본값)을 따른다.

진행 중인 업무는 저장된 대상·계획·승인으로 이어가고 새 업무는 [work](../work/SKILL.md)로 요청한다.
구성 수정·리소스 준비 요청은 setup으로 연결한다.

## 삭제

[profile 삭제 계약](../../docs/spec/configuration/profiles.md#profile-삭제)을 읽고 관리 CLI로 수행한다.
미리보기·실행은 저장소의 일반 정리를 포함할 수 있으므로 실행 가능한 모드에서 호출한다.
Plan에서 이미 받은 미리보기의 확인을 받았다면 실행 모드로 돌아와 그 확인값으로 진행한다.

1. 요청의 삭제 대상을 실제 목록에서 확인하고 모호하면 정형 질문으로 선택받는다.
2. `profile delete PROFILE`로 대상·개정·관련 자료 수·상태·확인값을 받는다.
   준비·로그인·진단·호출이 진행 중이면 완료 또는 중단 후 다시 미리보기한다.
3. 대상·삭제 자료·건수와 공유·외부 자료의 보존 범위를 요약해 사용자의 명시적 삭제 응답을 받는다.
   확인값은 대상·개정 결합에 사용하고 실제 사용자 응답은 별도로 확인한다.
4. 사용자 확인 뒤 같은 대상의 `profile delete PROFILE --confirm TOKEN`을 실행한다.
   대상·개정 충돌은 새 미리보기·확인으로, 정리 실패는 같은 확인값의 재시도로 처리한다.
   건수는 최초 전체 범위로 설명하고 정리 대기의 `last_error`에서 실패 단계·조치를 안내한다.
5. 성공이면 완료를 알리고 삭제한 대상이 대화의 기본 선택이면 그 선택을 비운다.
   실패·대기이면 사용 차단 상태와 같은 대상의 재시도 경로를 알린다.

삭제의 귀속 범위·공유 자료·외부 자료·복구 조건은 runtime의 삭제 계약이 소유한다.
