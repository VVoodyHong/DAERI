# DAERI profile

기본 응답은 한국어이며 사용자가 다른 언어를 지정하면 따른다.
`profile PROFILE`은 이 대화의 이후 새 업무에 사용할 기본 대상을 선택한다.
`profile delete PROFILE`은 대상과 정리 범위를 확인한 뒤 해당 profile의 로컬 자료를 삭제한다.
선택의 범위는 [호스트 명세](../../docs/spec/hosts/plugins.md), 구성과 식별자는 [profile 명세](../../docs/spec/configuration/profiles.md)를 읽는다.
이 Skill에서 `../../`는 설치된 플러그인 루트다.

## 관리 명령 실행

두 OS 모두 플러그인 루트의 `.venv/bin/python.exe`를 절대 경로로 지정하고 `-I -m daeri.cli`로 실행한다.
[환경 격리 기준](../../docs/spec/installation/environment.md#공통-실행-파일과-환경-격리)을 적용하고 PATH의 Python·uv나 외부 가상환경으로 대체하지 않는다.
관리 명령의 자식 환경에 `__PYVENV_LAUNCHER__`를 빈값으로 전달하고 사용자의 원래 환경 변수는 수정하지 않는다.
명령은 플러그인 루트에서 실행하고 사용자 입력·확인값은 별도 인자로 전달한다.
사용자 입력을 명령 문자열에 보간하지 않는다.
실행 환경이 없으면 [setup](../setup/SKILL.md)을 안내하고 설치·로그인·연결 진단으로 자동 전환하지 않는다.

## 선택과 전환

1. `profile list`로 실제 등록 목록을 확인한다.
   목록이 비어 있으면 setup으로 등록하도록 안내하고 종료한다.
   조회 실패는 빈 목록으로 처리하지 않는다.
2. 인자로 받은 이름 또는 식별자를 확인한다.
   생략·미등록·모호한 대상은 실제 목록을 바탕으로 호스트의 정형 질문 도구에서 선택하게 한다.
   질문 도구가 없으면 [정형 질문 계약](../../docs/spec/hosts/plugins.md#setup의-정형-질문)에 따라 모드를 안내하며 선택을 추정하지 않는다.
3. 같은 전용 Python의 `-I -m daeri.cli profile show PROFILE`이 성공한 경우만 반환한 `name`과 `profile_id`를 이 대화의 선택으로 확인한다.
   오류·취소·미응답이면 기존 선택을 바꾸지 않는다.
4. 선택한 이름·식별자와 이후 새 업무에 적용된다는 사실을 짧게 알린다.
   전체 설정·인증 참조를 사용자에게 그대로 출력하거나 등록만으로 실제 연결 성공을 주장하지 않는다.

선택은 현재 대화에만 유지하며 전역 기본값·환경 변수·파일·DB에 저장하지 않는다.
새 대화나 선택을 신뢰할 수 없는 문맥에서는 다시 확인한다.
진행 중인 업무의 profile 스냅샷·계획·승인은 변경하지 않고 새 업무는 [work](../work/SKILL.md)로 요청하게 한다.
구성 수정이나 리소스 준비가 필요하면 setup으로 안내하며 선택 과정에서 수행하지 않는다.

## 삭제

삭제 요청은 선택·전환과 구분하고 [profile 삭제 계약](../../docs/spec/configuration/profiles.md#profile-삭제)을 읽는다.
호스트는 대상 확인·사용자 확인·관리 명령 호출을 맡으며 파일·DB·인증 저장소를 직접 순회해 삭제하지 않는다.
질문은 [호스트 질문 계약](../../docs/spec/hosts/plugins.md#setup의-정형-질문)의 현재 도구·응답 대기 기준을 따른다.
삭제 미리보기·실행 CLI는 저장소의 일반 정리도 수행할 수 있으므로 실행 가능한 모드에서 호출한다.
질문 도구를 위해 Plan 모드로 전환했다면 이미 받은 미리보기로 확인만 받고 실행 모드로 돌아온 뒤 원래 확인값으로 삭제한다.

1. 대상이 불명확하면 실제 목록에서 호스트의 정형 질문 도구로 선택한다.
   현재 대화의 기본 선택만으로 삭제 대상을 추정하지 않는다.
2. `profile delete PROFILE`로 대상·현재 개정·관련 자료 수·삭제 상태·확인값을 받는다.
   해당 profile의 준비·로그인·진단이나 리소스 호출이 진행 중이면 완료하거나 중단한 뒤 다시 확인한다.
3. 대상 이름·식별자와 삭제할 자료의 범위·건수를 요약하고 실제 사용자에게 삭제 여부를 확인한다.
   공유 자료·외부 관리 자료의 보존과 복구 제한은 삭제 계약을 따른다.
   명령의 확인값은 대상 결합용이며 사용자 승인 증거가 아니다.
   사용자 확인이 없거나 취소·미응답이면 삭제를 시작하지 않는다.
4. 확인한 경우만 같은 대상에 `profile delete PROFILE --confirm TOKEN`을 실행한다.
   대상·개정이 바뀌면 새 미리보기와 사용자 확인을 받고, 삭제 도중 실패하면 같은 확인값으로 재시도한다.
   정리 중 반환하는 건수는 최초 전체 범위이며 남은 자료 수로 보고하지 않는다.
   삭제 진행의 취소를 원상 복구로 해석하거나 다른 명령으로 차단을 해제하지 않는다.
5. 성공을 반환한 경우만 완료를 알린다.
   현재 대화에서 선택한 대상이었다면 선택을 지우고 다른 profile을 자동 선택하지 않는다.
   실패·정리 대기이면 완료로 표현하지 않고 사용 차단 상태와 재시도 방법을 안내한다.
   정리 대기이면 같은 대상의 미리보기에서 `last_error`를 확인해 실패 단계와 필요한 조치를 안내한다.

삭제 작업으로 운영 리소스·원격 계정·권한을 변경하지 않는다.
